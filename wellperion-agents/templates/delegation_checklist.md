# 위임 체크리스트 템플릿 (L18 확장)

> 목적: "요구를 조각내 순차 전달"·"담당이 지시 일부를 누락한 채 완료 보고" 사고 재발방지.
> 새 보고 체계 아님 — 기존 약속 L18(작업 보고 표준 표)의 **입력 단계**를 채우는 템플릿이다.
> 웰리가 담당에게 위임할 때 이 템플릿을 채워 프롬프트에 포함시키고, 담당은 보고 시
> "체크리스트 이행" 표를 반드시 먼저 채운 뒤 L18 표준 표를 잇는다.

## 1. 위임 시 (웰리가 채움)

요구사항을 **한 번에, 번호로 쪼개서** 전달한다(왕복 조각전달 금지 — 화면 디테일이 나오는
건 정상이지만, 이미 정해진 요구는 한 메시지에 모아 전달).

```
위임 대상: {담당 agent/역할}
관련 배(ship_no): {있으면 기존 배 번호 — 신규 배 남발 금지, 없으면 "신규"}

요구사항:
1. {요구 1 — 구체적으로, 파일/위치 명시}
2. {요구 2}
3. {요구 3}
...

완료 판정 기준: {무엇이 되면 "됐다"인지 — 애매하면 담당이 판단할 여지 명시}
```

## 2. 위임 전 상태확인 (웰리 — "아직 안 됐다" 지시 전 필수)

"다시 해라 / 아직 안 됐다"류 지시를 보내기 **전에** 반드시 아래로 현재 실제 상태를 먼저 확인한다.
확인 없이 감(느낌)으로 재지시하지 않는다 — 오늘 3회 헛돌림이 전부 이 단계 생략이 원인이었다.

```bash
python scripts/delegation_state_check.py state --path "<레포상대경로>" \
  --string "<확인할 문자열/마커>" --live "<라이브 URL>"
```

결과가 `커밋됨=✅ / 푸시됨=✅ / 라이브=❌`이면 **담당 문제가 아니라 배포 지연**이다 —
담당을 헛돌리지 말고 라이브 재확인만 기다리거나 별도 재촉(배포 적체는 시토 배9332/9199 소관).

같은 대상에 새 담당을 붙이기 전에는:

```bash
python scripts/delegation_state_check.py dup --keyword "<검색어>"
```

기존 PENDING·IN_PROGRESS 매치가 있으면 새 담당을 붙이지 말고 기존 배에 이어서 지시한다.

## 3. 보고 시 (담당이 채움 — L18 표준 표 앞에 삽입)

받은 요구사항 번호별로 **전부** 답한다. 하나라도 생략하면 "완료" 보고 불가.

| # | 요구사항 | 처리 결과 |
|---|---|---|
| 1 | {위임 요구 1 그대로 복사} | ✅ 완료 / ❌ 미처리(사유) / ⚠️ 부분(무엇이 남았는지) |
| 2 | | |
| 3 | | |

이후 약속 L18 표준 표를 잇는다:

```
{✅완료 / ⏳진행 / ⚠️GM필요 / ❌막힘} — {담당 닉네임+배번호} — {제목}

| 🔴 이슈 | 🔧 해결 | ✅ 반영 | 🔍 웰리 검수 | 👉 GM 액션 |
|---|---|---|---|---|
| ... | ... | ... | ... | (필요 없으면 행 삭제) |

기록 위치: {어디에 박제했는지}
```

## 설계 원칙

- 왕복을 줄이려고 "GM이 최종 모습을 미리 다 말하게" 하지 않는다 — 화면 작업은 보면서
  디테일이 나오는 게 정상이다. 이 템플릿이 줄이는 건 **왕복의 비용**이다(누락·오판 방지).
- 이 템플릿은 위임 프롬프트에 붙이는 입력 보조물이다 — 새로운 보고 체계나 새 파일
  종류를 늘리지 않는다(L18 확장일 뿐).
