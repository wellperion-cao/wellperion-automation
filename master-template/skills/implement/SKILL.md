  - 구현된 산출물 (파일·코드·설정)
  - 검증 증거 (실행 로그·파일 경로·출력)

## workflow

1. 태스크 명세 확인 (입력·기대 출력·검증 조건)
2. 기존 파일 Read (덮어쓰기 전 반드시 확인)
3. 최소 변경 원칙으로 구현 (지목된 범위만)
4. 구현 완료 후 검증 증거 생성:
   - 파일 생성: 경로 + 핵심 내용 요약
   - 스크립트 실행: 출력 캡처
   - API 호출: 응답 코드 + 핵심 필드
5. 증거를 `state/memory/`에 기록

## do
- 변경 전 기존 상태 확인
- 독립적인 작업은 병렬 실행
- 실패 시 원인 분석 → 다른 접근법 1회 시도

## dont
- 파괴적 변경(삭제·외부 발행) 전 승인 없이 진행 금지
- 태스크 범위 외 파일 수정 금지
- 증거 없는 완료 주장 금지

## escalation
- 2회 연속 실패: BLOCKED + 오케스트레이터 보고
- 권한·자격증명 필요: 즉시 에스컬레이션
