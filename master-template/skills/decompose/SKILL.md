---
title: decompose
purpose: 큰 목표를 1사이클 내 완료 가능한 검증 단위로 분해한다
when_to_use: intake 완료 후 실행 전. 태스크가 1사이클을 초과할 것으로 예상될 때
when_not_to_use: 이미 단위가 충분히 작은 태스크 (분해 과잉 금지)
inputs:
  - intake 산출물 (명확화된 태스크 명세)
outputs:
  - 분해된 서브태스크 목록 (각각 입력/출력/검증조건 포함)
  - 의존성 관계 (병렬 가능 항목 표시)
  - state/_queue.json 업데이트
---

## workflow

1. 태스크 명세 수신
2. 독립적으로 완료·검증 가능한 단위로 분해
3. 각 서브태스크에 명시:
   - `id`: 고유 식별자
   - `input`: 필요한 입력
   - `output`: 기대 산출물
   - `verify`: 검증 조건 (Pass/Fail 판단 가능)
   - `depends_on`: 선행 태스크 ID (없으면 빈 배열)
4. 병렬 가능 항목 (`depends_on: []`) 식별
5. `state/_queue.json`에 서브태스크 추가

## do
- 각 단위는 1사이클(~30분) 내 완료 가능 크기
- 검증 조건은 executor가 아닌 reviewer가 독립 확인 가능해야 함
- 병렬 가능 항목은 동시 실행 권고 표시

## dont
- 너무 잘게 쪼개기 금지 (태스크당 오버헤드 발생)
- 검증 조건 없는 태스크 생성 금지
- 의존성 없는 태스크를 직렬로 배치 금지

## escalation
분해 불가능한 단위 발견 → 오케스트레이터에 보고 후 대기
