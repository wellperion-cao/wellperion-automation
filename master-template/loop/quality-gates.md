# 완료 품질 게이트

완료 선언 전 아래 4개 게이트를 모두 통과해야 한다.  
하나라도 FAIL이면 완료 선언 불가.

## 게이트 1: 완전성 (Completeness)

**질문:** 명세된 모든 항목이 처리되었는가?

- [ ] 태스크 명세의 output 항목이 모두 존재하는가?
- [ ] 제외범위로 명시된 항목이 포함되지 않았는가?
- [ ] 범위 외 파일이 수정되지 않았는가?

FAIL 조건: output 항목 누락, 범위 초과

## 게이트 2: 정확성 (Accuracy)

**질문:** 실제 결과가 기대값과 일치하는가?

- [ ] 검증 조건(verify 필드)이 충족되었는가?
- [ ] 산출물이 canon.json 공식값과 충돌하지 않는가?
- [ ] 약속.json 규칙을 위반하지 않았는가?

FAIL 조건: 검증 조건 미충족, 공식값 불일치

## 게이트 3: 검증 증거 (Evidence)

**질문:** 재현 가능한 증거가 존재하는가?

- [ ] 로그·파일 경로·스크린샷·API 응답 중 하나 이상 존재?
- [ ] 증거가 state/memory/ 또는 큐의 evidence 필드에 기록되었는가?
- [ ] 제3자가 증거만 보고 완료를 독립 확인할 수 있는가?

FAIL 조건: 증거 없음, 증거 미기록, 재현 불가

## 게이트 4: 문서 최신 (Documentation)

**질문:** 관련 SSOT가 업데이트되었는가?

- [ ] state/_queue.json 태스크 상태가 DONE으로 업데이트되었는가?
- [ ] 새 교훈·약속이 있으면 ssot/약속.json에 추가되었는가?
- [ ] 인시던트 발생 시 ssot/incidents.json에 기록되었는가?

FAIL 조건: 큐 상태 미업데이트, SSOT 누락

## 최종 판정

| 게이트 | 결과 |
|--------|------|
| 완전성 | PASS / FAIL |
| 정확성 | PASS / FAIL |
| 검증 증거 | PASS / FAIL |
| 문서 최신 | PASS / FAIL |

**4개 모두 PASS → 완료 선언 가능**  
**1개라도 FAIL → 해당 게이트 재작업**
