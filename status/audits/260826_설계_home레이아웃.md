# home 레이아웃 재설계안 (2026-08-26)

대상: `3. 웰페리온 가이드/wellperion_guide(main).html` — `<article id="home">` (415~798행) + CSS(42~46행 부근)
검증 방법: 라이브 페이지를 브라우저(1920×1080)로 열어 실측 → **제안 CSS·래퍼를 브라우저 안에서만 주입해 렌더 확인**(파일 무변경) → 전체 스크린샷으로 육안 검수까지 마쳤다. 아래 수치는 전부 그 실측값이다.

## 2) 왜 좁고 길어 보이나 — 원인

1. **`.main{max-width:980px}` (42행)** — 문서(글) 기준의 폭 제한을 대시보드인 home도 그대로 쓴다. 1920 화면에서 오른쪽 1/3이 빈다. 좌측 정렬이라 빈 공간이 전부 오른쪽에 몰려 "너무 좌측"으로 보인다.
2. **모듈 그리드가 폭 부족으로 2열로 접힘** — `repeat(auto-fill,minmax(280px,1fr))` (672행)은 넓으면 알아서 4~5열이 되는데, 860px밖에 없어 2열×4줄(932px)이 됐다. 폭만 주면 코드 수정 없이 스스로 풀린다.
3. **업무&결재가 풀폭 한 줄을 독점** — `grid-column:1/-1` (506행)이라 문의&등록·종합접수처와 나란히 서지 못하고 한 층을 더 쌓는다.
4. **프로스 2덩이(슬로건 카드+리드 문단) 세로 적층 288px**, **배너 2개 세로 적층 194px** — 옆으로 세울 수 있는 것들이 전부 아래로 쌓여 있다.

### 무엇을 줄였나 (단순화)
- 새 칸·새 카드 0개. **추가되는 것은 CSS 미디어 블록 1개 + 래퍼 `<div>` 2개**뿐이다.
- 층수가 7층 → 5층: 옆으로 설 수 있던 3개 층(프로스·업무&결재·배너)을 눕혔다.
- 카드 내부 구조·숫자·id·onclick·데이터 배선 **일절 무변경** — 그리드 열 수만 바뀐다.
- 1400px 미만 화면·인쇄·모바일·다른 탭 = 지금과 100% 동일(전 규칙이 `@media screen and (min-width:…)` 안에만 있음). 다크/라이트 테마는 색을 안 건드리므로 영향 없음.
- 기존 선례 준수: H3·H4가 이미 44·46행에서 "이 문서만 980 제한 해제" 패턴을 쓴다. home 은 음수 마진 핵 대신 `:has()`(크롬 지원 확인 완료 `CSS.supports=true`)로 더 깔끔하게 같은 일을 한다.

## 4) 패치 명세 (3건 — 파일 미수정, 명세만)

### P1. CSS 추가 — 46행 바로 아래에 삽입

```css

```
이 줄 **뒤에** 아래 블록 삽입 (원본 삭제 없음):
```css
  /* home 와이드(2026-08-26 GM: 좌우폭 활용·세로 축소) — 화면 전용. 인쇄(A3)·1400px 미만·다른 탭은 무변경.
     H3/H4의 "이 문서만 980 해제" 선례를 :has()로 잇는다(음수 마진 핵 불필요). */

  @media screen and (min-width:1400px){
    .main:has(#home.active) .ops-detail-grid{grid-template-columns:repeat(3,1fr)!important;}
    .main:has(#home.active) .ops-detail-grid>div:first-child{grid-column:auto!important;}
    .main:has(#home.active) .wa-block-grid{grid-template-columns:1fr!important;gap:10px!important;}
```

왜: 인라인 스타일(503·506·510행)을 이기려면 `!important`가 필요하다 — 337~338행 모바일 규칙이 이미 같은 패턴을 쓴다.

## 5) 위험한 곳 — 잘못 건드리면 값이 안 뜨는 자리
- **인라인 스타일·id 는 한 글자도 바꾸지 말 것.** 이 안은 전부 "삽입"이고 원본 문자열 삭제·치환이 0건이다. 특히 `kpi*`·`hero*`·`home-check-kpi`·`kpiVocCatGrid` id 는 JS 가 채우는 자리다.
- `.ops-detail-grid>div:first-child` = 업무&결재 래퍼(506행). ops-detail-grid **맨 앞에 다른 div 를 끼워 넣으면** 이 선택자가 엉뚱한 카드를 잡는다 — 카드 순서 변경 금지.
- P2 래퍼는 반드시 리드 `</p>` **뒤에서** 닫을 것 — 위치가 밀리면 이후 형제들이 전부 그리드 셀이 되어 화면이 통째로 깨진다.
- 42행 `.main{max-width:980px}` 자체를 늘리면 안 된다 — 모든 문서 탭의 글줄이 길어진다. home 한정(`:has`)이 요점.
- H3 전체화면 토글 JS(7628행)가 `.main`의 인라인 스타일을 직접 만진다 — `.main` 규칙을 인라인으로 옮기는 식의 변형 금지(충돌).
