## 3) 어긋난 것 — 무엇이 왜

**① 매출 카드: 팀별 펼침 합 ≠ 월 매출 큰숫자 (250.8만 원)**
- 펼침 11항목 합 495,931,941 / 큰숫자(AV 8월값) 493,423,941. 펼침 각주는 "총액과 동일 소스"(guide:1372)라 적혀 있으나 실측 불일치.
- 차액 분해: 주차 2,367,000 (펼침에만 포함) + **141,000 (원인 미상 잔차)**.
- 잔차 14.1만의 정체: 보고 탭 팀별 누적 합(펼침에서 주차 제외 = 493,564,941 = 스냅샷 monthInProgress 값과 정확 일치) vs 분석 시트 AV 8월값 493,423,941 — **같은 8월 매출을 두 시트가 14.1만 원 다르게 들고 있다.** 8월이 안 끝났는데 AV(마감값 칸)에 이미 값이 있는 것 자체도 점검 대상(hasCurMonth=true 로 '진행중' 라벨 없이 마감값처럼 표시됨).

**② 어제 매출: GAS 가 스스로 어긋남을 신고하는데 화면이 무시**
- sales.yesterday 응답: 역산(누적차)+주차 = 41,816,100, 시트 '금일 합계' = 41,290,600, `mismatch:true` (차 525,500).
- 화면은 역산값 4,182만을 표시하고 mismatch 플래그는 어디에도 안 쓴다 — 두 원천이 어긋난 날에도 태연히 한쪽 값만 보인다.

**③ (잠재 · 현재 값 영향 0) 강습 등록 '누적' 라벨 vs 코드 기준**
- 카드 헤더는 "올해(2026) 누적"인데 코드(guide:1145)는 SUC 행 전체를 연도 필터 없이 센다. 지금은 list 데이터가 2026-01-01부터라 동치(올해 밖 행 0건 실측)지만, 시트에 과거 연도 행이 들어오는 순간 라벨과 어긋난다. 멤버십 문의(>=2026-01-01 필터 있음)와 기준이 다르다.

**④ (관찰) 죽은 배선** — 1) 하단 ※ 참조. 표시 요소 없는 fetch·set 이 매 로드 실행된다.

**시점차(어긋남 아님):** 업무 카드·강습 문의는 오전 1차 측정값과 1~4건 다르다 — 원장 라이브 이동분(업무 1건 완료 전환, 강습 문의 4건 신규). 같은 시각 재호출로 화면 로직과 정확 일치 확인.

## 4) 자동 검사에 넣을 만한 규칙 (한 카드 안에서 합이 맞아야 하는 관계)

1. 접수처: `이번달 접수 = 이번달 미처리 + 이번달 처리중 + 이번달 완료` (오늘 세 건 사고났던 그 관계 — 이미 수리됨, 회귀 감시)
2. 업무: `총 = 진행 + 완료 + 보류` — 이번달·전체·오늘 각각
3. 결재: `총 = 대기 + 완료 + 반려` — 이번달 16=1+14+1 · 전체 40=1+38+1. 단 '대기'에 다음결재자 게이트가 있어 **결재요청은 있는데 대기자 산출이 null 인 행**이 생기면 항등식이 깨진다 → 깨짐 자체가 데이터 이상 신호
4. 강습 문의: `이번달 = 성인 + 유소년` · 강습 등록: `이번달 = 성인SUC + 유소년SUC`, `누적 = 성인SUC누적 + 유소년SUC누적`
5. 지원부 점검: `남 total + 여 total = 전체 total`, `남 done + 여 done = 전체 done`, 성별 회차 합 = 성별 total/done
