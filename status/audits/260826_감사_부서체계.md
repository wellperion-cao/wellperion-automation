# 부서 체계 4장 감사 (2026-08-26)

감사 방식: 화면 코드가 실제로 부르는 GAS action·파라미터를 코드에서 읽고, 같은 조건으로 GET 조회만 하여 원천에서 직접 세었다. 파일 수정·POST 없음.

## 2) 원천 대조 (표)

원천 = 2026-08-26 조회값. "일치"는 화면 계산식을 원천 값으로 재현해 같음을 확인한 것.

| 부서 | 화면 숫자 | 원천에서 직접 센 값 | 판정 |
|---|---|---|---|
| 시설부 | 오늘 입력률 93% (25/27) | board store: 회차 15항목 전부 + 일일 10항목 입력(미입력=최종퇴실·키패스 2개) → 25/27=93% | 일치. monthly dailySeries 08-26 도 27/25/93% 동일 |
| 시설부 | 월간 세션수 23 · 활성일 23 | dailySeries 23일, total>0 일수 23 | 값은 일치하나 라벨 문제 → §5 |
| 시설부 | 월간 입력률 70% (449/644) | dailySeries 합 done 449 / total 644 = 69.7→70% · byCategory 합도 449/644 | 일치 (단 죽은 분모 83칸 포함 → §3) |
| 시설부 | 기준이탈(참고) 0건 | outOfRange.total 0 · byItem 합 0 · 일별 합 0 | 내부 일치. 표본검증: 오늘·어제 측정값 전건을 기준표(fcheck_ranges 16행)에 대조 — 이탈 없음, 0은 그럴듯함(기준폭이 넉넉: 찜질방 55~75 등) |
| 시설부 | 점검자별 세션 합 | 김종현11+박호균10+이정헌2=23 | 일치 |
| 지원부 | 오늘 23% (26/112) | today_live: done 26/total 112 (남 26/57·여 0/55) | 일치 |
| 지원부 | 월간 완료율 44% (1109/2531) | dailySeries 합 1109/2531 | 일치 |
| 지원부 | 월간 세션 64 · 활성일 24 | byZone 세션 합 47+17=64 · byShift 합 24+21+19=64 · total>0 일수 24 | 일치 |
| 지원부 | 제출률 47%·제출분 체크율 93% (mrSubmitBreakdown) | byZone sumTotal 합 1191/2531=47% · 1109/1191=93% | 일치 |
| 지원부 | 이슈 총계 57 | byZone 이슈 합 31+26=57 · 일별 합 57 | 일치 (교대별 표는 불일치 → §5) |
| 지원부 | 주간 트렌드 (08-26 100%: 26/26) | weekly 응답 그대로 | 응답과 일치. 단 같은 날 월간 그래프는 23% → §2 비고 |
| 주차 | 오늘 0/9 | 08-26 원장: 행 0건·체크 0건 | 일치 (진짜 0 — 제출 자체 없음, §6) |

비고 — 같은 날 두 그래프의 % 가 다르다: 지원부 한 화면에서 08-25가 주간 트렌드 93%(78/84, 제출분 기준) / 월간 일별 66%(78/118, 예정 전체 기준). 분모가 다른 두 지표가 라벨 구분 없이 나란히 있어 어긋남으로 읽힌다.

## 3) 못 채우는 칸 — 분모에는 있는데 입력 화면에 없는 항목

- **시설부 「F 안전」 83칸 (80 AI초안 + 3 새이름)**: 2026-08-26 GM 확정으로 입력 화면에서 카테고리 전체가 제거됐다. 그러나 8월 월간보고 분모에는 그대로 남아 있다(83칸 중 9칸 입력, 11%). 이 죽은 분모가 월 입력률을 70%로 깎는다 — **제외하면 440/561 = 78%**. 서버 월집계는 제출 payload 기준이라 9월부터는 자연 소멸. 8월 보고를 읽을 때만 주의하면 된다.
- 오늘 기준 그 외 부서에서 "입력 칸이 아예 없는 분모 항목"은 **더 발견되지 않았다**. 의심했던 지원부 G-2 접점 소독·G-3 환기(08-25 신설, 이틀 연속 미체크)는 08-26 남 오전 세션에서 실제 체크된 것이 원장에 찍혀 있어 칸이 존재·작동함을 확인 — 미체크는 신규 항목 적응 문제다.
- 시설부 「최종퇴실(fc_eq_final)」·「키패스 라이트」는 칸은 있으나 상습 미입력(오늘도 이 둘만 빔) — 못 채우는 칸은 아니고 안 채우는 칸.

## 4) 갈린 카테고리 — 이름만 다른 같은 것

- **시설부 byCategory**: 서버 원천은 여전히 `F 안전(AI초안)` 80/9 와 `F 안전` 3/0 두 줄. 화면은 오늘 들어간 fmCatCanon 병합으로 한 줄(83/9, 11%)로 표시 — 화면 수리는 확인됨, 서버 시트는 비파괴 유지(의도된 상태).
- **지원부 byInspector — 동일인이 이름 표기로 갈림(월간 점검자별 표에 12행)**:
  - 박남일(30세션) / **박남잏**(1, 오타)
  - 김종현(3) / 김종현 차장(2)
  - 이정헌(2) / 이정헌소장(1) / **이정한**(1, 오타 추정)
  - 박호균(6) / 박호균 과장(1)
  - 이경연실장(1) — kpi.json 정본 표기는 '이경연 실장'
  - 점검자 칸이 자유 입력(R4, 2026-06-11)이라 매 제출마다 표기가 흔들린다. 세션 수가 분산돼 사람별 통계가 실제보다 잘게 쪼개져 보인다.
- 시설부 byInspector 는 갈림 없음(김종현·박호균·이정헌 3인).

## 5) 건수만 있고 내용이 안 보이는 칸

- **텔레그램 회차 알림 「이상 N건」** (시설부 제출 시): abnormalCount 숫자만 발신, 어떤 항목이 왜 이탈인지 미포함. GM의 "이상 1건은 뭐야?"가 여기서 나온다. 월간보고 화면의 기준이탈 표(byItem)는 내용이 있으나, 알림에는 없다.
- **지원부 월간 「이슈 원문 보기 (57건)」**: 제목은 57건인데 펼치면 34행(세션 단위 병합, sessionsWithIssue=34). 한 세션의 여러 이슈가 ' / '로 합쳐져 행수와 건수가 안 맞아 보인다.
- **지원부 월간 교대별 표 '이슈' 칸이 전부 0**: 서버 byShift 응답에 issueCount 필드 자체가 없다(byZone 에는 있음). 월 이슈 57건인데 교대별로는 모두 0으로 표시 — 없는 값을 `||0` 으로 채워 '이슈 없음'처럼 보이는 가짜 0.
- **시설부 월간 「세션수(회차 제출) 23」 라벨**: 서버 sessionCount 는 하루=1세션 계산(회차 통합)이라 활성일수와 같은 값이다. 실제 회차 제출은 하루 여러 건(08-25 9건·08-26 5건). '회차 제출'이라는 라벨과 실체가 다르다.

## 7) 자동 검사에 넣을 만한 규칙

1. **가짜 0 탐지**: 집계 응답에서 하위 표 합계(byShift 이슈 합 등)가 상위 총계(issues.total)와 다르면 경보 — 필드 부재를 `||0`으로 가리는 유형을 잡는다.
2. **분모 죽은 칸 탐지**: 월간 byCategory 중 최근 7일 done=0 이면서 입력 화면 항목 마스터(items/FC_*_ITEMS)에 없는 카테고리 → "입력 경로 없는 분모" 경보.
3. **점검자 이름 정규화 대조**: byInspector 이름을 kpi.json staff 정본과 fuzzy 대조(공백·직함 제거) — 2개 이상 변형이 잡히면 경보. 근본 수리는 자유 입력 → 정본 select.
4. **중복 제출 탐지**: 같은 날 submissions 에서 (endHHMM, inspector, items 지문) 동일 쌍 → 경보 (08-25 seq3=seq4 재발 방지).
5. **미제출 연속일 경보**: 부서별 마지막 제출일이 영업일 기준 N일(주차 2일·시설 1일) 넘으면 운영부 방 알림 — 주차부 6일 공백이 아무 데도 안 떴다.
6. **휴관일 구분 표기**: weekly·dailySeries 렌더에서 2·4주 일요일은 0% 빨간 막대 대신 '휴관' 표기.
7. **건수 알림에 내용 동봉**: '이상 N건'·'이슈 N건' 발신 시 항목명 상위 3개까지 같이 싣는다.
8. **분모 라벨 검사**: 같은 화면에 분모가 다른 %가 나란히 있으면(주간=제출분 vs 월간=예정 전체) 그래프 제목에 분모를 명기.
