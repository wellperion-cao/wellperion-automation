## 2. 핵심 진단 (3줄)

1. **양이 문제다.** 한 방에 하루 90~150줄이 도착한다. 사람은 첫 화면만 보고 넘긴다.
2. **매일 같은 문장이 반복된다.** 지연 목록·측정값·무응답 목록이 어제와 오늘 거의 동일 → "또 그 얘기"로 학습돼 안 읽게 된다.
3. **행동 요청이 본문 끝에 묻힌다.** "정리해 주세요"가 40줄 아래에 있다. 카드의 역할 = **행동 요청을 맨 앞 큰 숫자로 끌어올리는 것.**

카드 공통 원칙: 카드 1장 = 항목 3~5개만. 상세 목록은 카드 뒤에 링크(또는 기존 글을 짧게 줄여 후속 1통). 값이 없으면 "측정 불가" 그대로 표기(카드 엔진에 이미 있는 정직 원칙).

## 3. 방별 카드 설계

### ① ★운영+시설+지원+주차 — 「오늘 점검 마감 카드」 (22:30 회차)

- **누가 읽나**: 시설·지원·주차·운영 4부서 실무진(청소·설비·주차 담당). 명단은 방 등록부에 없음(5장 참고). 로그상 등장 인물: 김종현·박호균(시설), 박남일·이연희(지원) 등.
- **지금 글의 문제**: 22:30에 약 47줄 + 42줄 두 통. 시설부 회차별 일지 8줄·측정값 20여 줄이 이상 없어도 매일 전문 발송. 정작 "남성구역 오전조 0/25 제출 0건" 같은 행동 필요 줄은 중간에 묻힘.
- **오늘 해야 할 행동**: ①제출 안 한 조가 내일 아침 제출하기 ②본인 앞으로 밀린 접수 건 처리하기.
- **카드에 들어갈 것 (5개)**:
  | 항목 | 형태 | 데이터 출처 |
  |---|---|---|
  | 부서 신호등 3칸 (시설 ✅ / 지원 47% ⚠️ / 주차 —) | 타일 3개 | 시설·지원: `scripts/report_stream_2_check.py`가 이미 계산하는 값(현재는 문장만 만듦 — 숫자 반환 소폭 손질 필요, 4장) · 주차: 자체점검 준비 중이라 "준비 중" 고정 표기 |
  | 오늘 0% 조 경보 ("남성구역 오전조 0/25") | 경보 배너(⚠️) | 위와 동일 스트림의 조별 완료율 |
  | 미처리 접수 건수 + 기한초과 건수 (예: 31건 · 초과 13건) | 큰 숫자 타일 | `scripts/report_stream_2b_reception.py`가 이미 계산하는 미처리·기한초과 수 |
  | 이번 주 점수판 1위 한 줄 ("박호균 3점") | 작은 줄 | 위 접수 스트림의 주간 점수판 |
  | 지원부 완료율 7일 미니 막대 | 미니 그래프 | **출처 없음 — 일별 스냅샷 저장이 없어 처음엔 뺀다** (5장) |
- **안 들어갈 것**: 시설부 회차별 일지 전문·측정값 전체(염소·pH·탕 온도 등) — 이상 없으면 "측정 전부 정상" 한 줄이면 충분. 이상값만 경보 배너로 승격. 독려 미체크 항목 33개 나열 — 조 이름과 건수만.
- **캡션(카톡 미리보기)**: "오늘 점검 — 시설 정상 · 지원 47% · 미처리 접수 31건. 빈 칸인 조는 내일 아침 제출 부탁드립니다."
- **개인정보 판정**: 회원 이름 원래 안 나감. 직원 이름(점수판·경보)은 이 방 내부 인정 문화라 유지 가능. **접수 내용 문구(컴플레인 본문)는 카드에 넣지 않음** — 건수만.

### ② ★부서장 — 「문의 처리 현황 카드」 (22:30 회차)

- **지금 글의 문제**: 밤에 경보 2통 + 현황 1통 = 약 50줄. 특히 "60일 무응답 493건" 매일 5건 회전 노출 — 8/6 488건 → 8/7 493건으로 **늘고 있다.** 목록을 매일 보여주는 방식이 행동을 만들지 못함.
- **오늘 해야 할 행동**: ①24시간 미배정·미컨택 건에 담당 정하고 연락시키기 ②3일+ 미배정 적체 나눠 배정하기.
- **카드에 들어갈 것 (4개)**:
  | 항목 | 형태 | 데이터 출처 |
  |---|---|---|
  | 24시간 미배정·미컨택 건수 (예: 6건) | 큰 숫자 + 빨강 경보 | `scripts/unassigned_nudge.py`의 24시간 위반 집계(이미 매일 계산 중) |
  | 3일+ 미배정 적체 건수 (예: 35건) + 팀 구분 | 큰 숫자 타일 | `scripts/report_stream_1_inquiry.py`가 이미 계산하는 3일+ 미배정 수 |
  | 오늘 신규 문의 건수 + 유형 구성 (멤버십 5 · 강습 3) | 타일 | 위 문의 스트림의 신규 문의 집계 |

- **캡션**: "문의 처리 — 24시간 미배정 6건 · 3일+ 적체 35건. 담당 배정 부탁드립니다 → (처리 링크 · 입장코드 1200)"
- **개인정보 판정**: **이 방이 4개 방 중 유일하게 회원 이름이 나가는 방.** 글에서는 허용돼 왔지만 카드(이미지)에는 넣지 않는 것을 원칙으로 제안. 건수와 링크로 대체해도 행동에는 지장 없음(어차피 처리는 링크 페이지에서 한다).

- **캡션**: "오늘 챙길 것 5건 — 자동문(최우선) · 백승화 1건 · 최준용M 2건. 상세는 카드에서 확인해 주세요."
- **개인정보 판정**: 챙길 것에 회원 이름이 섞일 수 있음(예: "김현진2 회원 라커 확인"). **카드에는 회원 이름 대신 "라커 6번 배정 확인"처럼 대상물 중심으로 쓴다.** 직원 이름은 유지.

**4개 방 카드가 서로 다른 이유 요약**: ①은 조·부서 단위 점검 마감판, ②는 건수·링크 중심 배정 독촉판(회원 이름 제거), ③은 주 1회 사람별 정리판, ④는 매일 아침 사람별 행동판. 같은 틀(타일+경보+캡션)을 쓰되 내용물·주기·행동이 전부 다르다.

## 5. 데이터가 없어 못 만드는 칸 (정직)

| 칸 | 어느 카드 | 상태 |

| 지원부 완료율 7일 추세 | ① | 출처 없음 — 일별 완료율 스냅샷을 저장하는 곳이 없음. 만들려면 매일 값 한 줄 적립 필요 |
| 60일 무응답 전일 대비 증감 | ② | 출처 없음 — 당일 총량만 계산하고 저장 안 함. 하루 한 줄 적립 필요 |
| 멈춘 업무 지난주 대비 증감 | ③ | 출처 없음 — 주간 스냅샷 저장 없음 |
| 주차부 점검 칸 | ① | 자체점검 준비 중 — 데이터 자체가 아직 없음. "준비 중" 고정 표기 |

## 6. 먼저 만들 순서 3개

1. **★운영+시설+지원+주차 「오늘 점검 마감 카드」** — 가장 긴 벽글(밤 90줄 2통)이라 개선 폭이 제일 크고, 필요한 숫자(완료율·조별·미처리 건수)가 기존 스트림에 전부 이미 계산돼 있어 손질이 가장 적다.
2. **★부서장 「문의 처리 현황 카드」** — "반영이 안 된다"는 GM 문제의식이 숫자로 증명되는 방(무응답 488→493건 증가). 카드로 총량·증감을 정면에 세우는 효과가 가장 필요한 곳. 단, 방 구성원 명단 확인(5장)을 먼저 받는다.
3. **★중간관리자 「멈춘 업무 정리 카드」(금 17:00)** — 주 1회라 부담이 없고, 기존 주간 초안 위에 표지만 얹는 구조라 실패 위험이 낮다. ④ ★운영부 아침 카드는 다이제스트 생성부 구조화 손질이 가장 커서 마지막에 한다.
