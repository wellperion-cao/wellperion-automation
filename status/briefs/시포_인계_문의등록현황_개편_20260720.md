## 1. 현재 구조 (실측 확인)

### A. O3 재등록 대시보드 — GM이 "잘 만들었다"고 한 것

- 위치: ERP `wellperion_guide(main).html` 의 O3 = **iframe 1줄 껍데기**, 실체는 `3. 웰페리온 가이드/wellperion_dashboard_web.html` (29KB)
- 구성: 탭(전체/월별) + KPI 4카드 + 차트 5종(재등록률 추세·월별매출·상태 스택바·이탈사유·이용일수) + 저활동 표

**왜 빠른가 — 이게 벤치마킹 포인트다**

| 기법 | 내용 |
|---|---|
| **서버가 집계해서 준다** | 원본 행이 아니라 `months[]` 집계본만 받는다. **응답 크기가 회원 수와 무관하게 약 4KB 고정** |
| **3층 즉시 렌더** | localStorage → 파일에 박힌 SNAPSHOT 상수 → 라이브. **네트워크 0회로도 첫 화면이 뜬다** |
| **탭 전환 시 재조회 0** | 이미 받은 데이터만 다시 그림 |
| **실패 설계** | 12초 타임아웃 + 에러 표시 + "다시 시도" 버튼 |
| **PII 분리** | 집계는 공개, 명단만 PIN 게이트 |

### B. 「문의 & 등록 현황」 — 고쳐야 할 것

- 위치: `3. 웰페리온 가이드/cpo/member/문의회원.html` (8,886줄 / 572KB)
- 진입: 버튼 `#btnInquiryDash` → `openInquiryDash()` → 모달 `#inquiryDashModalOverlay` (6섹션)
- **별도 페이지가 아니라 거대한 페이지 안의 모달이다.** 이게 느림의 뿌리 중 하나.

## 2. 왜 느린가 (실측 근거)

| # | 원인 | 근거 |
|---|---|---|
| 1 | **전량 fetch — 기간 파라미터가 아예 없음** | `member_inquiry_list`(L3418)에 from/to 없음. 스냅샷 실측 **멤버십 632건 / 584KB**, 강습 682KB |
| 2 | **부팅 시 콜드 GAS 다중 호출** | `cpo_today_stats`·`cpo_churn_stats`·`stage_funnel`·`type_channel_breakdown`·`member_registered_list`·`member_active_list`… 코드 주석이 자인: **`member_active_list` ~11초** |
| 3 | **632행 DOM 전량 생성** | `renderDbTable()`(L7678) `filtered.forEach → appendChild`. **페이지네이션·가상스크롤 전무** |
| 4 | **필터·정렬 100% 클라이언트** | 입력할 때마다 전량 재스캔 + 전량 재렌더 |
| 5 | **파일 자체가 572KB 단일 HTML** | 데이터 도착 전에 이미 파싱 비용 발생 |

> 이미 있는 완화층: localStorage 5분 TTL + raw.githubusercontent 스냅샷. **체감만 가릴 뿐 GAS 부하는 그대로.**

**결론: 근본 원인은 "집계 엔드포인트가 없어서 행을 다 끌어온다"는 것.** O3처럼 서버가 집계해 주면 대부분 해소된다.

## 3. 해야 할 일

### 과제 1 — 「신규 문의 & 등록 현황」으로 개편 (가장 중요)

**이름 변경:** 문의 & 등록 현황 → **신규 문의 & 등록 현황**
이름만 바꾸는 게 아니라 **"신규"라는 말에 맞게 기본 화면이 최근 기간만 보여야 한다.** GM 불만의 핵심이 여기다.

**필수 작업**
1. **GAS(Survey.js)에 집계 액션 신설** — 예: `inquiry_stats{from,to}` → 건수·단계별·채널별·전환율 **집계값만** 반환. ★이게 최대 작업이자 핵심
2. `member_inquiry_list` 에 **from/to 기간 파라미터** 추가
3. 화면 기본값 = **당월**(또는 최근 30일). 전체 누적은 토글로만
4. 목록에 **페이지네이션 또는 가상스크롤** (632행 한 번에 그리지 않기)
5. 부팅 호출 통합·지연로드 — 모달 열 때만 필요한 건 그때 부르기

**O3에서 그대로 가져올 것:** 3층 로드 폴백 · 탭 전환 무재조회 · 12초 타임아웃+재시도 · KPI/panel CSS · 차트 `destroy()` 누수방지 · PII PIN 게이트

### 과제 2 — 재등록 대시보드를 멤버십 회원관리 페이지에 넣기

O3 실체(`wellperion_dashboard_web.html`)를 멤버십 회원관리 화면에서도 볼 수 있게 한다.
**권장: iframe 임베드** — O3가 이미 iframe 구조라 그대로 재사용 가능하고, 사본을 만들면 또 어긋난다(오늘 시설부 기준값 사고가 정확히 그 사례).

### 과제 3 — 현황(라이브)에 진입 버튼

현황 화면에 버튼 하나 → 재등록 대시보드 페이지로 이동.

## 5. 주의사항 (실제 사고 이력 기반)

- **값을 복사하지 마라.** 같은 수치를 두 곳에 두면 반드시 어긋난다 — 오늘 시설부 점검 기준값이 3곳에 갈라져 "매번 이상건" 사고가 났다.
- **저장 성공을 확인하고 성공이라 표시하라.** 이 저장소엔 저장 실패를 성공처럼 표시한 사고가 3건 있다(INC-011·INC-013, 그리고 오늘 발견한 O2 종합접수처 처리자 저장).
- **`USE_GVIZ` 재활성 주의** — 과거 gviz 행번호 어긋남으로 예약·편집이 사라진 사고(INC-013). 성능 욕심에 다시 켜지 말 것. 성능은 서버 집계로 풀어라.
- **⚠️ 2026-07-20 현재 GitHub 장애로 배포가 밀려 있다.** 푸시해도 라이브 반영이 늦을 수 있다. 코드 문제로 오해하지 말 것.
