# ERP 로그인 — 개인 구글 계정 + 가입 시 부서 지정 (배982·978)

GM 방향(2026-09-05): 역할별 회사 계정 1개 방식 폐기 → 직원 개인 구글 계정으로 로그인, 첫 로그인 때 이름·부서 선택 → GM 승인 → 부서·역할이 곧 권한. 기존 인증 서버(`server/erp_auth/app.py`)를 그대로 확장 — 새 서비스 없음.

## 1. 로그인 흐름

| 단계 | 계정 종류 | 결과 |
|---|---|---|
| 구글 로그인 클릭 | 전체(개인·회사 계정 chooser에 다 뜸 — `hd` 제한 제거) | 구글 인증 |
| 콜백 — 이미 있는 계정 | 회사·개인 무관 | 상태 그대로(활성=로그인, 대기/차단=안내) |
| 콜백 — 신규 + `@wellperion.com` | 회사 워크스페이스 | 종전대로 승인 없이 즉시 활성(GM 2026-09-03 결정 유지) |
| 콜백 — 신규 + 개인 계정 | 개인 Gmail 등 | `/auth/google/finish` 로 이동 — 이름 확인 + 부서 선택 → `pending` 생성 → GM 텔레그램 알림 |
| GM 승인(`/auth/admin`) | — | `active` 전환 → 다음 로그인부터 그 부서 화면이 보임 |
| 비밀번호 로그인 | 종전(회사 이메일만) | 변경 없음 — 두 방식 병행 |

## 2. 권한표 — 부서 → 그룹 → 카드

정본 = `erp/modules.json` 카드의 `group`/`core`/`roles`. 가입 폼 부서(6종) → `server/erp_auth/app.py` `PRESETS` 매핑(기존 프리셋 재사용 + 3종 추가):

| 부서(가입 폼) | 그룹 묶음 | 비고 |
|---|---|---|
| 운영부 | 핵심·시포·시우 | 이경연 실장·임정은M 등 |
| 시설부 | 핵심·시토 | 이정헌 소장 |
| 지원부 | 핵심·시토 | 이연희·박남일 반장 |
| 주차관리부 | 핵심·시토 | 양상규 고문 |
| 경영지원 | 핵심·시로·시뽀·시우 | 나우열M |
| 파트너팀 | 핵심·시모·시보 | 강습 강사진(`lessons@` 계정과 동일 범위) |

가입 시 perms JSON 에 `dept` 키를 같이 저장(관리자 화면 대기 목록에 부서 배지로 표시). `allowed()` 판정 로직은 `groups/modules/deny/all` 만 보므로 `dept` 는 무해.

## 3. 계정 정책

- 개인 구글 계정 허용. 비밀번호는 발급하지 않음(구글 전용 — 랜덤 문자열로 채워 로그인 불가 처리, 회사 계정 방식과 동일).
- 퇴사·이탈 = 관리자 화면에서 `차단`(즉시 로그인 불가) 또는 대기중이면 `삭제`.
- 관리자 비밀번호(별도 문) 는 변경 없음.

## 4. 되돌리기

기존 비밀번호 로그인 경로는 손대지 않음 — 문제 생기면 `/auth/login` 비밀번호 폼으로 계속 쓸 수 있다. 구글 로그인만 끄려면 서버 `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` 을 비우면 버튼이 "아직 설정 전" 안내로 바뀌고 나머지는 그대로.

## 5. 978 — 회원 카드 admin 전용 문제

`scripts/erp_modules_build.py` 의 CORE 딕셔너리에서 `member` 카드 `roles: ["admin"]` → `["admin","staff"]`. 생성기 재실행으로 `erp/modules.json` 반영. 원인은 `allowed()` 의 "권한 미배정 기본값" 경로가 `roles` 를 보는데 회원 카드만 admin 전용으로 박혀 있었던 것 — 임정은M·이경연 실장(둘 다 staff)이 기본 권한으로 못 보던 이유.

## 6. GM 확인 필요

1. 위 부서→그룹 매핑(특히 지원부·주차관리부를 시토 그룹 하나로 묶은 것)이 맞는지.
2. 구글 OAuth 클라이언트가 이미 서버에 등록돼 있어(`GOOGLE_CLIENT_ID/SECRET` 존재 확인됨) 개인 계정 로그인이 지금 라이브 상태 — 원치 않으면 끄라고 말씀만 하면 된다.
