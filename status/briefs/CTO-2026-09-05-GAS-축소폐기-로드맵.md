방식 = 기존 파일이 이미 쓰는 관례(`ERP_API_ON` 판정 + `_apiXxx().catch(gas)`) 그대로 재사용 — 새 패턴·새 파일 0. GitHub Pages(`ERP_API_ON=false`)에선 종전과 100% 동일 동작, ERP 도메인에서 서버 실패 시에도 자동 GAS 폴백이라 회귀 위험 없음.
검증 = `node --check` 로 스크립트 블록 구문 확인 통과. 로그인 쿠키가 있어야 여는 화면이라 브라우저 실클릭은 못했다 — 다음 로그인 세션에서 강습 회원관리 탭 1회 열어 콘솔에 API 실패 경고가 없는지 확인 요망.

**같은 화면에서 오늘 건드리지 않은 것(다음 전환 대상, 이유 명시)**:
- `cpo_churn_stats`·`member_registered_list`·`member_active_summary` — 서버 라우트(`/api/report/*`)는 이미 있으나 이 화면 안에서만 호출부가 4곳(줄 4209·4499·7342·8568·9975)으로 흩어져 있어 한 번에 안전히 바꾸기엔 검증이 부족하다. 개별 호출부 단위로 다음 배에서 하나씩.
- `월간운영계획.html`의 `readWorkApproval()`(todo_list, GM 행 포함 `include_gm=1&gmkey=1531`) — 서버 `/api/todo` 가 같은 열쇠 판정(`_gm_ok`)을 이미 구현했지만, 서버 env `GM_TODO_KEY` 값이 화면의 `1531` 과 실제로 일치하는지 이 세션에서 서버 접속 권한이 없어 확인 못 했다(SSH permission denied). 값이 다르면 에러 없이 조용히 GM 행만 빠지는 위험(폴백이 안 걸린다) — **키 값 대조 확인 전에는 전환 보류**.
