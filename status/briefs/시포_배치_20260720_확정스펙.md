## 2. 멤버십 회원관리 페이지 — `3. 웰페리온 가이드/cpo/member/membership.html`

### 2-A. 로딩 속도 【최우선】

- 원인 확정: `member_active_list` 콜드 GAS **~11초**, 전체 행 fetch.
- 해결 경로(인계문서 §6에 이미 적힌 것): **백엔드 요약 집계 액션 신설**. `renderActiveSummary()`가 `_activeRows` 순회로 카드를 계산하므로, 그 숫자를 서버가 주면 화면에서 뺄 수 있다.
- 참고 모델: `inquiry_stats`(응답 ~2KB 고정) · `cpo_today_stats` · `renewal.html`(~4KB 고정).
- **기능 회귀 금지**: 요약 카드(대기자·단기 회원 수) 값이 지금과 100% 동일해야 한다. 교차검증 수치로 증명할 것.

### 2-B. LOSS 회원 관리 카드 진입 시 헤더 【GM 지적】

- 현재: LOSS 명단을 보는데 헤더가 `총 유효회원`으로 뜸 → **틀린 맥락**.
- 변경: `LOSS 회원 704명` 처럼 **지금 보고 있는 집합의 이름 + 실제 건수**. 704는 예시이고 **동적 계산값**이어야 한다.
- **월 단위 보기 추가** — 기존 기간 토글 패턴(`_mdashPeriod`/`_mdashSetPeriod`) 재사용, 새 패턴 발명 금지.

### 2-C. 대기자 회원 관리 카드 — 2-B와 동일 처리

- 같은 결함(헤더가 `총 유효회원`). 같은 방식으로 수정. 월 단위 보기도 동일 적용.

### 2-D. 잔여일 색상

- **10일 이내 = 빨강** / **30일 이내 = 주황** / 그 외 = 현행.
- 색은 **기존 토큰 재사용**(`--red` / `--accent` 계열). 새 색 발명 금지.
- 이미 만료(잔여일 0 이하)는 빨강보다 더 확실히 구분되게(회색 처리 등) — 만료와 임박이 같아 보이면 안 된다.
