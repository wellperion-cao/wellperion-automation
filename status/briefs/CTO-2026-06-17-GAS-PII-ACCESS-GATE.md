# CTO-2026-06-17 · GAS PII 접근 게이트 활성화 완료

> 회원 개인정보(이름·연락처) 무인증 노출을 막는 접근 게이트를 **라이브 발효**했다. 무중단·무파손 순서로 완료.

## 무엇이 바뀌었나 (효과)
- **문의·VOC GAS**의 개인정보 조회(원시 이름·연락처 포함)는 이제 **접근 열쇠**가 있어야 열린다.
- 열쇠 없는 외부 접근 = `unauthorized` (개인정보 차단).
- **회원이 직접 쓰는 화면은 그대로** — 문의 제출·VOC 제출·통합 접수·마스킹 공개보드·마케팅 집계(숫자)는 열쇠 없이도 정상. 폼이 막히는 일은 없다.

## 직원(실무진)이 할 일 — 딱 1회
1. 실무진 공용 PC(cao 단일 로그인)의 크롬에서 가이드 ERP 대시보드를 연다.
2. 개인정보가 들어간 화면(예: home 문의·VOC 카드)을 처음 열면 **“접근 열쇠를 입력하세요”** 팝업이 뜬다.
3. **별도 전달받은 열쇠값**을 한 번 붙여넣는다 → 자동 새로고침 후 정상 표시.
4. 이후 그 브라우저에서는 다시 묻지 않는다(localStorage `wp_access_token`에 저장). 공용 PC 1대 = 전 직원 적용.
   - 열쇠를 잘못 넣었거나 안 보이면, 같은 팝업이 다시 떠서 재입력하면 된다.

> ⚠️ 열쇠값은 **이 문서·repo·메신저 공개채널에 절대 적지 않는다.** GM이 별도(비공개)로 1회 전달.

## 기술 메모 (AI 운영용)
- 게이트는 ScriptProperties `TOKEN_ENFORCE='1'` + `ACCESS_TOKEN`(공유 1값)으로 켜짐. 둘 다 충족해야 발효 — 코드가 아닌 **속성**으로 제어(요청 시점 런타임 읽기).
- **문의·VOC는 동일 ACCESS_TOKEN 1개 공유** → 프론트 단일 열쇠(`wp_access_token`)로 양쪽 모두 열림.
- 공개 면제 액션: (문의) `submit_inquiry`·`track_click`·`period_breakdown`·`funnel_conversion`·`type_channel_breakdown`·`click_stats`·`today_live` / (VOC) `voc_submit`·`voc_types`·`reg_submit`·`reg_board`·`reg_update`.
- 게이트 대상(열쇠 필요): `inquiry_list`·`voc_list`·`voc_update` 등 **원시 PII 반환 액션**.
- 라이브 배포ID는 **재배포 없이** 발효(속성은 모든 버전 공유). 임시 설정코드는 별도 throwaway 배포로 1회 set 후 **즉시 제거**(라이브 URL 무변경).
- **비상 롤백**(게이트가 직원을 막을 때): ScriptProperties에서 `TOKEN_ENFORCE` 삭제(또는 빈값) → 즉시 전부 통과(무중단). 코드 변경·재배포 불필요.
