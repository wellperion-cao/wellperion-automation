## 여기부터 복사 ↓↓↓

당신은 웰페리온 운영 실무를 돕는 AI입니다. ERP의 「종합 접수처」 보드에 있는 버그 3건을 고쳐 주세요.

### 대상 파일

`3. 웰페리온 가이드/wellperion_guide(main).html`

이 파일 안 **O2 종합 접수처 보드** 영역(대략 1396행~1800행 사이, `_regCard` · `_regHandlerSave` · `_regAssign` 등이 있는 곳)입니다.

화면: https://wellperion-cao.github.io/wellperion-automation/wellperion_guide(main).html#O2

---

### 버그 1 — 처리자가 두 번 표시된다 (제일 눈에 띄는 것)

**증상:** 접수 카드에 처리자 이름이 입력칸에 한 번, 그 아래 "처리자: 최준용" 이라는 줄로 또 한 번 나옵니다. 라이브 실측: 입력칸 33개 중 24개 카드에서 중복.

**원인:** `_regCard` 함수 안에 `COMMON_KEYS` 라는 배열이 있습니다. 이건 "카드 아래 추가정보 줄에 자동으로 나열하지 말 것" 목록인데, 여기에 `'처리자'` 만 빠져 있습니다. (담당·처리메모·부서·접수문자·조치문자는 다 들어있습니다.)

**고치는 법:** `COMMON_KEYS` 배열에 `'처리자'` 를 추가하세요. 한 단어면 끝납니다.

---

### 버그 2 — 저장이 실패해도 "저장됨 ✓"이 뜬다 (제일 위험한 것)

**증상:** 처리자 저장, 조치내용(메모) 저장, 접수문자/조치문자 체크, 담당자 배정 — **네 곳 모두** 서버가 실제로 저장했는지 확인하지 않고 무조건 성공 표시를 냅니다.

**원인:** 해당 함수들(`_regHandlerSave`, `_regMemoSave`, `_regSms`, `_regAssign`)이

- 버튼 글자를 `저장됨 ✓` 로 바꾼 **뒤에** 서버로 전송하고
- 전송 실패를 `.catch(function(){})` 로 **조용히 삼킵니다**

그래서 인터넷이 끊겨도, 서버가 거부해도, 화면은 초록불입니다.

**고치는 법:** 네 함수 모두 아래 순서로 바꿔 주세요.

1. 버튼을 먼저 `저장 중…` 으로 바꾼다
2. 서버 응답을 받는다 (`.then(r => r.json())`)
3. 응답의 `ok` 가 `true` 일 때만 `저장됨 ✓` (초록)
4. `ok` 가 아니거나 통신이 실패하면 **`저장 실패 ✕` (빨강)** 로 표시하고, 사용자가 다시 시도할 수 있게 원래 값을 그대로 둔다
5. **실패를 조용히 삼키지 마세요.** 화면에 반드시 보여야 합니다

체크박스(`_regSms`)는 특히 주의: 실패했으면 **체크 표시를 원래대로 되돌려** 주세요. 안 그러면 체크된 것처럼 보이는데 저장은 안 된 상태가 됩니다.

> 왜 이게 중요한가: 웰페리온에서 이미 같은 종류의 사고가 두 번 있었습니다(사내 기록 INC-011·INC-013 — 저장 실패를 화면이 성공처럼 표시해 데이터가 조용히 사라진 건). 같은 병이라 반드시 막아야 합니다.

---

### 버그 3 — 배정 버튼이 부실하다

**증상:** 지금은 크롬에서 우연히 동작하지만, 다른 브라우저나 상황에서 깨질 수 있습니다.

**원인:** HTML은 배정 버튼이 자기 자신을 세 번째 값으로 넘기는데(`_regAssign('id','분류', this)`), 정작 함수는 `function(id, category)` 로 **두 개만 받습니다.** 그래서 함수 안에서 전역 `event.target` 에 의지하고 있습니다.

**고치는 법:** 함수가 세 번째 값(버튼)을 제대로 받도록 고치고, `event.target` 대신 그 값을 쓰세요. 다른 세 함수(`_regHandlerSave` 등)는 이미 그렇게 되어 있으니 같은 모양으로 맞추면 됩니다.

---

### 지켜야 할 것

- **접수 데이터를 건드리지 마세요.** 화면 코드만 고칩니다. 시트·서버(Apps Script)는 수정 대상이 아닙니다.
- **O2 보드 밖은 손대지 마세요.** 이 파일은 ERP 전체가 들어있는 큰 파일이라, 다른 영역을 건드리면 GM님이 매일 보시는 화면이 깨집니다.
- 고친 뒤 **깃에 커밋·푸시**해야 실제 화면에 반영됩니다.
- ⚠️ **2026-07-20 현재 GitHub 장애로 배포가 밀려 있습니다.** 푸시해도 화면에 바로 안 나타날 수 있습니다. 장애 복구 후 반영됩니다 — 코드가 잘못된 게 아닙니다.

### 다 하고 나서 확인해 주세요

1. 접수 카드에 처리자가 **한 번만** 나오는가 (입력칸에만)
2. 처리자를 저장하면 `저장됨 ✓` 가 뜨고, **새로고침해도 값이 남아있는가**
3. 일부러 인터넷을 끊고 저장을 눌러보면 **`저장 실패 ✕` 가 뜨는가** (이게 핵심 — 이전엔 실패해도 성공처럼 보였습니다)
4. 담당자 배정 버튼이 정상 동작하는가

3번까지 확인되면 완료입니다. 결과를 GM님과 시우(AI COO)에게 알려 주세요.
