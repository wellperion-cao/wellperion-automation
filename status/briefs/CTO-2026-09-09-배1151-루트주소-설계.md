# ERP 첫 화면 주소 루트 전환 — 설계 (배1151 · 시토)

GM 지시(2026-09-09): 첫 화면 주소를 `/erp/` 에서 루트(`/`)로. 옛 주소는 301 로 살린다. 이 배는 설계·저장까지만 — 서버 반영은 하지 않는다.

## 1. 착지를 정하는 자리

로그인 성공 뒤 이동은 `server/erp_auth/app.py` 의 `next` 파라미터(기본값 `"/"`, `/auth/login` GET·POST 양쪽)가 정한다 — 이미 루트가 기본값이라 **app.py 는 고칠 게 없다.**

진짜 문제는 그 다음 단계였다: nginx `location /` 이 루트 요청(`/`)에 대해 저장소 루트의 옛 `index.html`(2026-06-06 자 · `wellperion_guide(main).html` 로 JS 리다이렉트하는 스텁)을 내주고 있었다 — ERP 모듈 홈(`erp/index.html`)이 아니었다. **착지 자리 = `server/erp_auth/erp.nginx.conf` 의 `location /` try_files.**

## 2. 고친 블록 (`server/erp_auth/erp.nginx.conf`)

```nginx
    # 옛 첫 화면 주소(/erp/) → 루트로 301(영구). 하위 경로(/erp/launchers/…·/erp/modules.json 등)는
    # 이 exact match 에 안 걸려 그대로 살아있다 — 첫 화면만 옮기고 폴더는 안 없앤다(배1151 · GM 2026-09-09).
    # 09-07 옛 주소 스텁을 지워 파트너팀 팀장이 404 를 본 사고 재발 방지 — 지우지 않고 리다이렉트만 건다.
    location = /erp { return 301 /; }
    location = /erp/ { return 301 /; }

    # 첫 화면 = ERP 모듈 홈(erp/index.html), 주소는 루트(배1151). 로그인 관문은 그대로.
    location = / {
        auth_request /auth/check;
        error_page 401 = @login;
        error_page 403 = @forbidden;
        try_files /erp/index.html =404;
    }
```

위 세 블록을 기존 `include /etc/nginx/conf.d/erp-locations/*.conf;` 다음, 일반 `location /` 앞에 끼워 넣었다.

- `location = /erp`·`location = /erp/` 는 **exact match** — nginx 는 exact match 를 최우선으로 처리하므로 `/erp/launchers/foo.html`·`/erp/modules.json` 같은 하위 경로는 이 규칙에 안 걸리고 기존 `location /` 로 그대로 흘러 지금과 동일하게 열린다.
- `location = /` 도 exact match 라 기존 `location /` (prefix) 를 대체한다 — 그래서 auth_request·에러 페이지 3줄을 그대로 복붙해 로그인 요구를 유지했다. `try_files /erp/index.html`(절대경로) = `root /srv/erp/www` 기준 `/srv/erp/www/erp/index.html` 을 그대로 서빙 — URL 은 `/` 그대로, 화면만 모듈 홈.
- 권한 판정 확인: `app.py:module_at()` 은 X-Original-URI `"/"` 에 대해 `modules.json` 어떤 항목과도 안 겹친다(직접 조회 완료 — index.html 을 모듈로 등록한 항목 없음). 즉 루트는 지금 `/erp/` 와 동일하게 **로그인만 요구, 별도 권한 게이트 없음** — 회귀 없음.

## 3. `/erp/` 절대경로 하드코딩 — 건수만 (고치지 않음, 웰리가 화면 쪽 별도 훑음)

저장소 전체에서 실제 URL 로 쓰인 절대경로 `/erp/` 참조 = **3건**:
1. `3. 웰페리온 가이드/erp/index.html:167` — JS: 세션 401 이면 `location.href = '/auth/login?next=/erp/'` (기능 코드 · 재로그인 뒤 옛 주소로 되돌아감)
2. `3. 웰페리온 가이드/cto/AWS_ERP_운영가이드.html:72` — 문서 링크 `https://erp.wellperion.com/erp/`
3. `3. 웰페리온 가이드/wellperion_guide(main).html:5032` — 문서 링크 `https://erp.wellperion.com/erp/`

(`/srv/erp/...` 형태의 서버 경로 문자열은 "/erp/" 부분 문자열 매치라 위 3건에서 제외했다.)

## 4. 반영 절차 (지금은 저장까지만 — 아래는 시토 세션이 GM 확인 뒤 실행)

1. `scp server/erp_auth/erp.nginx.conf ubuntu@<AWS_IP>:/etc/nginx/conf.d/erp.conf` (certbot 관리 파일이므로 HSTS 줄 등 기존 손 추가분 유지 확인 — diff 먼저 볼 것)
2. `sudo nginx -t` — 문법 통과 확인(실패하면 절대 reload 안 함)
3. `sudo systemctl reload nginx`
4. 확인할 주소:
   - `https://erp.wellperion.com/` → 로그인 안 된 상태면 `/auth/login?next=/`, 로그인 뒤 ERP 모듈 홈이 루트에서 보이는가
   - `https://erp.wellperion.com/erp/` → 301 로 `/` 로 가는가 (`curl -I` 로 `Location: /` 확인)
   - `https://erp.wellperion.com/erp` (슬래시 없이) → 301 로 `/` 로 가는가
   - `https://erp.wellperion.com/erp/launchers/...` (실제 파일 하나) → 그대로 200 열리는가
   - `https://erp.wellperion.com/erp/modules.json` → 그대로 200 열리는가
   - 회원·매출 등 기존 화면 하나 → 여전히 로그인 요구하는가(`auth_request` 살아있는지)

## 5. 되돌리는 법

`server/erp_auth/erp.nginx.conf` 에서 이번에 넣은 3블록(`location = /erp`·`location = /erp/`·`location = /`)만 삭제하고 다시 §4 절차로 올리면 원상 복구. 서버 파일이 `/etc/nginx/conf.d/erp.conf` 한 곳뿐이라 롤백도 같은 파일 재배포 한 번으로 끝난다.
