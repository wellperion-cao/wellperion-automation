## 2. ★최우선 발견 — safe_commit 경유 시 훅가드 11개 전부 미발화

`scripts/safe_commit.py`는 `commit-tree`+`update-ref`로 커밋을 만든다(스테일 트리·레이스 차단이 목적). 이 방식은 **git 훅(pre-commit/post-commit)을 전혀 발화시키지 않는다** — `safe_commit.py` 자체 주석(20행)에 이미 명시돼 있음. 즉 `.git/hooks/pre-commit`에 걸려 있는 아래 **가드 전부**가 safe_commit 경유 커밋에는 원래부터 안 돈다:

| pre-commit 훅 내 가드(실행 순서) | safe_commit 경유 시 |
|---|---|
| ① `precommit_phantom_delete_guard.py` | 미발화 — 단 safe_commit 자체가 동일 판정 로직을 내부 재구현(`_precheck_violations`)해 대체 확인됨 |
| ② `precommit_truncation_guard.py`(대량 라인 유실 차단) | **미발화, 대체 없음** |
| ③ `precommit_queue_guard.py`(큐 급감 차단) | **미발화, 대체 없음** |
| ④ `ssot/precommit_incident_guard.py` | **미발화, 대체 없음** |
| ⑤ `precommit_enforcement_guard.py`(공식값·금지경로) | **미발화, 대체 없음** |
| ⑥ `check_chatid_drift.py` | **미발화**(warn-only라 영향 작음) |
| ⑦ `check_reception_wp_drift.py` | **미발화**(warn-only) |
| ⑧ `precommit_erp_anchor_guard.py`(죽은 문서 앵커) | **미발화, 대체 없음** |
| ⑨ `precommit_sheet_link_guard.py`(시트 원본 링크 노출) | **미발화, 대체 없음** |
| ⑩ `precommit_secret_guard.py`(비밀값 평문 커밋) | **미발화, 대체 없음** — 가장 위험(토큰 유출 재발방지용) |
| post-commit `auto_log_adhoc_to_queue.py`(G1 자동기록, L15) | **미발화** — safe_commit은 push만 직접 호출(354행), auto_log는 호출 안 함 |

**근거:** `safe_commit.py` 현재 호출자 3개(`ig_publish_verify.py`·`ig_review_publish_watcher.py`·`publish_register.py`) 확인 — 아직 소수 경로지만, GM 지시(L21)로 "커밋=safe_commit 경유 의무화"가 2026-07-23 커밋(`feat(cto): 세션 커밋 safe_commit 경유 의무화`)으로 이미 진행 중이라 **앞으로 확산될수록 사각지대가 커진다.**

**대비:** `git_lock.py::git_commit_push()`(구 경로, real `git commit` 사용)는 훅이 정상 발화 — secret_guard 등 다 돈다. 즉 지금 저장소엔 "레이스는 막지만 훅가드는 못 받는" 경로와 "훅가드는 받지만 레이스 보호 없는" 경로가 **공존**한다. 둘 다 가진 경로가 없다.
