# 지원부 점검 단일출처 재설계 (시트 = 유일 원천)

작성: 시우(COO) · 2026-06-25 · GM 옵션A 승인

## 문제 (근본)
점검 분모가 **세 군데서 다른 데이터로** 계산돼 영구적으로 어긋남("또 안맞네"):
- **화면(점검)**: 하드코딩 `WEEKDAY/WEEKEND` 배열 + **브라우저 localStorage**(custom/hidden 항목) → 슬롯-시프트 기준. 26/20/19.
- **서버 today_live**: 구글시트 `SHEET_ITEMS` → 회차 기준. 74(합산).
- **17시 독려**: 또 다른 계산. 8/9.

→ 출처가 쪼개져 있어 **서버 재계산으로 화면값 재현 불가**. 화면값은 localStorage 의존이라 **기기마다 다를 수 있음**. 패치(삭제·재계산)로 해결 불가 — 구조 일원화 필요.

## 목표 아키텍처
**시트(SHEET_ITEMS) = 점검 항목·분모의 유일 원천.** 화면·서버·독려가 모두 시트를 경유해 **같은 숫자**를 본다(기기 무관).

### 핵심 결정 (구현 전 확정)
1. **공식 카운트 모델 = 성별별(per-gender)** — 남 탭=남 적용항목(공용+남전용), 여 탭=여 적용항목(공용+여전용). 성별 전용(수면실 남/찜질방 여)이 있어 남≠여 가능(매뉴얼 기준·GM 06-25 확인). 독려와 동일 기준.
   - 시프트: 회차 prefix am*→오전 / pm*→오후 / close*·'마감'→마감 / night*→야간(분모 제외).
   - 한 항목은 시프트당 1회(회차 여러개라도).
   - sched 요일/주차 필터: `"days|weeks"`(예 tue|2,4) — 오늘 요일·주차 일치만.
   - df_*(요일집중)=오늘 요일 일치 시 마감 1회.
2. **하드코딩 WEEKDAY/WEEKEND 배열 폐기** → 시트 시드로 이관(autoSync로 이미 시트에 있으면 검증·정합).
3. **localStorage custom/hidden 폐기** → 시트로 이관(잃지 않게 먼저 백업·마이그레이션).
4. **화면 분모 = today_live(서버/시트) 사용** — 화면이 자체 하드코딩 계산 대신 서버값 표시(현재 admin은 이미 그럼, 점검화면도 동일화).
5. **독려 = today_live 읽기** — 자체 계산 폐지.

## 구현 단계 (검증 우선)
1. **백업**: 현 시트 SHEET_ITEMS + (가능하면) GM 기기 localStorage 항목 스냅샷 → status/briefs.
2. **시트 정합**: 하드코딩 배열·localStorage 항목을 시트에 합류(중복·고아 정리, cx_/custom_ 포함 검토). 시트가 매뉴얼 전체를 담게.
3. **서버 today_live**: 위 모델(성별별·sched필터·시프트presence)로 확정 구현.
4. **화면**: collectDashboardData가 today_live 결과를 분모로 사용(하드코딩 계산 경로 제거). 점검 항목 목록도 시트 기준.
5. **독려**: daily_scheduler가 today_live 호출값 사용.
6. **검증**: 시크릿 크롬(기기 무관) + 다른 기기에서 화면=서버=독려 **동일 숫자** 확인. @HEAD 테스트배포는 인증게이트라 불가 → 라이브 검증 시 역롤백 준비(현 @111 안정).

## 리스크·주의
- 라이브 today_live는 home·12시 텔레그램·점검화면에 물림 → 신중·단계 배포·역롤백.
- @HEAD 테스트 URL이 Google 로그인 게이트 → 오프라인 검증 불가. 대안: 로컬 모의(시트 데이터 복제해 노드로 카운트 단위검증) 후 라이브 1회 + 즉시 확인.
- 마이그레이션서 항목 유실 금지(백업 필수). cx_(OP-6·OP-7)는 실제 항목 — 삭제 아닌 정식ID 이관.
- 회귀: CHKNOTI dedup·이슈집계·제출 영속 건드리지 말 것.

## 상태
설계 확정 대기 → 승인 시 단계1(백업)부터. 현 라이브=@111(스팸 dedup 적용·집계 미변경, 안정).
