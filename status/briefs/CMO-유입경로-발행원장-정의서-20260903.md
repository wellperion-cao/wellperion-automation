# 문의 유입 경로 칸 · 콘텐츠 발행 원장 칸 — 정의서

작성 AI 시모 · 2026-09-03 · 근거 = `3. 웰페리온 가이드/reports/260902_AWS전환_마케팅요청사항_A3.html` 요청 1·2번, GM 확정 방향(2026-09-03)

## 1. 목적 + 측정 시작 규칙

마케팅 1순위 지표 「노출→문의 전환율」(정본: `ssot/kpi.json` roles.cmo.kpi_html)을 재려면 문의 한 건마다 "어느 게시물에서 왔는지"가 남아야 한다. 지금은 이 칸이 없어 미측정 상태다.

**측정 시작 규칙(GM 확정):** 지난 문의는 소급해 채우지 않는다. 이 정의서가 실제 시스템(폼+DB)에 반영된 날짜부터 접수되는 문의에만 유입 경로가 채워진다. 그 이전 문의와, 반영 이후라도 경로를 특정할 수 없는 문의는 전부 코드값 `unknown`(기록없음)으로 채운다 — 빈칸이 아니라 명시적 값으로 채워 집계 시 분모에서 구분되게 한다.

**GM 확정 3결정:**
1. 유입 경로는 채널 단위가 아니라 **게시물 단위**까지 나눈다.
2. 지난 문의는 **비워 두고 새것부터** 쌓는다(경로값 `unknown`).
3. 발행 원장은 **ERP 안**(문의와 같은 DB)에 둔다 — 밖에 두고 연결만 하는 방식은 채택하지 않는다.

## 2. 표 A — 문의 유입 경로 칸

문의 화면(`3. 웰페리온 가이드/cmo/survey/wp_inquiry_form.html`)에는 이미 유형별 폼마다 `channel`(select, 라벨 "알게 된 경로"/"문의 경로") 필드가 있다. 값 목록이 채널 단위(예: "인스타그램" 하나로 개인·공식 계정 미구분)라 게시물 단위 분석이 안 된다. 이를 아래로 교체하고, 게시물 번호 칸을 새로 추가한다.

| 칸 이름 (필드명 / 한글) | 타입 | 값 목록 | 필수 |
|---|---|---|---|
| `channel_code` / 유입 채널 | select (기존 `channel` 필드 값 목록 교체) | 채널 6종 + 특수값 5종 — 아래 표 | 필수 |
| `post_id` / 게시물 번호 | hidden text | 표 B의 원장 키(`post_id`, 예: `CMO-2026-07-01-SUMMER-CAMP-EP3-DANGGN`) 그대로 참조. 없으면 공란 | 선택 |
| `channel_captured_at` / 유입 기록 시각 | timestamp (자동) | 문의 제출 시각과 동일값 자동 기록 | 자동(항상) |

**채널 코드 표 (11종):**

| 코드 | 한글 표시 | 비고 |
|---|---|---|
| `ig_personal` | 인스타그램(개인 namuk.wellperion) | 채널 6종 |
| `ig_official` | 인스타그램(공식 wellperion) | 채널 6종 |
| `naver_blog` | 네이버 블로그 | 채널 6종 |
| `naver_cafe` | 네이버 카페(동부이촌동) | 채널 6종 |
| `danggn` | 당근 | 채널 6종 |
| `kakao` | 카카오톡 채널 | 채널 6종 |
| `direct_visit` | 직접방문(오프라인·간판) | 특수값 |
| `referral` | 소개·지인 | 특수값 |
| `naver_place` | 네이버 플레이스 | 특수값 |
| `search` | 검색(네이버 등, 콘텐츠 무관 유입) | 특수값 |
| `unknown` | 기록없음 | 특수값 — 측정 시작 전 문의 + 경로 특정 불가 문의의 기본값 |

**게시물 번호 형식:** 표 B 발행 원장의 기본키를 그대로 쓴다. 현재 검수 큐(`review_queue.json`)의 `id` 필드 형식(예: `CMO-2026-07-01-SUMMER-CAMP-EP3-DANGGN`)을 원장 이관 후에도 유지 — 새 형식을 만들지 않는다.

**채워지는 시점(둘 다 적용):**
- **사용자 선택** — 문의 폼 제출 시 `channel_code` select를 방문자가 직접 고른다(URL 파라미터가 없거나 방문자가 값을 바꾼 경우 이 값이 최종값).
- **URL 파라미터 자동 채움** — 콘텐츠에 붙이는 랜딩 링크에 `?src=<channel_code>_<post_id>` 형식으로 붙이면, 폼 로드 시 JS가 파싱해 `channel_code` select의 기본 선택값과 숨김 `post_id` 값을 미리 채운다. 방문자는 여전히 `channel_code`를 수정할 수 있다(둘이 다르면 방문자가 고친 값이 우선).

## 4. 이사 규칙 — 179건 → 원장

- **1:1 매핑:** `id`→`post_id`, `title`→`title`, `post_url`→`external_url`, `status`→`status`, `published_at`→`published_at`, `note`→`note`.
- **변환 매핑(`channel`+`account` → `channel_code`):**
  - "인스타그램 (namuk.wellperion)" / account `namuk.wellperion` → `ig_personal`
  - "인스타그램 (wellperion 공식)" / "인스타그램 (wellperion)" / account `wellperion`·`wellperion 비즈(cao)` → `ig_official`
  - "네이버 블로그" → `naver_blog`
  - "네이버 카페 (동부이촌동)" → `naver_cafe`
  - "당근채널" → `danggn`
  - "카카오 채널" → `kakao`
- **비워 두는 칸:** `format`(이미지/영상) — 과거 179건은 표기가 없어 지어내지 않고 `unknown`으로 채운다. `reach`/`inquiry_count`는 애초에 저장 칸이 아니므로 이관 대상이 아니다.
- **버리는 칸:** `digest_title`·`digest_intro`·`url`·`review_artifact`·`writer`(각 1건) — 원장 스키마 밖. `qc_flags`·`info_lines`(각 3건)는 부속 메타로만 유지.
- **발행 워처가 바뀌는 지점 1줄:** 발행 완료를 판정해 `review_queue.json`에 항목을 append하던 워처가, 파일 대신 이 원장 테이블에 `insert`하도록 그 지점 하나만 바꾸면 된다(로직 무변경, 쓰기 대상만 교체).

## 5. 폼 쪽 변경 1줄

`wp_inquiry_form.html`의 `channel` select(라벨 "알게 된 경로"/"문의 경로") 값 목록을 표 A의 채널 코드 11종으로 교체하고, URL `?src=<channel_code>_<post_id>` 파라미터로 기본값을 자동 채운다(방문자가 직접 수정 가능). 화면 코드 자체는 이번 정의서에서 고치지 않는다 — 정의만 한다.

## 6. 전환율 계산식

`전환율(%) = (측정 시작일 이후 접수된 문의 중 해당 post_id로 귀속된 문의 수) ÷ (그 게시물의 도달, cmo_reaction_scorecard.json latest_reach) × 100` — 게시물 단위로 먼저 계산한 뒤 채널·기간으로 합산한다.
