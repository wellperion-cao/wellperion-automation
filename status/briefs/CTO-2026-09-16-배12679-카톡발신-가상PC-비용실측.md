## ③ 카카오톡 PC — Windows Server 설치·실행 가능 여부

- 카카오 공식 고객센터 "지원되는 Windows OS 버전" 페이지(cs.kakao.com)는 JS 렌더 페이지라 이번 도구로 직접 못 열었음. 검색 스니펫 기준 공식 지원 OS = **Windows 7/8/8.1/10/11**(클라이언트 계열만 나열) — Windows Server는 목록에 없음.
- Windows Server에서 실제로 카카오톡 PC를 돌린 실사용 후기 2건 이상 = **못 찾음(미확인)**.
- 확인된 일반 사실: AWS EC2는 **Windows Server AMI만 제공**한다(Windows 10/11 데스크톱 OS는 마이크로소프트 라이선스 정책상 EC2로 못 띄움). AWS 안에서 Windows 10/11 데스크톱이 필요하면 **Amazon WorkSpaces가 사실상 유일한 경로**다.
- 결론: EC2 Windows Server 쪽은 카카오톡 PC가 설치·구동될 수는 있으나 **카카오 공식 지원 대상이 아니다(추정)** — 되는지 여부는 실제로 한 대 띄워 로그인까지 해봐야 확정된다(이번 조사는 결재 전 사전 조사라 생성 안 함).

## ④ 필요 조건

- **로그인**: 법인폰 인증번호 1회 + 새 기기 등록, 이후 카카오 "PC 인증 유지" 설정으로 재인증 주기 연장(정확한 주기 일수는 미확인).
- **세션 유지**: `scripts/kakao_report_sender.py` 확인 결과 발신기는 `win32gui`/`pywinauto` **창 핸들 기반 UI 자동화**(포그라운드 전환·화면 요소 클릭) — 화면이 실제 렌더링되는 콘솔 세션이 살아 있어야 동작한다.
  - Windows Server(RDS 다중세션 구조)는 RDP 클라이언트 접속이 끊겨도(Disconnected) 세션의 데스크톱 컴포지팅이 계속 도는 구조라, 이론상 `tscon` 콘솔 되돌리기 없이도 유지될 가능성이 높다(실측 안 함).
  - WorkSpaces는 Windows 10/11 데스크톱 경험 기반 단일세션이라, 접속이 끊기면 화면 잠금·자동화 중단 우려가 있다 — `autologon` + 화면잠금 해제 설정이 별도로 필요할 수 있다(미실측).
  - 어느 쪽이든 GM PC에서 이미 겪은 포그라운드 잠금류 문제(카카오톡 "대화 내보내기" 창 잠금, `kakao_report_sender.py` 09-08 재현 주석)는 동일하게 남는다.
- **카카오 ToS 리스크**: 본인 계정 UI 자동화는 회색지대라는 내부 판단이 이미 있다 — 법인폰 계정이라도 자동화 성격은 같아 리스크는 동일하다. 소량 내부용 원칙을 유지해야 한다.
- **GM PC → AWS 이전 시 바뀌는 것**:
  - `kakao_rooms.json`(창 핸들 재등록 — 새 세션에서 방을 다시 열어야 값이 잡힘)
  - 로그 경로(로컬 절대경로 → 서버 경로 전환)
  - 예약작업: 이번 조사에서 작업명에 "kakao"가 들어간 예약작업 **4건 실측 확인** — `Wellperion-Kakao-External-0630` · `Wellperion-Kakao-Pending-0900` · `Wellperion-Kakao-Sales-Report-0930` · `Wellperion-Ops-Kakao-Export-2130`. 내부적으로 `kakao_report_sender`를 간접 호출하는 예약작업까지 전수조사는 안 함(더 있을 수 있음 — 미확인).
