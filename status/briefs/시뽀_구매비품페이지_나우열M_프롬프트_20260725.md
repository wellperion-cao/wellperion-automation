## 탭별 요구사항
### ② 구매진행
- `procCall("list",{mode:"active",noimg:1})` + done 병합으로 내 요청 목록을 단계 트랙으로 표시:
  요청(품의) → 검토 → 승인 → 발주(26열 구매날짜 기입 시) → 입고(아래 규칙)
- '입고' 판정 1차 규칙: 구매날짜가 있고 직원이 [입고 확인] 버튼을 누르면 완료 처리.
  [입고 확인] = ③비품관리 원장에서 해당 품목 qty +N 갱신(신규 품목이면 행 추가) + note에 "입고 YYYY-MM-DD" 기록.
  **진행상황 12열에 '입고' 값을 새로 쓰지 않는다** (GAS 상태기계 변경은 이번 범위 밖).
- 승인/미승인 상태 전환 UI는 만들지 않는다 — 💰구매 승인은 GM 결재 영역이라 기존 관리자 표면(비번 게이트)에만 있다. 직원 화면은 조회 전용.

### ③ 비품관리
- SUPPORT_SUPPLY 보드를 읽어 지원부 체계 탭과 동일한 표(분류·품명·수량·위치·담당·발주점·비고) CRUD.
- 발주점(reorder) 미달 품목 = '발주 필요' 강조(기존 supplyIsLow 로직 이식) + 그 행에 [구매요청으로] 버튼 → ①탭으로 이동하며 물품명 자동 채움.
- 불용 처리: 행 삭제가 아니라 note 앞에 `[불용 YYYY-MM-DD]` 접두어 + 표에서 회색·별도 '불용' 필터로 분리 표시. (스키마에 새 필드를 늘리지 않고 note 재사용 — 9KB 상한 방어)
