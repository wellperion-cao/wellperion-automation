# 배1039-C — 종합접수처 서버 원천 전환·접수번호 통일 (시토)

작성 2026-09-05 · 대상 서버(`server/erp_api/`) 전용 · 화면·워드프레스는 시우 소관(안 건드림)

## 결론 한 줄
접수번호 통일은 실측 결과 **이미 되어 있었다**(오늘 배984 이후). 대신 그 배984 전환이 만든 새 구멍 —
**신규 접수건의 상태변경(reg_update)이 100% 실패**하는 버그 — 를 찾아 서버 API로 메웠다.

## 1. 번호 통일 — 실측: 이미 OK
`origin_switch.py` 의 `NO_SERVER["reception"]` 이 막던 문제(서버 L260904-101010 vs GAS RECEPTION-n)는
**2026-09-05 배984(커밋 af713fa1c) 부터 이미 무관해졌다.** 확인 방법:
- `reception_block.html`·`wp_reception_block_en.html`·`public/{ko,en}/reception.html` 5개 폼 전부
  `_rcSubmitUrl()` 이 `https://erp.wellperion.com/api/reception/submit` 로 **고정 배선**돼 있다(도메인 분기·폴백 없음).
- `/api/reception/submit`(`api_reception.py`)은 `origin_switch` 를 아예 보지 않고 `reception_seq` 로
  `RECEPTION-<n>` 을 곧장 발급해 손님에게 그대로 돌려준다 — 손님 receipt 번호 = 화면·보드에 뜨는 번호, 하나다.
- 옛 통로 `POST /api/intake/reception`(`api_intake.py`, L-형식 발급)은 전 저장소 검색으로 **호출부 0건** 확인
  — 죽은 경로다. `origin_switch.NO_SERVER["reception"]` 은 이 죽은 경로 전용이라 값은 그대로 `dual` 로 뒀다
  (지우면 죽은 L-형식 발급 코드가 스위치 파일 설정에 따라 되살아날 수 있어 위험 대비 이익이 없음).
- 조치: 주석만 갱신 — `origin_switch.py`·`api_intake.py` 에 "이 경로는 이제 아무 화면도 안 부른다" 명시.

## 2. 발견한 버그 — 상태변경이 오늘부터 조용히 실패 중이었다
배984 는 접수·습득물 **생성**만 서버 직행으로 바꾸고 시트는 "이후 갱신 안 됨(동결)" 으로 설계했다.
그런데 `종합접수처_현황.html` 의 상태·담당·메모 **갱신**(`reg_update`)은 여전히 옛 GAS(`RECEPTION_EXEC_URL`)로 간다.
GAS `_regUpdate` 는 시트를 행 단위로 스캔하는데(`_vFindRow`), 배984 이후 생긴 접수건은 시트에 아예 없으니
**"해당 접수ID를 찾을 수 없습니다"** 로 실패한다 — 오늘 이후 접수된 모든 건은 상태 변경·담당 배정·메모 저장이
화면에서 눌러도 조용히 안 먹힌다. 코드 추적 + 로직으로 확인(실제 GAS 호출은 안 함).

## 3. 조치 — POST /api/reception/update 신설
`server/erp_api/api_reception.py` 에 서버 원장(`reception_items`) 직접 갱신 엔드포인트 추가. GAS 호출 없음.
- 입력: `{id, status?(접수|처리중|완료), memo?, memberReply?, handler?, reporter?, name?, targetStaff?, dept?, dueDate?, policyFix?}`
  — 옛 `reg_update` 가 받던 칸과 1:1(화면 `_update()` 함수 수정 없이 그대로 붙일 수 있게).
- 없는 ID·잘못된 상태값은 `{ok:false, error:"..."}` 로 응답(GAS 와 같은 문구).
- 라이브 배포 완료. 테스트 접수 1건(`TEST-1039C-1`)으로 성공·없는ID·잘못된상태 3케이스 검증.
  **1차 검증에서 없는ID 케이스가 500 으로 새는 버그를 실측으로 발견**(with 블록 안에서 먼저 close() 하고
  return 하니 커밋이 닫힌 연결을 때렸다) → 즉시 수리·재배포·재검증 통과. 테스트 행 삭제 확인(격리 완료).

## 4. 안 건드린 것
- `api_write.py`·`sync_members.py`·`api_members.py` — 다른 레인(1039-A) 작업 중, 손 안 댐.
- `reg_delete`·`lf_handover`·`lf_delete`·`hold_complete`·`reg_staff_suggest` — 아직 GAS(`/api/write`) 그대로.
  범위 밖(브리프가 요청한 건 "상태변경(처리중/완료·담당배정)" 뿐).
- `origin_switch.json` 값(라이브 스위치 파일) — 안 바꿈. `write_reception` 은 위 나머지 5개 액션이 계속 쓰므로
  그대로 `dual` 유지가 맞다(`reg_update` 는 이제 이 새 엔드포인트로 옮겨가 스위치와 무관해진다).
- 화면(`종합접수처_현황.html`)·워드프레스 — 시우 전담 지시대로 안 건드림.
