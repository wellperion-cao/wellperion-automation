# 시모 → 웰리 : 작업 현황 로그 전사 확장 배정 제기 (2026-07-23)

GM 2026-07-23 "타 C-Level 확장 안내면 웰리 시키면 되는거 아냐?" 지시. 확장 배정·순서는 오케스트레이션 담당인 웰리 판단 영역이라 시모가 직접 타 C-Level 페이지에 손대지 않고 웰리에게 제기한다.

---

## 무엇을 만들었나

전 C-Level 공통 「작업 현황 로그」 틀. 배9820(GM 2026-07-23 지시로 신설). M1(마케팅)에 최초 적용·라이브 반영 완료.

## 두 구획

- **📋 한 일** — 자동 기록.
- **⚠️ 빠진 것** — 짝 불일치 자동 적발.

★핵심 설계: 로그는 "한 일"만 보여주므로 **"안 한 일"을 잡는 감지가 반드시 같이 있어야** 한다. 계기 = AI하루 EP10이 제작됐는데 검수큐 등록이 누락돼 아무도 몰랐던 사고.

## 구성 파일

- `scripts/worklog.py` — 공용 기록 모듈
- `scripts/worklog_gaps.py` — role별 규칙 등록부
- `3. 웰페리온 가이드/_assets/worklog_panel.js` — 공용 화면 조각(기존 gate.js·print_options.js 관례)

## 타 C-Level이 붙이는 법 (인계 핵심)

1. 자기 페이지에 `<div data-worklog="{role}"></div>` + 스크립트 태그 1줄
2. `worklog_gaps.py` 의 role별 규칙 등록부에 **자기 도메인 감지 규칙만** 추가
3. 기록은 자기 자동화 코드에 `worklog.log(role=..., ...)` best-effort 호출 얹기

새 화면·새 파일·새 예약작업 불필요.

## 데이터 규격(고정 계약)

- `status/worklog.jsonl` 한 줄 = `{ts, role, area, event, result(ok|warn|fail), detail, ref, url}`
- `status/worklog_gaps.json` = `{generated_at, gaps[{role,severity(high|mid|low),title,detail,hint,ref,age(신규|누적),first_seen}], rules_run, summary}`

## ★설계 원칙 2개(꼭 전달)

1. **평상시엔 조용해야 한다** — 신규 0건이면 배지 없음, 과거 누적은 접힌 한 줄. 매일 수십 건이 떠 있으면 아무도 안 본다.
2. **0건일 때도 "빠진 것 없음 ✅" 줄을 숨기지 않는다** — 조용한 게 정상인지 고장인지 구분돼야 한다.

## CMO 실적(효과 증거)

규칙 8종 가동. 첫 스캔에서 실제 적발:
- 콘텐츠 원본 폴더 소실 7건(그동안 아무도 몰랐음)
- 발행완료인데 주소 없음 47건(→오늘 46건 회수)
- 아무도 호출하지 않는 자동화 4건(그중 GM이 만들게 한 재발방지 감사기가 저장소에서 삭제된 채 방치돼 있던 것 포함)

## 웰리께 요청

시우(O1 운영)·시포(회원)부터 확장 배정. 시모는 **규격 제공·질문 응대**만, 타 도메인 규칙은 각자가 작성(도메인을 모르는 사람이 만든 규칙은 오탐만 낸다).

## 시모가 직접 안 한 이유

타 C-Level 페이지·도메인 침범 금지. GM 2026-07-23 "웰리 시키면 되는 거 아냐" 지시.
