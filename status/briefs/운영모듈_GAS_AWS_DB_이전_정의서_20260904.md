### 3. 상태값
- **접수 상태** (`LEGACY_RECEPTION_STATUSES`): 접수 → 처리중 → 완료. 자동 전이(`_regEffectiveStatusOnMemo`): 사람이 status를 주면 그 값 / 없고 memo가 비어 있지 않고 `[초안]`으로 시작하지 않으며 현재 '접수'면 '처리중' / 완료→재오픈·처리중→완료는 사람만. 완료 전환 순간 memberReply 비어 있으면 카테고리 템플릿 채움. 셀 배경색 주황/파랑/초록.
- **SLA 상태**(계산값, 저장 안 함 · `_regComputeSla`): `-`(SLA 없음·파싱실패) / 완료 / 초과(remainH<0) / 임박(remainH ≤ SLA×25% 또는 ≤2h) / 정상. 분실물은 대신 3단계.
- **분실물 3단계**(`_regLostStage`, 접수 경과시간): <720h 보관 / <1440h 공지 중 / ≥1440h 이관대상. 60일 넘은 미완료 건은 트리거가 status=완료 + memo 뒤에 `[자동 종결 날짜] 60일 경과 …` 덧붙임(`_regCloseExpiredLost`).
- **습득물 단계**(`LF_STATUS`): 게시중 → 수령완료(handover) / 게시중 → 폐기물·경찰인계(자동 · 현재월 ≥ 습득월+2, consumable→폐기물, 그 외·빈값→경찰인계, disposedAt=오늘). 자동 처분은 크론이 아니라 lf_gallery·lf_list·lf_disposal **읽을 때** 실행(read-time sweep). 수령완료·폐기 이후 handover 거부(`ALREADY_HANDLED`).
- **점수제 칸**: dueDate·policyFix는 자유 text만 저장. 점수 판정은 GAS에 없음 — `scripts/report_stream_2b_reception.py`(dueDate 비면 접수+3일 간주). 점수판(`reg_scoreboard`)은 별개: 접수 1점(reporter) + 완료 1점(handler, status=완료).
- **휴회**: 처리메모='휴회완료' + 처리일시(비어 있을 때만 오늘) = 완료.

### 4. 쓰기 진입점
공통 게이트(`_vProcess`): ① 접근키 — 공개 액션 목록 밖이면 `TOKEN_ENFORCE='1'` 이고 `ACCESS_TOKEN` 설정 시 `key` 일치 필요(기본 OFF=전부 통과). ② 제출토큰 — reg_submit·voc_submit·lf_submit·lf_handover는 `t`(또는 `token`)가 `RECEPTION_SUBMIT_TOKEN`(폴백 VOC_SUBMIT_TOKEN, 없으면 코드 기본 `wlp_voc_7b3f9a2e6c1d4085`)과 일치해야 함(`RECEPTION_GATE_OFF='1'`이면 해제) + 속도제한(전역 40/분 · 같은 지문 60초 중복 차단 · 캐시 장애 시 통과).

### 7. 이전 시 주의
- **순번 경합**: LockService 5초 대기 실패해도 진행 → 이론상 중복 번호 가능. DB에서는 시퀀스/`SERIAL`로 대체하고 표시번호 `RECEPTION-n`은 파생.
- **재제출 흡수**는 시트 최신순 정렬 전제(상위 20행). DB에서는 `WHERE category,contact_digits,status='접수',created_at>now()-30min` 쿼리로 치환.
- **시트 재정렬·상태색·열 자가치유**(`_regGetSheet`가 없는 헤더 뒤에 추가) = DB에서 불필요.
- **PII**: 접수 name·contact·photoUrl, 습득물 receiver·receiverPhone·ownerName·ownerContact·signUrl. 공개 응답은 §5 마스킹 규칙 유지. reg_list·lf_list는 인증 뒤로. reg_update가 현재 공개(무인증) — REST에서는 인증 필수로 올릴 것.
- **사진**: 현재 `ANYONE_WITH_LINK` 공개 URL을 시트에 저장·갤러리에 노출. S3는 접수사진·습득물사진 = 공개 read 버킷(또는 CloudFront) · **서명은 비공개 버킷**(presigned만). 기존 Drive URL은 그대로 문자열로 옮기고 `_vExtractFileId_` 형태(`/d/<id>/`) 의존 코드는 버린다.
- **6개월 서명 파기**: signPurgeAt ≤ 오늘 → 객체 삭제 + signUrl='(파기됨)'. GAS엔 호출 트리거가 없어 실제 실행 여부 미확인 → 이전 후 일일 크론으로 확정.
- **습득물 자동 처분·분실물 60일 종결**은 읽기 시점/30분 트리거 의존 → 크론 1개로 통합.
- **제출토큰**이 클라이언트 6개 폼에 평문(`wlp_voc_7b3f9a2e6c1d4085`) — 값 바꾸면 접수 즉시 막힘. 이전 시 폼과 동시 교체.
- **삭제 PIN** 기본 '1200' 코드 하드코딩.
- **날짜가 문자열**: `yyyy-MM-dd HH:mm:ss`(KST) / `yyyy-MM-dd`. 파싱 실패 행은 SLA `-`로 남아 있음 — 이전 시 실패 행 목록 뽑을 것.
- **레거시 '접수 RECEPTION' 탭·voc_* 액션**: 탭이 실제로 없음(07-27 실측). 이전 대상 아님, 호출자 잔존 여부만 확인.
- GAS URL(`AKfycbwk2XS1…VcF3gQ/exec`) 하드코딩 파일: reception_block.html · wp_reception_block_en.html · wp_lookup_block.html · wp_lookup_block_en.html · wp_lost_found_register_block.html · wp_lost_found_gallery_block.html · wp_lost_found_gallery_block_en.html · lost_found_register.html · lost_found_gallery.html · lost_found_disposal.html · 종합접수처_현황.html · wellperion_guide(main).html · 월간운영계획.html (이상 `3. 웰페리온 가이드/`) · `scripts/collectors/ops_shared.py` · `scripts/erp_status_publisher.py` · `scripts/telegram_health_check.py` · `telegram_bot/daily_scheduler.py` · `.deploy-todo/업무&결재 현황.js` · `status/gas_push_baseline.json` · 회사문서/나우열M_업무SSOT_점수판_프롬프트.md (백업·아카이브·scratchpad 제외).

### 8. DB 테이블 초안 (Postgres)
```sql
CREATE TABLE reception (               -- 접수 6종 통합 (탭 6개 → 1테이블 + category)
  id            BIGSERIAL PRIMARY KEY,                    -- RECEPTION-n 의 n (기존 값 그대로 적재, 시퀀스는 max+1로 재설정)
  category      TEXT NOT NULL CHECK (category IN ('lost','facility','clean','praise','voice','complaint')),
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),       -- 접수일시
  name          TEXT NOT NULL,   contact TEXT NOT NULL,   -- 이름·연락처 ('익명'·'지원부 점검' 문자열 포함)
  contact_digits TEXT GENERATED ALWAYS AS (regexp_replace(contact,'\D','','g')) STORED,
  loc           TEXT, content TEXT, photo_url TEXT,       -- 장소·내용·사진URL
  status        TEXT NOT NULL DEFAULT '접수' CHECK (status IN ('접수','처리중','완료')),
  memo          TEXT, dept TEXT,                          -- 처리메모·부서
  handler TEXT, reporter TEXT NOT NULL DEFAULT '회원', member_reply TEXT,  -- 처리자·접수자·회원안내
  due_date      TEXT, policy_fix TEXT,                    -- 완료예정일·정책반영 (자유 text 유지)
  extra         JSONB NOT NULL DEFAULT '{}',              -- 카테고리별 추가칸 {itemName,lostWhen,equipName,severity,usable,issueKind,urgency,targetStaff,episode,anonymousPref,area,occurredAt}
  source        TEXT,                                     -- 'check' 등
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ON reception (created_at DESC);
CREATE INDEX ON reception (category, status, contact_digits, created_at DESC);  -- 재제출 흡수·필터
CREATE INDEX ON reception (contact_digits, name);                                -- reg_lookup

CREATE TABLE lost_found (              -- 습득물 (LF_HEADERS + Q~V)
  id BIGSERIAL PRIMARY KEY,                               -- LF-n
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(), found_when TEXT, found_loc TEXT, item_desc TEXT,
  photo_url TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT '게시중' CHECK (status IN ('게시중','수령완료','폐기물','경찰인계')),
  category TEXT NOT NULL DEFAULT 'general' CHECK (category IN ('consumable','general','valuable')),
  staff TEXT, keep_loc TEXT, memo TEXT,
  receiver TEXT, receiver_phone TEXT, handed_at TIMESTAMPTZ, handover_loc TEXT, handover_staff TEXT,
  owner_name TEXT, owner_contact TEXT, provided_date TEXT,
  sign_key TEXT, sign_purge_at DATE,                      -- 서명 S3 key(비공개) · 수령+6개월
  disposed_at DATE
);
CREATE INDEX ON lost_found (status, created_at DESC);

CREATE TABLE sla_notified (reception_id BIGINT PRIMARY KEY REFERENCES reception(id));  -- REG_SLA_NOTIFIED_IDS 대체
-- 휴회접수: 시포 GAS 원장 → 본 이전 범위 밖. 필요 시 hold_intake(name, phone, hold_start DATE, status, done_at DATE, memo).
-- 설정(토큰·chat_id·SLA시간·부서표·템플릿)은 코드 상수 → 환경변수/설정 테이블. 레거시 접수 RECEPTION 탭은 테이블 없음.
```
원장 칸 ↔ 컬럼: 접수ID→id · 카테고리(label)→category(key) · 접수일시→created_at · 이름/연락처/장소/내용/사진URL/상태/처리메모/부서/처리자/접수자/회원안내/완료예정일/정책반영 → 동명 snake_case · 추가칸 → extra JSONB. 습득물은 §1-2 key → snake_case, 서명URL→sign_key.

이 GAS 하나에 TODO 외에도 공지서식·상품기획·카톡방목록·home_kpi(매출/지출/VOC 집계)·GitHub 커밋 중계·배(항로) 휴지통·AI배 탭이 같이 산다. 본 정의서는 **업무·결재(TODO) 축만** 다룬다. 나머지는 §6에 의존성으로만 적는다.

### 2. 키
- id = `'TODO-' + KST yyyyMMddHHmmss + ms 3자리`. 서버 유일성 검사 없음(밀리초 충돌 이론상 가능).
- 중복 업무명: **서버 없음**. 프론트 `checkDuplicateTitle()`이 진행중 목록에서 동일 제목 찾으면 confirm(「같은 업무명이 이미 있습니다」) → 확인=기존 편집 열기 / 취소=새 행 생성. 즉 같은 이름 행이 여러 개 있을 수 있다.
- 행 탐색 = A열 id 문자열 일치(`_findRow`). 삭제 = 물리 행 삭제.

### 3. 상태값
- 상태: `진행중`(기본) · `완료` · `보류`. 그 외 값 거부 없음.
- 결재상태(서버가 쓰는 값): `''`(결재 없음) · `대기`(결재요청 있음) · `부서장 완료` · `GM 완료`(라인이 더 남았을 때 — 현 라인은 GM 종착이라 실제로는 안 찍힘) · `결재완료` · `부서장 반려` · `GM 반려`. 구 `대표님 *` 문자열 데이터 잔존 가능(프론트는 `/반려/`·`/완료/` 정규식 매칭).
- 결재선(`_buildApprovalRoute`): 결재요청 또는 `===BUDGET===` 있으면 결재 대상. 라인 = [`부서장`(결재요청에 실장/소장/나우열M 중 하나가 체크돼 있고 담당자에 김남욱GM 없을 때)] → `GM`(항상 최종). 대표 단계는 라인에 없음(2026-06-16 폐지) — 대표는 `대표싸인` 칸 3상태로 별도.
- 반려 = 싸인 3칸·결재완료시각·결재요청 비움 + 결재상태 `<role> 반려` + 내용에 `===반려이력===` append. 상태는 진행중 유지.
- 재상신 = todo_update에서 결재요청 값이 **바뀌었을 때만** 결재상태 `대기`로(본문만 고치면 반려 흔적 유지).
- GM 최종승인 = 결재상태 `결재완료` + 결재완료시각 + 상태 `완료` + 완료일 + 완료 탭 복사.

### 5. 읽기 진입점
- `todo_list` (GET): 전량 반환 `{ok,count,data:[{한글칸:값}]}`. 필터 `owner`(완전일치)·`status`·`category`.
  - **GM 행 규칙:** `include_gm=1` **그리고** `gmkey` == Script Property `GM_TODO_KEY`(양쪽 trim)일 때만 담당자에 `김남욱GM` 포함 행을 돌려준다. 그 외엔 제외. 필터 없음+GM 제외 응답만 캐시(300초, 90KB 조각). GM 행 응답은 캐시 안 탐.
  - 소비자: 업무 현황 SSOT(GM 없이) · 결재 현황 SSOT(2026-09-03부터 `include_gm=1&gmkey=1531` — **키가 공개 HTML에 평문**) · G1/GM업무(_owner_directive.js) · rep_approval_relay.py(`hangro_board._gm_key()` = 환경변수 `GM_TODO_KEY` 또는 `telegram_bot/.env`).
- `todo_scoreboard`: 담당자별 진행중/완료/기한초과 건수. GM 행 제외 고정.
- `ai_list`: AI배 탭 전량. `todo_categories`: 9분류.
- `board` / `saveBoard`: **이 GAS가 아니다.** 공용 저장소 = 점검 GAS(`.deploy-check/지원팀 일일점검.js`, exec `AKfycbyXw4ZaA6hLK567…`). 저장 = 그 프로젝트 Script Properties `BOARD_<key>` 에 JSON 문자열(속성 1개당 9KB 천장). 무인증. `FACILITY_CHECK_*`만 submissions union 병합, 나머지는 통째 덮어쓰기. 업무·결재 화면이 쓰는 키: `GM_TASK_OWNERS`(GM업무 담당 배정) · `GM_TASK_CHECKS` · `CHAIRMAN_REPORTED`(회장님 보고 표시) · `BROJ_TASK_BOARD`(브로제이 업무분장). 그 밖에 `SUPPORT_*`·`PARK_*`·`OPS_*`·`FACILITY_*`·`LIVE_TEAMMAP`·`TEAM_BLOCK`·`ROUNDS` 등 점검/매뉴얼 보드 키가 같은 창고를 쓴다.

### 7. 이전 시 주의
1. **무인증 쓰기:** todo_add/update/delete/done/upload/remove_file/rep_cancel/orphan_cleanup/ai_* 전부 서버 검증 없음(시토 배947). 결재 현황 페이지가 todo_update에 pin을 실어도 서버는 버린다. DB 이전 시 인증을 서버에 세우면 이 페이지들의 호출부(업무 현황 SSOT 약 10곳·결재 현황 SSOT·_owner_directive.js·python 3종)를 전부 토큰 실어 보내게 바꿔야 한다.
2. **GM 행 숨김**이 "인증"의 전부다: 담당자 문자열에 `김남욱GM` 포함 여부. 결재 SSOT는 2026-09-03부터 GM 행을 받으려고 gmkey를 **공개 GitHub Pages HTML에 평문**으로 박았다(`gmkey=1531`). 이전 후엔 행 단위 가시성이 아니라 로그인 역할로 갈라야 한다.
3. 결재 PIN이 그대로 새는 자리: 부서장 PIN은 속성 미설정이면 통과, todo_reset은 pin 안 보내면 통과. 응답에 `pinKey`(키 이름)를 돌려준다.
4. **완료 탭은 복사본** — 원장 행이 그대로 남고 완료 탭에 한 줄 더 생긴다. 같은 id가 두 탭에 있으며, todo_delete는 완료 탭을 건드리지 않는다. 마이그레이션 시 완료 탭은 이력(archived_at=보관시각)으로만 취급하고 진실은 원장 행.
5. 내용 칸 = 마커 섹션 한 덩어리(45,000자 프론트 한도·`===반려이력===`은 서버가 append). DB로 옮길 때 기획안 HTML을 쪼갤지는 결정 필요 — 현 프론트 parseContent는 한 문자열을 기대한다.
6. 첨부 5MB 프론트 한도, Base64 본문으로 GAS에 전송. Drive URL이 원장·대표싸인 칸에 문자열로 박혀 있어 Drive를 끄면 링크가 죽는다(S3 이전 시 URL 재작성 필요). 대표 결재완료 판정 = 대표싸인이 `http`로 시작하는가.
7. 빈 문자열=보존 규칙 때문에 "칸 비우기"가 API로 불가능하다(결재 칸은 reset/reject 전용 경로).
8. 캐시 5분·쓰기 시 즉시 삭제 — DB 이전 후엔 불필요. 시트 재정렬(생성일 DESC)도 DB ORDER BY로 대체.

### 2. 키·회차 모델

- 부서 `dept` ∈ support·facility·ops·parking. 미등록/빈값 → support 폴백(읽기·쓰기 공통).
- 성별 `gender`/`genderTab` ∈ m·f·all. 원장 키는 m/f만 실사용(all 원장은 생성된 적 없음). 항목 성별 all → [m,f] 양쪽 계상.
- 회차: 키 `am1|pm1|close1|night1`(프론트 roundChecks `'<round>_<itemId>'`) ↔ 라벨 오전조·오후조·마감조·야간조(탕청소) ↔ 버킷 `am|pm|close|night`(_shiftBucket, 문자열 접두 판정) ↔ 제출도장 shiftKey `am|pm|close|night`. 변환 함수 4개가 각각 따로 있다(_roundKeyLabel·_labelToShiftKey·_roundLabelToKey·_roundBucket).
- facility 회차 = 자유 라벨('1일' 기본·과거 '07시'·'측정'). 남/여·A/B는 측정값 JSON 필드 접미 `_a/_b`.
- ops = 1일 1회, parking = 1일 2조(평일·주말 동일). support = 평일 am+pm+close, 주말 am+close(pm 없음), night는 외주 탕청소로 합계 제외.
- 항목→탭 라우팅 `_routeItem`: id 끝 `_f`/`_m` → 성별탭 · 카테고리 A/B·사우나·락커·데일리 → 활성 성별탭 · 그 외 → 공용(support는 공용 폐기 → 활성 성별탭).
- 점검일정 `sched` = `"tue,fri|2,4"`(요일|몇째주, `b`=격주). 몇째주 = ceil(일/7). 요일 토큰 sun..sat.
- 날짜: 클라가 `'yyyy-MM-dd'` 문자열 전송. 서버 오늘 = `Utilities.formatDate(new Date(),'Asia/Seoul')`. 시트 셀은 Date 객체·문자열 혼재 → `formatDate()`로 KST 문자열 정규화 후 비교. 자정 경계 = KST 00:00. 원장 TTL 계산은 `date+'T00:00:00+09:00'`.

### 7. 이전 시 주의

1. **속성 한도**: 값 9KB·스크립트 500KB. 07-16 유실 후 시트=SoT, 속성=캐시로 강등(`_resolveLedger` = 속성 우선·시트에서 없는 키만 추가). 이전 시 원장은 구역시트에서 재구성 가능하지만 **sub/subAt(제출도장)·timers·imemo·gsub·board·CHKNOTI 는 시트에 없다** → 마이그레이션 직전 `dump_cr`·`dump_board_facility` 로 속성 덤프 필수. 제출도장은 점검일지 스냅샷(제출시각·점검자)으로도 대부분 복원 가능.
2. 원장 TTL 30일(`chk_` 과거분 하루 1회 삭제) · BOARD_FACILITY_CHECK 5일 보존 → 그 이전 회차 데이터는 시트에만 있다.
3. 휴관일 = 2·4주 일요일(`_isClosedDay_`) — ops/parking 월간 분모에만 적용. weekly·support 는 미보정. 주말 support pm 없음.
4. 일정 게이트: parking 2026-09-18 · ops 2026-10-01 은 kpi_collector 상수. GAS·시트엔 없음 → DB 이전 시 `dept_schedule` 로 올려 단일 출처화.
5. 보안: 익명 접근·인증 없음·파괴적 GET 다수(clear_check_ledger, reset_facility_common, purge_*). REST 이전 시 GET 은 읽기 전용으로 고정, 쓰기는 토큰.
6. 식별자: 이슈대장 id = 행번호(정렬·삭제 시 어긋남) · 구역시트는 저장마다 전체 재정렬 → 행 기반 참조 금지, 자연키(dept,date,gender,round,item)로 전환.
7. 데이터 형: 시트 셀 Date/문자열 혼재, 측정값은 JSON 문자열, 소요시간 '12분' 문자열, 제출시각 'yyyy-MM-dd HH:mm[:ss]' 문자열. 한글 코드값(성별·타입·부서·회차·점검일정)은 적재 시 영어 enum으로 정규화.
8. 기본값 하드코딩: facility 점검자 '박호균', support 기본 점검자 '남 오전 주임' 등(defaultInspector), DEFAULT_STAFF·ZONE_ITEMS·COMMON_ITEMS 레거시 시드 — 이전 대상 아님.
9. 산식 이관: today_live·monthly 분모는 `_buildTodayMaster`(마스터×sched×회차 presence×성별) 하나로 통일돼 있다 — DB에서도 뷰/함수 1개로 유지해야 두 값이 안 어긋난다.
10. 텔레그램 dedup 키 `date|itemId|issueText` 는 실시간 드립 OFF 라 현재 미사용.
