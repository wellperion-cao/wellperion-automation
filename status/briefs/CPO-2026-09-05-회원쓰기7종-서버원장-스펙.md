정본 코드 = `.deploy-funnel-v2/Survey.js` (줄번호는 2026-09-05 기준). 코드에 없는 것은 「없음」으로 적었다.

공통 사실
- 회원 원장 스프레드시트 = `MEMBER_SPREADSHEET_ID`(L15). 탭 = 유효회원(`MEMBER_SHEET` L16) · LOSS보관(`MEMBER_ARCHIVE_SHEET` L22). 등록현황 탭 `'26년 등록현황'`(`_REG_SHEET` L2620)은 같은 스프레드시트(`_MI_SS_ID` L2139 = 같은 ID).
- 휴회 접수 탭 = 종합접수처 시트 `17ly-…`의 `휴회접수` 탭(L10544~10545). 회원 원장과 다른 스프레드시트.
- 전화 정규화 = 숫자만(`_normPhone_` L127). 헤더 매칭은 공백 제거 후 부분일치가 기본(액션마다 다름 · 각 절에 명시).
- 변경이력 = `회원변경이력` 탭 8칸 [시각·직원·회원명·연락처(뒤4자리 가림)·항목·이전값·새값·화면] (`_memberLog_` L1272). 기록 실패는 삼키고 저장은 성공 처리(L1283).
- 직원 = `_logWho_`(L1268): body에 `staff` 키가 없으면 '자동', 있는데 비면 '이름미상'.
- 캐시 2종: `_memberCacheBump_`(L2730 · 스크립트 속성 MEMBER_CACHE_GEN +1 · MEMBER_SORT_DIRTY=1) / `_aaCacheClear_(scope[])`(L1429 · 명단 캐시 valid/ended/corp/archive).
- 서버 미러 표 `members` 열쇠 = (tenant_id, member_no, scope) (`sync_members.py` L41~74). 회원번호 없는 행은 미러에 안 들어간다(L50).
- 현재 서버 관문 `api_write.py` L45~46 `_MEMBER_WRITES` 7종 = GAS 포워드 → 성공 시 `sync_members.py` 재실행(L232~233).

## 3. 서버 이식 순서 제안 (단순 → 복잡 · 7단계)

전제: 관문 `api_write.py`에서 액션별로 "서버 원장 먼저 쓰기 → 성공 시 GAS 비동기 write-through(기존 포워드 그대로)" 로 뒤집는다. `reconcile_dual_write.py`(L35~40 FORMS)에 `members` 미러 대조 항목을 추가해 "회원 쓰기 write_log 행 ↔ 다음 sync_members 배치 값 일치"를 날짜별로 세고, 액션당 **행 있는 날 3일 연속 mismatch 0** 이면 다음 단계로 간다(전환 판단은 사람).

| 단계 | 액션 | 왜 이 순서 | 검증 방법(3일 게이트) |
|---|---|---|---|
| 1 | member_owner_save | 1칸·화이트리스트·이력 있음. 서버 컬럼 5개 추가만 하면 끝 | write_log의 (member_no, field, value) ↔ 다음 배치 `data` JSON 같은 칸 값 일치 · 3일 |
| 2 | member_hold_transition | 1칸(휴회접수상태) · 회원번호 지목으로 fail-open 제거 | 위와 같은 대조 · 3일 |
| 3 | member_active_update | 칸 자유 쓰기지만 행 1개·이력 완비. rowIndex+rowKey → member_no 변환층이 이 단계의 핵심 | 저장 칸 전부(`cols[]`) ↔ 배치 값 · `saved` 되읽기가 서버 값과 같은지 · 3일 |
| 4 | member_hold_approve | 2원장·증분. 3단계 변환층 재사용. 접수 상태 재검사 가드 추가 | 회원 5칸 + 접수 상태/처리일시 ↔ 두 미러 · 횟수·누적이 정확히 +1/+N · 3일 |
| 5 | member_registered_add | 신규 행·채번. 서버 시퀀스로 회원번호 부여 후 GAS `member_registry_build`와 번호 충돌 0 확인 필요 | 새 회원번호가 다음 배치에 같은 번호로 나타남 · `classify_overlaps` 충돌 0 · 3일 |
| 6 | member_archive_restore | scope 전환 + 칸 인계. 5단계 upsert 재사용 | scope='valid' 1행만 남고 'archive' 0행 · 회원번호 동일 · 이력 JSON 존재 · 3일 |
| 7 | member_registered_remove | 하드 삭제 2탭. soft-delete + 이력 보존으로 바꿔 마지막에 | 삭제 회원번호가 다음 배치에서 사라짐(diff삭제) · 이력 행 존재 · 등록회차==1 조건 유지 · 3일 |

미러 표에 없어서 먼저 정해야 할 것: ① 등록현황 탭(`'26년 등록현황'`)은 서버 표를 만들지 시트 전용으로 둘지(2-3 참조 · 시포 판단은 시트 전용). ② `members` 컬럼 추가 목록 = 종목 담당자 5칸 · 휴회 6칸(휴회기간·시작·종료·횟수·누적·접수상태) · 주소 · 비고 · 나이 · 재등록상담 3칸 · 재등록예약목록 · 종료사유 2칸(현재 전부 `data` JSON 안).
