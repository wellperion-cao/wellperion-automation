# 인사 데이터 AWS 이관 — 서버 준비 회신 (시토 → CHRO · 2026-09-05)

CHRO 사전 요청 4건 + 사양 판단 1건에 대한 회신. 실측 기준(2026-09-05 17:0x · 15.164.151.105).

## 0. 사실 정정

| CHRO 파악 | 실제 |
|---|---|
| nginx + php-fpm 8.2 + MariaDB 10.11 위에 ERP 관문이 돈다 | ERP 관문·API 는 **Python FastAPI + PostgreSQL 17** (server/erp_auth · server/erp_api). php-fpm·MariaDB(`wp` DB)도 같은 서버에 있으나 그것은 워드프레스 사본(wp.conf)용이고 ERP 와 무관 |
| t3.small 위에 워드프레스 + ERP 관문 + 브로제이 CRM | 실측: 메모리 1.9GB 중 사용 427MB · 가용 1.26GB · 부하 0.4 · 디스크 20GB 중 3.6GB · PostgreSQL ERP DB 23MB. 브로제이 CRM 은 이 서버에 없다(외부 SaaS · API 로만 읽는다) |

## 1. 회신 5줄

| # | 요청 | 회신 |
|---|---|---|
| 1 | 접속 권한 | **CTO 배치 대행.** SSH 키는 시토 전용으로 유지(개인정보 서버 · 접근 주체 최소화). CHRO 는 저장소 `server/erp_api/api_hr.py`(API)·`server/common/schema.sql`(표 정의 · `hr.` 스키마)·`server/erp_api/migrate_hr.py`(시트→DB 적재 스크립트 · `--dry-run` 기본) 를 커밋하면 시토가 `server/deploy_api.sh` 로 올린다. 나우열M 이 직접 만들면 같은 자리에 두면 된다 |
| 2 | DB | **생성 완료 — PostgreSQL 17 · 같은 인스턴스 · 스키마 `hr`** (별도 인스턴스 아님 · 규모가 작고 백업(새벽 3시 pg_dump → S3 30일)이 이미 돈다). 접속은 서버 안에서만(`common/db.py` 가 `/srv/erp/db.env` 를 읽는다 · 외부 포트 안 연다). 표는 `CREATE TABLE IF NOT EXISTS hr.<표>` 로 schema.sql 에 추가하면 배포 때 멱등 적용 |
| 3 | 경로·인증 | 화면 = 지금 그대로 `https://erp.wellperion.com/chro/hub/…` (저장소 `3. 웰페리온 가이드/chro/` · 앱 셸 카드 그룹 '시로' 6장 이미 등록). API = `https://erp.wellperion.com/api/hr/*` (FastAPI 라우터 prefix). 인증 = 기존 관문 그대로 — nginx `auth_request` → 로그인 필수 · 화면별 권한은 `erp/modules.json` 의 roles/group('시로') · 개인정보 화면은 배1026 권한 정리에서 '인사·재무 = 나우열M 개인' 예외로 잠긴다(2026-09-05 설계). 새 인증 체계 만들지 않는다 |
| 4 | API 스택 | **Python FastAPI + PostgreSQL 확정.** PHP 안 쓴다(ERP 표준 · api_*.py 자동 등록 · 접수·문의·업무·강습·채팅이 전부 이 방식). 응답 형식은 GAS 봉투 `{ok, data}` 그대로 두면 화면 코드가 주소만 바꾸면 된다(배990 선례) |
| 5 | 서버 사양 | **현행 유지(t3.small).** 지원자 180건·휴무 5,600셀·표 14개는 수 MB 수준 — 가용 메모리 1.26GB 에 영향 없음. 상향 기준을 미리 박아 둔다: 가용 메모리 400MB 아래 또는 5분 부하 1.5 이상이 하루 2회 넘으면 t3.medium(자동화 헬스 다이제스트가 잰다) |

## 2. 이관 순서(ERP 공통 · GAS 폐기 로드맵과 같은 6단계)

①읽기 미러(시트 → hr 스키마 5분 동기) → ②쓰기 서버화(휴무·지원자 저장을 /api/hr 로) → ③화면이 서버만 부르게 → ④3일 대조 → ⑤GAS 배포 끄기(코드는 git 보존) → ⑥시트 읽기 전용 거울.
"방금 저장한 값이 5분간 안 보이는" 문제는 ②에서 사라진다(서버가 원장이면 즉시).

## 3. 개인정보·백업(별도 협의 대상 — 시토 안)

- 접근 주체: 서버 SSH = 시토 · DB 외부 접속 없음 · 화면 = 로그인 + 나우열M 개인 예외(배1026).
- 백업: 기존 새벽 3시 pg_dump → S3(30일) 에 hr 스키마가 자동 포함. 별도 보관처 불필요.
- 테스트 데이터: 쓰기 관문의 테스트 마커 격리(`is_test_payload`)가 hr 에도 적용되게 api_hr 에서 같은 함수 재사용.
