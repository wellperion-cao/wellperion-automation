### 시로 결정 (Fable 자율 · 금지 5종 비저촉 확인)
1. **새 페이지·새 GAS·새 시트 신설 금지.** `june_data.js`와 완전히 같은 패턴으로 정적 `.js` 파일 하나만 추가한다.
2. **두 파일의 내부 변수명(`DEFAULT_DEPTS`/`DEPTS`)과 로직은 그대로 둔다.** 공유 파일은 얇은 데이터 원본만 담고, 각 HTML이 자기 이름의 변수에 대입하는 어댑터 한 줄만 추가한다 — 렌더링·localStorage 오버라이드(schedule.html의 `loadRoster()`) 등 기존 동작은 전혀 안 건드림.

# 작업: 근무표·연차현황 두 화면이 공유하는 "직원 명단 단일 파일" 만들기

## 목표
지금은 `chro/hub/schedule.html`의 DEFAULT_DEPTS 배열과 `chro/hub/leave.html`의 DEPTS 배열이
**완전히 똑같은 내용을 각각 하드코딩**하고 있다. 신규 입사·퇴사·부서 이동이 생길 때마다
두 파일을 따로따로 고쳐야 하고, 하나만 고치면 다른 화면은 조용히 옛날 명단으로 남는다
(2026-07-27 실측: 이지영 사원 퇴사가 딱 이 문제로 화면에 남아 있었다).
**앞으로는 파일 하나만 고치면 두 화면 모두에 반영되게 만든다.**

## 수정 대상 (파일 3개 — 새 파일 1개 + 기존 2개 소폭 수정)

### 1. 새 파일: `3. 웰페리온 가이드/chro/hub/roster_data.js`
같은 폴더의 `june_data.js`(6월 근태 데이터를 별도 .js로 분리해 `<script src>`로 불러오는 기존 파일)와
**똑같은 패턴**으로 만든다. 내용은 schedule.html의 DEFAULT_DEPTS 배열과 RETIRED 맵을
그대로 옮겨온다(현재 두 파일의 배열은 100% 동일하니 어느 쪽에서 복사해도 같다):

    var WP_ROSTER = [
      ["운영", ["김남욱","이경연","임정은","나우열","최준용","윤병현","이지영","백승화"]],
      ["뮤지컬", ["편한별"]],
      ["시설", ["이정헌","김종현","박호균"]],
      ["지원(남)", ["황용석","박남일","김유정","천진석"]],
      ["지원(여)", ["우춘화","김미영","이경미","이연희"]],
      ["지원·주차", ["양상규"]],
      ["지원·탕청소", ["한두희(외주)"]],
      ["수영", [...실제 schedule.html DEFAULT_DEPTS 그대로...]],
      ["PT", [...]], ["PL", [...]], ["골프", [...]], ["체조", [...]], ["스쿼시", [...]]
    ];
    // 퇴사자 — 명단에서 지우지 않고 남긴다(이력 보존). 표시만 "(퇴사)" 태그.
    var WP_RETIRED = {"이지영":"2026-06-27"};

(배열 항목은 지금 두 파일에 있는 값을 한 글자도 바꾸지 말고 그대로 옮길 것 — 새로 타이핑하지 말고 복사.)

### 2. `chro/hub/schedule.html` 수정 (2곳만)
- `<script>` 태그 **앞**에 `<script src="roster_data.js"></script>` 한 줄 추가.
- 기존 `const DEFAULT_DEPTS=[...]` 배열 리터럴 전체를 지우고 `const DEFAULT_DEPTS=WP_ROSTER;`로 교체.
- 기존 `const RETIRED={...}` 줄을 지우고 `const RETIRED=WP_RETIRED;`로 교체.
- **그 아래 `retTag()` 함수·`loadRoster()`·`rebuildRoster()` 등 나머지 로직은 한 글자도 건드리지 않는다.**

### 3. `chro/hub/leave.html` 수정 (2곳만)
- 기존 `<script src="june_data.js"></script>` 바로 위나 아래에 `<script src="roster_data.js"></script>` 한 줄 추가.
- 기존 `const DEPTS=[...]` 배열 리터럴 전체를 지우고 `const DEPTS=WP_ROSTER;`로 교체.
- 기존 `const RETIRED={...}` 줄을 지우고 `const RETIRED=WP_RETIRED;`로 교체.
- **그 아래 `EMP_DEPT`·`ALL_EMP`·`retTag()` 등 나머지 로직은 한 글자도 건드리지 않는다.**

## 경계 (중요)
- ERP 백엔드(GAS)·시트는 전혀 안 건드린다 — 순수 프런트 정적 파일 정리다.
- schedule.html의 localStorage 로스터 오버라이드(`loadRoster()`가 개인 브라우저에 저장된
  커스텀 명단을 우선 쓰는 기능)는 그대로 둔다 — WP_ROSTER는 "기본값"만 제공한다.
- 두 화면의 화면 동작(탭·렌더·연차 계산·결재 등)은 절대 바꾸지 않는다 — 순수하게
  "배열을 어디서 가져오나"만 하나로 합친다.

1. 두 화면(근무표·연차현황)을 각각 열어 이전과 동일하게 보인다(회귀 없음) — 특히 이지영 사원
   "(퇴사)" 표시, 백승화 사원 정상 표시가 두 화면 다 유지되는지 확인.
2. `roster_data.js`에서 아무 직원이나 하나 이름을 바꿔보고 두 화면 다 바뀌는지 확인한 뒤 원복.
3. 커밋은 저장소 표준 `python scripts/safe_commit.py -m "<메시지>" -- <파일 3개>` 사용,
