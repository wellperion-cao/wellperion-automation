## 1. 방향과 범위

**GM 지시(2026-09-17)** — 「ERP 관리자에 만들어서 내용 정립해두면 문자 버튼으로 자동발송할 수 있게 만들거야. 현재 작업하고 있는 게 휴회 발송 + 종합접수처 접수 및 진행결과 발송 + 회원등록시 담당자 안내 발송 + 회원 문의 시 Survey폼 안내 발송 등으로 셋업을 해줘. 벤치마킹할 내용은 카톡채널 메시지 보내는 것을 학습해서 반영해줬으면 좋겠어.」

| 단계 | 범위 | 시점 |
|---|---|---|
| 1단계 | 서버 발신 모듈 + 문구 저장소 + 관리자 카드 + 휴회 1회 버튼 | 이번 주 |
| 2단계 | 종합접수처 접수 즉시 자동 + 진행결과 버튼 | 1단계 무사고 3일 뒤 |
| 3단계 | 회원등록 담당자 안내 · 문의 Survey 안내 · 알림톡(ATALK) 검토 | 서버 원천 전환 뒤 |

원칙 — 자동 발송 장치는 서버 한 곳(`server/erp_api/dlive_sms.py`)만 만든다. 화면마다 발신기를 만들지 않는다(약속 L21).

## 2. 카톡채널 벤치마크

| 항목 | 카톡채널이 하는 것 | 우리 SMS 판 반영 | 출처 |
|---|---|---|---|
| 메시지 유형 | 기본 텍스트·와이드 이미지·캐러셀·와이드 리스트 | SMS 는 글자만. 이미지·슬라이드는 링크 한 줄로 대체 | [채널 메시지 보내기](https://kakaobusiness.gitbook.io/main/partner/smb/channel/message/basic) |
| 변수 치환 | `#{이름}` 형식 · 개수 제한 없음 · 예시 텍스트 필수 | `{이름}{기간시작}{기간종료}{담당자}{링크}` · 예시값을 템플릿에 함께 저장 | [알림톡 템플릿 생성](https://docs.salesmap.kr/kakao/infotalk/generating-infotalk-template) |
| 버튼·링크 | 버튼 최대 5개(웹링크·앱링크 등) | 버튼 없음. 링크 1개만 본문 끝에 | [알림톡 심사 가이드](https://kakaobusiness.gitbook.io/main/ad/infotalk/audit) |
| 발송 대상 | 전체 친구·그룹·성별/연령 타겟 | 대상 고르기 없음. 트리거 1건 = 수신자 1명 | [메시지 발송 설정](https://kakaobusiness.gitbook.io/main/ad/moment/messagead/channelmessage/new/send) |
| 예약 발송 | 발송대기 상태에서 취소 가능 | 딜라이브 `sendTime` 으로 가능. 1단계는 즉시 발송만 | 위와 같음 |
| 발송 결과 | 대상자 수와 실제 성공 건수가 다를 수 있음 | 「보냈다」가 아니라 「도착했다」로 판정 — `/report` 를 당겨 로그에 붙임 | 위와 같음 |
| 광고 표기 | (광고) 머리말 + 상호·연락처 + 무료수신거부 080 | 4종은 본인이 요청한 건의 응답 = 정보성 → 표기 불필요 | [광고문자 표기의무](https://developers.popbill.com/guide/sms/introduction/ads-duty) |
| 야간 제한 | 21:00~08:00 발송은 사전 동의 필요 | 자동 발송은 21~08시 보류 후 08:00 발송 | [광고성 정보 전송 가이드](https://developers.fingerpush.com/biz-message/console/ads-guide) |
| 템플릿 심사 | 정보성만 허용 · 광고 섞이면 반려 · 사전 심사 | 2단계 알림톡 갈 때 필요. 스키마를 `templateCode` 에 맞춰 둔다 | [알림톡 심사 가이드](https://kakaobusiness.gitbook.io/main/ad/infotalk/audit) |

**가져오지 않는 것** — 이미지·캐러셀·버튼·대상 타겟팅·친구 그룹. SMS 한글 45자에 안 들어간다.
**중요** — 딜라이브 API 는 `/kkomsg` 로 알림톡(ATALK)·친구톡(FTALK)을 같이 지원한다. 버튼 5개·변수·SMS 대체발송(fallback)이 그 규격에 이미 있다. 즉 카톡채널 방식은 3단계에서 업체 교체 없이 그대로 얹힌다.

## 3. 문구(템플릿) 스키마

| 칸 | 뜻 | 예 |
|---|---|---|
| `id` | 문구 고유 id | `hold_confirm` |
| `name` | 사람이 보는 이름 | 휴회 확정 안내 |
| `trigger` | 트리거 자리 | `hold` / `reception` / `member_add` / `inquiry` |
| `body` | 본문(변수 포함) | `[웰페리온] 휴회가 확정되었습니다. 기간 {기간시작}~{기간종료}. 문의 02-6261-1200` |
| `sample` | 변수 예시값 | `{"기간시작":"9/20","기간종료":"10/19"}` |
| `len` | 치환 뒤 글자수(45자 검사) | 48 → LMS 전환 표시 |
| `sndr` | 발신번호 | 등록된 대표번호(값은 서버에만) |
| `state` | 발효 상태 | 초안 / GM확정 / 발효 |
| `updated_by`,`updated_at` | 마지막 수정자·시각 | 관리자 계정 · KST |

**정본 저장 위치 제안 — 서버 파일 `/srv/erp/sms_templates.json` 한 곳.** 서버가 읽고 관리자 화면이 API 로 고친다. 저장소(`status/`) 에 두지 않는 이유는 서버가 매분 git pull 로 덮어 화면이 고친 값이 사라지기 때문이다. 쓰기는 `api_partner_secrets.py:44` 패턴 그대로(임시파일 → `os.replace` · 권한 600).

확정 문구 4종 초안 = `status/drafts/dlive_msg_templates_confirmed_20260910.md`. 발효 전 GM 확인 1회 필요(대외 발신 문구).

## 4. 트리거 4자리

| 자리 | 화면·서버 함수 | 버튼 이름 | 수신번호 원천 | 자동/버튼 | msgKey | 담당 |
|---|---|---|---|---|---|---|
| 휴회 확정 | `cpo/member/membership.html:11247` `holdApprove` → `api_members_write.py:621` `_handle_member_hold_approve` | 승인 후 「문자 보내기」 | 회원 원장 전화 칸 | 1회 버튼 | `hold-{회원번호}-{YYYYMMDD}` | 시토 |
| 종합접수처 접수 | `api_reception.py:616` `_submit` (알림 함수 `notify` 는 `:298`) | 없음(접수 즉시) | 접수 원장 `contact` | 자동 | `rcpt-{regId}-{YYYYMMDD}` | 시토 |
| 접수 진행결과 | `coo/reception/종합접수처_현황.html:1174` 상태 select · `:1167` 전달완료 | 「결과 문자」 | 접수 원장 `contact` | 1회 버튼 | `rcptdone-{regId}-{YYYYMMDD}` | 시우 |
| 회원등록 담당자 | `api_members_write.py:1080` `_handle_member_registered_add` | 「담당자 안내」 | 회원 원장 전화 칸 | 1회 버튼 | `newmem-{회원번호}-{YYYYMMDD}` | 시포 |
| 문의 Survey 안내 | `api_intake.py:117` `intake` (`POST /api/intake/inquiry`) | 없음(접수 즉시) | 문의 원장 연락처 칸 | 자동 | `inq-{문의id}-{YYYYMMDD}` | 시포 |

- 담당자 칸은 원장에 이미 있다 — 공용 `담당자`(`:120`), 종목별 `PT 담당자`·`골프 담당자`·`P.L 담당자`·`스쿼시 담당자`·`수영 담당자`(`:89`).
- 휴회 기간 칸 = `휴회시작일`·`휴회종료일`(`api_members_write.py:104`).
- ⚠ 회원 신규 행 생성은 아직 GAS 몫이다(`api_members_write.py:1087` 주석). 서버에 자동 트리거를 걸 자리가 없어 1단계는 1회 버튼으로 간다.
- 문구는 GM 확정 전까지 초안 4종을 그대로 쓴다. 자리별 배정 = 접수 즉시 ① · 진행결과 ②③ · 휴회 ④.

## 5. 관리자 화면 규격

**위치** — `/erp/admin/` 「문자 발송」 카드 1장. 권한 = 회사 관리자 계정만(`server/erp_auth/app.py:675` `path_allowed` 가 `/erp/admin/` 을 플랫폼 관리자에게만 연다). 카드 정의는 `3. 웰페리온 가이드/erp/modules.json` — 손으로 고치지 않고 `scripts/erp_modules_build.py` 로 만든다.

| 탭 | 담는 것 |
|---|---|
| 문구 | 목록(자리·이름·상태) → 편집. 45자 카운터가 치자마자 셈. 초과하면 「LMS 로 나감」 배지 |
| 미리보기 | 예시값을 넣은 실제 문장 한 줄 — 보낼 글자 그대로 |
| 시험 발송 | 관리자 본인 번호 1건만. 하루 10건 상한 |
| 발송 로그 | 최근 50건 · 시각·자리·문구 id·수신번호 뒷 4자리·상태(접수/성공/실패+오류코드) |

- 수신번호 가림은 `api_partner_secrets.py:64` `mask_id` 방식과 같게 한다.
- 잔액·단가는 딜라이브 API 에 조회 기능이 없다 → 카드에 `letter.dlive.kr` 링크 한 줄만 둔다.
- 문구를 「발효」로 올리는 버튼은 회사 관리자만 누른다. 초안 상태 문구는 발송에 쓰이지 않는다.

## 6. 서버 모듈 `server/erp_api/dlive_sms.py`

| 항목 | 규격 |
|---|---|
| 토큰 | `POST /token` → `accessToken`·`expiresIn`(기본 3600초). 메모리 캐시 · 만료 60초 전 재발급 · 401 이면 1회 재발급 후 재시도. 파일에 안 남김 |
| 보내기 | `send(template_id, rcpt, vars, origin_key)` → 문구 읽기 → 변수 치환 → 글자수 판정 → `POST /legacy` |
| msgType | 기본 `SMS`(한글 45자/영문 90자). **45자 초과 = `LMS`**(제목 필수 한글 30자 · 본문 한글 1000자). `NSMS` 는 해외 SMS(E.164 · 영문숫자 70자)라 우리와 무관 — 쓰지 않는다 |
| 중복 방지 | `msgKey` = 4절 규칙(64자 이내). 보내기 전 로그에 같은 키가 있으면 안 보낸다 |
| 발송 로그 | `/srv/erp/sms_log.jsonl`(서버만). 수신번호는 뒷 4자리만 · 본문은 문구 id + 변수 키만 |
| 결과 확인 | 5분마다 `GET /report` 를 당겨 로그 행에 `sendStatus`·`errorCode`·`deliveryTime` 을 붙인다. 개별 조회는 `POST /query` |
| 재시도 | 실패 1회(5초 뒤) · 같은 `msgKey` 로 |
| 야간 | 21:00~08:00 자동 발송은 보류 후 08:00 발송. 관리자가 누른 1회 버튼은 그대로 보내되 화면에 경고 한 줄 |
| 킬스위치 | `SMS_ENABLED` — 0 이면 보내지 않고 로그만 남긴다. **기본값 0 으로 시작** |

계정 6키는 서버 `/srv/erp/api.env` 에만 있다(값은 이 문서에 적지 않는다). 서버 → 딜라이브 `/token` 200 · `/ping` 200 실측 2026-09-17 10:08.

## 7. 실행 순서와 완료 판정

| 걸음 | 내용 |
|---|---|
| ① | `dlive_sms.py` + `/srv/erp/sms_templates.json` + 관리자 카드 + 휴회 1회 버튼 |
| ② | 시험 발송 — 2026-09-18 10:00 · GM 휴대폰 1건(딜라이브에 일정 공유 예정) |
| ③ | 같은 `msgKey` 로 한 번 더 보내 중복이 걸러지는지 본다 |
| ④ | 이상 없으면 `SMS_ENABLED=1` |

**완료 판정 3가지를 모두 채울 때만 완료라 한다.**
1. 실발송 1건이 GM 휴대폰에 도착했다
2. `/report` 로 당겨온 성공 상태가 발송 로그에 붙었다
3. 관리자 화면에서 문구를 고쳐 다시 보내면 바뀐 문장이 온다
