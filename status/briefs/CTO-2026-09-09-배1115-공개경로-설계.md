## 5. 보안 체크리스트 (요청 항목 대조)

| 항목 | 상태 | 근거 |
|---|---|---|
| 로그인 없이 열림 | 충족 | `location ^~ /public/`이 `location /`의 auth_request보다 먼저 매칭(상위 location 아님, 상속 없음) |
| 디렉터리 목록 금지 | 충족 | `autoindex off`(명시) + `try_files`가 `$uri/`를 안 써서 폴더 자체는 애초에 안 열림 |
| 하위 경로만 서빙 | 충족 | `location ^~ /public/`은 그 접두 아래만, root는 서버 전역 설정(`/srv/erp/www`) 그대로 |
| 실행 가능한 것 없음 | 충족 | nginx는 이 location에 어떤 실행기(CGI·proxy_pass)도 안 붙였다 — 무슨 파일이든 정적 바이트로만 내려간다 |
| 검색엔진 수집 차단 | 충족(신규) | `X-Robots-Tag: noindex, nofollow` 추가 |
| 경로 탐색(`..`) 차단 | 충족 | nginx가 location 매칭 전에 URI의 `../`를 정규화한다(엔진 표준 동작) — 별도 처리 불필요 |
| 심볼릭 링크로 상위 노출 | 해당 없음 | `public/` 아래 실측 파일 전부 실파일(심볼릭 링크 0개, 2026-09-09 확인) — 생기면 그때 `disable_symlinks` 추가 |
| 파일 없으면 404 | 충족 | `try_files ... =404`(로그인 페이지로 안 넘어간다) |

## 6. 되돌리는 법

`erp-locations/public-assets.conf`에서 이 location 블록을 지우고 재배포(scp+reload)하면 즉시 원상 —
서버 파일 자체를 지우면 로그인 관문 예외가 사라져 `/public/*`도 다시 로그인 요구로 돌아간다.
