## 6. owner_* 5칸 정합 수리(시포 실측 · 배1054 확장 · 2026-09-07)

**원인 한 문장(시포 실측 확인):** `schema.sql` 이 owner_* 5칸을 `WHERE owner_* IS NULL` 1회성으로만 채우고 `sync_members.py` 의 5분 갱신 열 목록엔 이 5칸이 없어(의도된 설계 — 서버가 쓴 값을 안 덮으려던 것), data(JSON, 5분마다 갱신)와 owner_* 컬럼(최초 배포 스냅샷에 고정)이 시간이 갈수록 벌어졌다 — valid 991행 중 owner_pt 846행 불일치.

**바꾼 것:**
| 파일 | 내용 |
|---|---|
| `server/erp_api/sync_members.py` | `OWNER_COLS`(5칸 매핑) + `sync_owner_cols(conn)` 신설 — 매 sync 끝에 owner_* 를 data JSON 으로 재정렬하되, `write_log` 의 `member_owner_save` 성공행(`payload._member_no`·`field`)에 해당하는 (회원번호,필드)는 예외로 안 덮는다. `main()` 에 훅 연결 + 예외 뺀 불일치 행수가 0 아니면 `_tell_gm()` 재사용해 업무보고방 경보(`sync_todo.staff_parity` 와 같은 모양 · fp 중복억제 없음). `selftest()` 에 예외 스킵·정상 갱신 양쪽 다 확인하는 assert 4개 추가 |
| `server/common/schema.sql` | 로직 변경 없음, 주석만 정정 — "이후 재실행은 아무 일도 안 한다"가 더는 사실이 아니라서(`sync_owner_cols` 가 매번 재정렬함) 오해 방지 |

**실행 순서:** ①카드 승인 ②`bash server/deploy_api.sh`(scp + `systemctl restart erp-api` 이미 포함 — 새 재기동 단계 불필요) ③첫 5분 cron sync 에서 owner_* 자동 재정렬 ④`/srv/erp/sync_members.log` 의 `[parity] owner_* 불일치 N행` 줄로 확인(N=0 이 정상, M00882 1건은 write_log 예외라 애초에 이 N 에 안 잡힌다).

**되돌리기:** DB 컬럼 삭제 등 파괴적 변경 없음 — `main()` 의 `sync_owner_cols(conn)` 호출 한 줄만 빼면 이전 동작(1회성 백필만)으로 즉시 복귀. 코드 재배포만으로 충분.

**검증:**
1. 로컬 selftest 통과 확인 — 저장소 코드를 서버 `/tmp`(운영 경로 `/srv/erp` 밖)에 임시로 올려 `python3 sync_members.py --selftest` 를 tenant `selftest` 로 실행, 통과 후 임시 파일 삭제(운영 미배포·실데이터 무영향). 예외행(M00003 흉내)은 서버값 유지, 비예외행(M00004 흉내)은 시트값 추종을 각각 확인.
