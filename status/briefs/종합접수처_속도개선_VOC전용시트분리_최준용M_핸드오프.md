# 종합접수처 현황 속도 개선 — VOC 전용 시트 분리 (실무 핸드오프)

> **담당:** 최준용M (실무 책임자) · **작성:** 시우(AI COO) 2026-07-07 · GM 위임
> 이 문서는 그대로 따라 하거나, 최준용M의 AI에게 프롬프트로 넣어 실행해도 되도록 자기완결로 작성했습니다.

## 1. 문제 (왜 느린가)
종합접수처 현황(`coo/reception/종합접수처_현황.html`)이 점점 느려짐.
- **진짜 원인:** VOC 접수 데이터(6종)가 **리셉션 공용 스프레드시트(60여 개 탭)** 안에 들어 있음.
- 접수처는 접수 관련 6개 탭만 필요하지만, 그게 큰 공용 시트 안에 있어 **페이지가 매번 그 큰 시트 전체를 열어(openById)** 읽음.
- 리셉션 시트가 커질수록(락커·시재금·GX 등 다른 팀이 계속 추가) 여는 시간이 늘어 → **점점 느려짐.**
- (페이지 자체·접수 건수 ~8건은 원인 아님. 자동 새로고침도 없음.)

## 2. 목표
VOC 접수 데이터를 **작은 전용 스프레드시트**로 분리 → 접수처가 작은 파일만 열게 →
근본적으로 빨라지고, 리셉션 시트가 아무리 커져도 **영향 안 받음.**

## 3. 이동 대상 (7개 탭)
현재 위치 = 리셉션 공용 시트 (ID: `1akZLs7ITs3FZWFIzMQvSYrdRucGQglmerOvTC2TLEcQ`)
옮길 탭 7개 (헤더·데이터·탭 이름 **그대로**):
`접수 VOC`, `접수_분실물`, `접수_시설고장`, `접수_청결`, `접수_칭찬`, `접수_쓴소리`, `접수_컴플레인`
> ⚠️ 리셉션 시트의 나머지 60여 탭(락커·시재금·GX 등)은 **손대지 말 것.**

## 4. 실행 절차
1. **백업** — 위 7개 탭 현재 데이터를 사본으로 1부 보관(안전용).
2. **전용 시트 생성** — 새 구글 스프레드시트 생성(예: `웰페리온 VOC 접수 DB`). 소유·공유 = cao 계정.
3. **7개 탭 복사** — 리셉션 시트에서 각 탭 우클릭 → "다른 스프레드시트로 복사" → 새 전용 시트 선택. 복사 후 새 시트에서 **탭 이름을 원본과 똑같이** 정리(구글이 "○○의 복사본"으로 붙이므로 이름 수정 필수. 예: `접수_분실물`). 헤더·데이터·행 순서 그대로.
4. **주소(ID) 교체** — VOC Apps Script 프로젝트 → **프로젝트 설정 → 스크립트 속성 → `SPREADSHEET_ID`** 값을 **새 전용 시트의 ID**로 교체.
   - 새 시트 ID = 새 시트 URL의 `/d/` 와 `/edit` 사이 문자열.
5. **재배포** — GAS 웹앱을 **기존 배포 업데이트**로 재배포(배포 URL·ID 유지). 새 배포로 URL이 바뀌면 안 됨(페이지가 옛 URL을 호출).
6. **검증** — 종합접수처 현황 페이지 새로고침 → ①6종 카테고리·기존 접수건 정상 표시 ②체감 속도 개선 확인. 테스트로 접수 1건 넣어보고 새 시트에 저장되는지 확인 후 그 테스트건 삭제.

## 5. 주의사항
- **탭 이름 정확히 유지** — 코드가 이름(`접수_분실물` 등)으로 시트를 찾음. 이름 다르면 그 카테고리가 안 뜸.
- **옛 7개 탭은 검증 100% 완료 전까지 삭제 금지** — 문제 생기면 되돌릴 폴백.
- **회원 개인정보(이름·연락처) 포함** — 전용 시트도 **접근 권한 cao 한정**(외부 공유 금지).
- 4·5번(스크립트 속성·재배포)이 기술적이라 막히면 시토(AI CTO) 또는 시우에게 지원 요청.
