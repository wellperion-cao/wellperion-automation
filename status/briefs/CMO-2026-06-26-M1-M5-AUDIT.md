# M1~M5 메뉴 전수 진단·보완안 (시모, 2026-06-26)

AI CMO 섹터 메뉴 5종을 병렬 정밀 분석. 모든 수치는 실측(추정 아님).

## 한눈 요약

| 메뉴 | 가장 심각한 문제 | 심각도 |
|---|---|---|
| M1 공식 채널 | @namuk.wellperion(매일 발행 중) 채널표 누락 + 창립연도·회원수 드리프트(2010/150 vs 2017/1,000) | 高 |
| M2 콘텐츠 제작 | "4채널 vs 5채널" 표기 혼재 + 6대 기둥 중 4개 미완(따라할 완결본 아님) | 中 |
| M3 오프라인 홍보물 | 사용법·예시·저장경로 전무 + 종류↔사이즈 옵션 불일치 + 슬로건 하드코딩 | 中 |
| M4 마케팅 대시보드 | 대시보드 "등록"(실측) ↔ 월간보고서 "전환"(추정)이 같은 개념 다른 수 → 신뢰 붕괴 | 高 |

## 진짜 문제 3가지 (메뉴 가로지르는 구조)

1. **현실↔기록 동기화 틈 (M1·M5 공통)** — 채널·수치가 실제로 바뀌었는데 문서/큐가 안 따라옴. 골프 EP2 누락이 증상. 근본=발행(사람 손)과 기록(봇)이 한 트랜잭션이 아님.
2. **"측정한 척" 위험 (M4)** — 전환/등록 정의가 페이지마다 다르고 추정값에 권위색(녹/황/적)이 붙어 확정처럼 읽힘. 출처미상 43%가 채널분석 신뢰도를 깎음.
3. **이중 시스템 (M5)** — CMO파이프라인.html(시트·3채널·URL칸 없음)과 review_queue.json(5채널·URL)이 서로 안 읽음 → 드리프트가 구조적으로 보장됨.

## 메뉴별 상세

### M1 공식 채널 (가이드 1889~2059행)
- [高] @namuk.wellperion 채널표 누락(본문 1971행엔 등장=자기모순) → 회사/개인 2계정 역할 명시
- [中] 창립연도·회원수 S0와 충돌(2010/150 vs 2017/1,000) → 라이브 KPI 단일출처 참조
- [中] 카카오 "보류"·당근 "인지만" badge가 현실(반자동 발행중)과 불일치 → badge 갱신
- [低] "하이엔드 격조"=금지어 충돌 → "프리미엄" / meta v1.0 한 달 미갱신
- 좋은 점: CTA 표준·DUOTONE 사양 구체적, 죽은 도구 참조 없음

### M2 콘텐츠 제작 프로세스 (3840~4101행)
- [中] 4채널/5채널 표기 혼재 → 5채널 통일
- [中] 6대 기둥 중 4개 미완 → "가능/불가" 분리 표기
- [低] 발행 스크립트가 IG 1개만 언급(블로그·카페·카카오·당근 누락) / 외부게시금지 경고가 주석에 숨음
- 좋은 점: 제작완료 종료절차·비가역 발행 게이트 명문화

### M3 오프라인 홍보물 (5749~5852행)
- [中] 사용법·예시·저장경로 전무 → 3단계 사용법+예시 추가
- [中] 종류(배너·현수막·봉투·브로슈어)↔사이즈 드롭다운 불일치 → 종류별 프리셋
- [中] 미리보기 슬로건 하드코딩(표준 슬로건과 불일치) → 표준 교체/편집필드화
- [低] 서브브랜드 로스터 M1과 불일치(brad) / 디자인표준 링크 없음
- 좋은 점: 사업부별 컬러·로고 자동전환+A3/A4 인쇄 자립구조

### M4 마케팅 대시보드 (cmo/funnel/)
- [高] 등록(실측)↔전환(추정) 정의 이중화 → 한 화면 병기·정의 단일화
- [高] 출처미상 43% → 문의폼 "어떻게 알고 오셨나요?" 필수화(처방은 화면에 있으나 미실행)
- [中] 설계 5단계 중간퍼널(응대·예약·방문) 미구현 + 죽은 배선(funnel-*/fc-* DOM) 잔존
- [中] "콘텐츠별 문의 유입"=실제론 클릭 순위(문의 귀속 아님) / 무인증 공개 GAS로 사업집계 노출
- [中] 월간보고서 항상 '이번 달' 고정(지난달 출력 불가)
- 좋은 점: 하드코딩 더미 0건, "측정 안 함" 정직표기 일관, 출처미상 배지가 행동처방까지 제시

### M5 검수큐 (cmo/review/)
- [高] 화면(시트 3채널)과 SSOT(review_queue 5채널) 별개 두 시스템 → 단일 정본 통합·재배선
- [高] 발행완료 75건 중 39건(52%) post_url 없음(비IG 27건 거의 전부) → 발행완료=URL 게이트
- [高] GM 수동 게시 → review_queue 콜백 훅 전무(watcher가 발행한 행만 갱신)
- [中] 채널 표기 8종 난립(IG만 4변형) → enum 6개 정규화
- [中] status 코드엔 5종인데 큐엔 '발행완료'만(수동발행대기가 사각지대) / published_at 형식 혼재·미정렬
- [高] 행 누락 3건: WJO·발레=IG회사 없음, 골프EP2=당근 없음
- 좋은 점: id 키 일치(혼용 0), 중복 0

## 보완 로드맵 (권장 순서)

1. **표준화(저비용·전제)** — 채널 enum 6개·status enum 5종·published_at ISO8601 통일. 코드 한 곳.
2. **M5 트랜잭션 닫기(최상위 레버)** — GM 텔레그램 [승인/게시완료] 1탭 회신으로 해당 행 발행완료 전환+URL 캡처. "발행(사람)=기록"을 한 트랜잭션으로. → post_url 공백·수동발행 사각지대·누락 동시 해소
3. **M5 5채널 선등록(A안)** — 콘텐츠 생성 시 5채널 행 '발행대기'로 깔기(IG단독은 '해당없음'). 누락 vs 미발행 구분
4. **M4 지표 정직화** — 등록/전환 정의 단일화·'추정' 라벨 통일 + 문의폼 출처필드 필수화
5. **M1 현실화** — 개인계정 등재·수치 단일출처·badge 갱신
6. **M2·M3 실무화** — 5채널 통일·기둥 가능/불가·M3 사용법/프리셋/슬로건
7. **B안(야간 대조)** — IG·당근 한정 자동 누락탐지 안전망(블로그·카페는 읽기 API 없어 자동대조 불가)
