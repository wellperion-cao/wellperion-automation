## 5. 재유입 차단 — 뿌리 수정

공통 판별 함수 `is_test_payload()` 를 `server/common/db.py` 에 신설(새 파일 대신 기존 db.py 에 함수 1개).
자체선언 태그(`[테스트]`·`[자동QA]`·`[자동검증]`·"테스트입니다" 류)나, **이름이 비어 있을 때만** 더미 전화
(010-0000-0000·전부 0)를 마커로 본다 — 이름이 있으면 더미 전화라도 실고객일 수 있어(Sina Melchin 실사례) 잡지 않는다.

- **server/erp_api/api_write.py** `/api/write` — 마커 있으면 write_log 에 `gas_status='test'` 로 저장만 하고
  GAS 전달·미러 동기화·리셉션 정본 갱신을 전부 건너뛴다.
- **server/erp_api/api_intake.py** `/api/intake/{form}` — 같은 방식으로 intake_log 에 `gas_status='test'` 격리,
  헬스 집계(`api_intake.health()`)의 실패 카운트에서도 제외.
- **server/erp_api/sync_inquiries.py**·**sync_reception.py** — 시트 미러 동기화 시점에 `is_test_payload()` 로
  걸러 미러 표엔 애초에 안 싣는다(시트 원본은 손대지 않음 — 시트 정리는 담당 C-Level 확인 뒤).
- **server/erp_api/reconcile_dual_write.py** — `gas_status='test'` 행은 이중기록 대조(3일 무결 스트릭)에서 제외
  (넣으면 격리된 테스트가 매번 "시트 도달 못 증명"으로 잡혀 서버 원본 전환 판정을 방해한다).

## 6. 실측 — 재유입 차단 확인

`/api/write` 에 `action=todo_add, title="[테스트] 더미 데이터 차단 확인"` POST →
`{"ok":true,"test":true,"id":87}` 응답, DB 확인 결과 `gas_status='test', gas_response=None`(GAS 미전달 확인 — 실제
시트에 더미 TODO 가 생기지 않았다). 확인 후 해당 행 즉시 DELETE(지시서 5번 절차 그대로).

`db.py`·`api_write.py`·`sync_inquiries.py`·`sync_reception.py` 자체점검(`--selftest`/`__main__`) 전부 통과.
