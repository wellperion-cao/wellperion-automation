## 1. 관리자 API 4개 — 라이브 확인 완료

파일 = `server/erp_api/api_chat.py`(배1018 라우터에 이어 붙임) · nginx = `server/erp_api/chat.nginx.conf`.

| 메서드·경로 | 접근 | 무엇 | 실측 |
|---|---|---|---|
| `PUT /api/chat/{t}/faq` | 로그인(관문) | FAQ 추가·수정 · 미답→FAQ 승격도 이 API 하나(`id` 없이 보내면 새 항목) · 저장 전 금액·의료 낱말 경고(막지 않음) | 내부 curl(127.0.0.1:8001)로 추가 확인 → `faq.json` 반영 확인 → 테스트 행 삭제 |
| `GET /api/chat/{t}/stats` | 로그인(관문) | 질문 수·자력 답변 비율·미답 상위 10 (chat_log.jsonl만 · 이름·전화 없음) | `days=30` 라이브 응답 확인(총 49 · 자력 18 · 36.7%) |
| `POST /api/chat/{t}/feedback` | 공개 | 👍👎 한 번(faq_id·vote만 · 개인정보 0) | `https://erp.wellperion.com/.../feedback` 200 확인 |
| `GET /api/chat/{t}/profile` | 공개 | 이름·상담원 페르소나(name·greeting·handoff·typing_ms·emoji)·연락처(phone·kakao·naver_place)·예약 링크·상태·FAQ 칩 6개(q·a·verified) · `?full=1` 이면 FAQ 전체(관리자 페이지가 씀) | `1_wellperion`·`3_spogym` 라이브 200 확인 |

`GET .../faq`(전체 목록)는 새 엔드포인트를 안 늘리려고 `profile?full=1` 에 얹었다 — FAQ 는 원래 공개 콘텐츠라 로그인 없이 봐도 안전하다.

nginx 관문: `unanswered`·`faq`·`stats` 세 경로만 `auth_request`(로그인 없으면 401 확인) · `feedback`·`profile`·기본 `POST /{t}` 는 공개. `TENANTS` 집합에 `3_spogym` 추가.

## 2. FAQ 정본 — 서버 파일로 전환(시보 확인사항 반영)

전에는 `deploy_dietcamp.sh`가 배포 때마다 저장소 FAQ를 서버에 덮어썼다 — 관리자 API로 고친 내용이 다음 배포에 지워지는 문제. 고침:
- `deploy_chat.sh`·`deploy_dietcamp.sh` 모두 서버에 `faq.json`이 **이미 있으면 건드리지 않는다**(최초 1회만 저장소 시딩).
- 프로필(`server/counselbot/tenants/{t}.json` → 서버 `profile.json`)은 관리자 API가 안 건드리는 칸이라 배포마다 그대로 덮어써도 안전 — 매번 동기화.
- **결론(정본 한 곳)**: FAQ 콘텐츠의 정본은 이제 **서버 파일**(`/srv/erp/faq/{t}/faq.json`)이다. 저장소 `seed_faq/`와 브랜드 폴더 FAQ 원본은 최초 시딩용 스냅샷으로만 남는다 — 이후 편집은 관리자 페이지에서.

## 5. 자연문 재작성 계층(L2) — GM 추가 지시 2건 반영

FAQ 문장을 그대로 보내지 않고 진짜 상담원처럼 말하게 하는 계층을 `POST /api/chat/{t}`에 얹었다(`_natural_answer`).

- **① 자연문**: 매칭된 FAQ 1건(`faq_id`) + 페르소나(`counselor_persona`) + 손님 질문 → `claude-sonnet-5`. system 프롬프트에 **테넌트 FAQ 전체**를 넣어 prompt caching이 먹게 하고(질문마다 안 바뀜), user 메시지에서 "이번엔 이 id 하나만 근거로" 지정한다. 출력은 코드로 검사 — 금액·의료 낱말이 있거나 근거 FAQ 원문에 없는 숫자가 새로 등장하면 자연문을 버리고 FAQ 원문 그대로 낸다(지어낸 숫자 0).
- **② 영어**: 질문에 한글이 하나도 없고 영문자가 있으면 같은 호출에서 영어로 답하도록 지시(1차 한·영만).
- **③ 스위치**: `ANTHROPIC_API_KEY`가 서버 `/srv/erp/api.env`에 없으면 `_anthropic_client()`가 `None`을 돌려주고 `_natural_answer`는 그 자리에서 FAQ 원문을 그대로 반환한다 — **회귀 0**. 지금 서버엔 키가 없음을 확인했다(`grep -c ANTHROPIC_API_KEY api.env` = 0). `anthropic` SDK(0.125.0)는 미리 서버에 설치해 뒀다 — 키만 GM 결재 뒤 `api.env`에 넣으면 코드 변경 없이 켜진다.
- 테스트 접수·질문에는 마커(「테스트」)를 넣고 이 배 끝나며 만든 테스트용 FAQ 행은 즉시 삭제했다(f01 임시 수정분 없음 확인).
