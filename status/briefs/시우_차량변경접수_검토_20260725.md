# 종합접수처 '차량 변경 접수' 검토 — 시우 (2026-07-25)

배96(GM 제안) 검토·설계. 배93(주차 공지·가이드)과 짝 — 이 문서는 **접수 채널 설계**만, 실제 등록 SOP 문구는 배93이 담당.

## 1. 중복 확인 결과 — **신설**

현행 종합접수처 8종(백엔드 REG_CATEGORIES 6종 + 습득물 + 휴회, `coo/reception/종합접수처_현황.html:184`)을 전수 대조.

| 기존 항목 | 담당부서 | '차량 변경'과 겹침? |
|---|---|---|
| 분실물 접수 | 운영부 | ✗ 물품 분실, 무관 |
| 시설물 고장 접수 | 시설부 | ✗ 설비 고장, 무관 |
| 청결 이슈 접수 | 지원부 | ✗ 청결, 무관 |

**판단: 신설.** 담당 부서가 위 6종 어디에도 속하지 않는 독립 부서 **주차관리부**(2026-06-13 시설부에서 분리·독립, `coo/check/주차관리부 체계.html`)이고, 성격도 '민원·이슈 접수'가 아니라 '정보 등록 요청'이라 기존 6종 어느 라벨에도 자연스럽게 안 붙는다. 확장이 아니라 신설이 맞다.

**신설 근거 자산 재사용(=최소 변경):** 종합접수처는 이미 접수(폼)→텔레그램 알림→담당 배정→상태(접수/처리중/완료)→처리메모 워크플로우와 PIN 게이트(gate.js) 보호 admin board를 갖추고 있다. 신규 시스템을 새로 만들지 않고 **7번째 네이티브 카테고리로 REG_CATEGORIES에 추가**하면 이 인프라를 그대로 재사용한다(휴회처럼 별도 백엔드로 뺄 이유 없음 — 휴회는 회원 DB라는 기존 소유 시스템이 있어서 그리 갔던 것이고, 차량 등록은 그런 소유 시스템이 우리 자동화 안에 없음. LPR은 외부 벤더 시스템).

### 2-3. 개인정보 취급 — 기존 수준과 동일(완화 없음)

| 구분 | 기존 6종 (예: 분실물 이름·연락처) | 신규 차량 변경 (차량번호) |
|---|---|---|
| 수집 방식 | 공개 폼, 백엔드 위조방지 토큰 게이트(`_vSubmitGateOk_`) | **동일** — 같은 폼·같은 백엔드 |
| 저장 | Google Sheet 평문 컬럼, PII 별도 암호화 없음 | **동일 수준** — 새 컬럼도 평문(기존과 다르게 만들지 않음) |
| 열람 | `종합접수처_현황.html` — gate.js PIN/JWT 게이트 뒤 | **동일** — 같은 페이지, 자동 상속 |
| 노출 범위 | 담당부서·GM만 | **동일** |

→ 차량번호를 더 느슨하게(예: 공개 board, 비게이트 페이지) 노출하는 설계 아님. 기존 PII 필드와 동급으로만 다룬다.

### 2-4. 접수 → 등록 반영 경로 (끊기지 않는 흐름)

```
① 회원이 종합접수처(웹폼 / 프런트 QR)에서 '차량 변경 접수' 제출
        ↓ (reg_submit, 기존 백엔드 그대로)
② 접수_차량변경 시트 저장 + 텔레그램 '종합접수처' 방 자동 알림
   (부서: 주차관리부 · 기존 _vNotifyTelegram 그대로 동작 — 카테고리별 분기 이미 파라미터화되어 있어 추가 코드 불요)
        ↓
③ 주차관리인(발렛/주차 담당 겸직)이 텔레그램 알림 또는 종합접수처_현황.html
   (부서 필터 '주차관리부')에서 확인
        ↓
④ 주차관리인이 LPR(번호인식) 관제 콘솔에 신규 차량번호 수동 등록
   ※ LPR은 외부 벤더 시스템 — 우리 자동화가 API로 못 건드림(자동 반영 불가, 항상 수동)
        ↓
⑤ 종합접수처_현황 보드에서 상태를 접수→처리중→완료로 갱신,
   처리메모에 "LPR 반영완료 (기간: ~)" 기록
        ↓
⑥ 완료 = 회원 재방문 시 차단기 자동 개방 확인으로 종결
```

**"접수만 받고 끝나지 않는" 보장 장치:** 기존 6종과 동일하게 상태(접수/처리중/완료) + SLA 타이머 + 처리메모 컬럼을 그대로 쓴다. 완료 처리를 안 하면 보드에 '미완료'로 계속 노출되고 SLA 초과 시 '초과' 배지가 뜨는 기존 메커니즘이 그대로 강제한다. → 새 시스템을 안 만들어도 이미 있는 강제 장치를 상속.

**배93과의 경계:** 배93(주차 가이드)이 "다른 차량 가져왔을 때 등록해주는 절차"의 SOP 본문(누가·언제·CCTV 확인 등)을 작성한다. 이 문서(배96)는 그 절차의 **입구(접수 채널)**만 설계한다. 배93 SOP 문구에 "종합접수처 '차량 변경 접수'로 신청 → 주차관리인이 LPR 반영"이라는 문장을 넣도록 배93 담당(같은 시우 세션)에 인계 필요 — 본 브리프 공유로 정합 확보.
