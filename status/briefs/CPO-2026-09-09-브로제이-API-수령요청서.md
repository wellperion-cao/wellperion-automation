# 브로제이 API 수령 요청서 — 그대로 보내면 되는 한 장

작성 AI 시포 · 2026-09-09 · 배908(브로제이 연동) · 받는 사람 = GM → 브로제이 담당자

## 0. 왜 이 한 장인가

우리 쪽 준비는 끝났다. 서버 코드(호출·저장·대조)가 9월 4일부터 서 있고, **환경값 네 줄만 채우면 재배포 없이 그 자리에서 돈다**(시토 실측 2026-09-09).
막힌 것은 하나 — 브로제이 쪽 주소·열쇠·응답 사양이 아직 안 왔다. 9/4 「오늘 알려준대」 → 9/7 수령 예정이었고 오늘까지 5일째 비어 있다.
그 사이 매출·입장 숫자는 계속 실무진 손입력으로 들어온다.

## 1. 우리가 채워야 할 값 네 줄 (이것만 오면 끝난다)

| 값 이름 | 무엇 | 지금 |
|---|---|---|
| BROJAY_SALES_URL | 일 매출 조회 주소 | 비어 있음 |
| BROJAY_ENTRIES_URL | 입장(출입) 조회 주소 | 비어 있음 |
| BROJAY_API_KEY | 발급 열쇠 | 비어 있음 |
| BROJAY_AUTH | 열쇠를 어떻게 실어 보내는지(머리말 이름·형식) | 비어 있음 |

## 2. 브로제이에 물어야 할 것 (그대로 복사해 보내도 되는 문장)

```
안녕하세요, 웰페리온입니다. 말씀 주신 API 연동 건으로 아래 항목을 요청드립니다.

1. 조회 주소 두 개 — ① 일 매출 ② 입장(출입) 기록
2. 인증 방식 — API 키 발급 절차와, 키를 요청에 싣는 방법(머리말 이름·형식)
3. 제공 항목
   · 일 매출: 회원권 · 강습권 · 옵션 각각의 금액과 합계
   · 계약 건별: 일시 · 담당 · 회원명 · 종목 · 금액 · 결제방법 · 신규/재등록/양도/환불 구분
   · 입장: 날짜별 입장 인원(가능하면 회원/비회원 구분)
4. 조회 범위 — 기간을 지정할 수 있는지, 한 번에 받을 수 있는 최대 건수, 페이지 넘김 방식
5. 호출 제한 — 분당·일당 몇 회까지 가능한지
6. 시험용 환경과 응답 예시 한 건
7. 개인정보 범위 — 회원명·연락처가 응답에 포함되는지, 포함된다면 그 범위에 대한 합의

우리 쪽은 읽기만 씁니다. 쓰기 권한은 요청하지 않습니다.
회신 주시면 그날 안에 연동해 하루치 숫자를 기존 집계와 맞춰 보겠습니다.
```

## 3. 값이 오면 그날 일어나는 일

| 순서 | 누가 | 무엇 |
|---|---|---|
| 1 | 시토 | 서버 환경파일에 네 줄 넣고 소급 호출 (환경파일은 시토 소관) |
| 2 | 시포 | 하루치 대조 — 브로제이 숫자 ↔ 보고 시트 일자탭(회원권·강습권·총매출·계약 건수 + 입장객) |
| 3 | 시포 | 대조가 맞으면 매출 11칸·입장 3칸의 원천을 시트 손입력에서 브로제이로 교체 |

대조가 안 맞으면 교체하지 않는다. 이 순서는 배908 착수 때 정한 그대로다.

## 4. 이것이 풀면 같이 풀리는 것

매출·회원 현황 보고 화면(배1071)의 마지막 손입력 14칸이 사라진다. 회원 5칸은 이미 서버 원장으로 바뀌었고,
남은 매출 11칸·입장 3칸이 이 API를 기다리고 있다. 그때 화면이 자동보고의 원본이 된다.
