## 2. 우리가 쓸 통로 넷

| 무엇 | 주소 | 인증 |
|---|---|---|
| 일 매출·계약 건별 | `GET /v1/groups/{센터}/sales/history/products?start_date=&end_date=&page_size=200` | 머리말 `API-KEY` |
| 입장(출입) | `GET /v1/attendance/histories?group_id=&start_date=&end_date=&size=200&page_index=` | 〃 |
| 회원 명단 | `GET /v1/members?group_id=&limit=200&cursor=` | 〃 |
| 회원별 잔여 세션·회차권 | `POST /v1/groups/{센터}/members/tickets` (회원 ID 목록을 한 번에) | 〃 |

기준 주소 = `https://api.broj.co.kr`

**세션카드는 묶음 조회가 있다.** 회원 한 명씩 부르는 통로(`/members/{id}/tickets`)도 있지만 쓰지 않는다 —
1,749명을 한 명씩 부르면 한 번 훑는 데 1,749콜이라 여섯 번이면 한 달 무료량이 끝난다. 묶음 통로면 9콜이면 된다.

## 3. 하루치 실측 (2026-09-08 · 실제로 받아 봤다)

| 무엇 | 건수 | 한 번 받는 데 드는 콜 |
|---|---|---|
| 매출 | 27건 | 1콜 |
| 입장 | 744건 | 4콜 (한 장에 200건) |

받은 칸도 확인했다 — 매출은 결제시각·상품명·회원·분류·담당자·금액·현금/카드·결제수단, 입장은 출입시각·퇴장시각·회원·이용권·출입문까지 들어 있다. 우리가 보고에 쓰는 값이 전부 있다.

## 4. 호출 예산 — 월 1만이면 넉넉하다

| 하는 일 | 주기 | 월 호출 |
|---|---|---|
| 매출·입장 (오늘+어제) | 하루 3회 | 900 |
| 회원 명단 + 세션·회차권 | 하루 1회 | 540 |
| 여유(재시도·소급) | — | 300 |
| **합계** | | **약 1,740 (17%)** |

첫 적재로 지난 60일을 한 번 끌어오면 300콜이 추가로 들지만 그달 한 번뿐이다.

⚠️ **5분마다 부르면 안 된다.** 코드 머리말에 예시로 적힌 5분 주기로 걸면 월 34,000콜이라 무료량의 세 배다.
하루 3회로 건다 — 매출·입장 보고는 다음날 아침 발송용이라 5분 신선도가 필요 없다.
분당 60 제한이 있으니 소급 적재는 호출 사이를 5초 띄운다.

## 5. 서버에 넣을 값 네 줄 (시토 소관 · 값과 이유만 넘긴다)

```
BROJAY_SALES_URL=https://api.broj.co.kr/v1/groups/01M1XBZTZSR5C4BRZ7VC73NPNC/sales/history/products?start_date={date}&end_date={date}&page_size=200
BROJAY_ENTRIES_URL=https://api.broj.co.kr/v1/attendance/histories?group_id=01M1XBZTZSR5C4BRZ7VC73NPNC&start_date={date}&end_date={date}&size=200&page_index=0
BROJAY_API_KEY=<위 공유 드라이브 api_key.txt 첫 줄>
BROJAY_AUTH=API-KEY: {key}
```

마지막 줄이 중요하다 — 코드 기본값은 `Authorization: Bearer {key}` 인데 브로제이는 `API-KEY` 머리말을 쓴다.
그대로 두면 전부 인증 실패한다.

입장은 한 날에 4장까지 나오므로 `page_index` 를 돌며 받아야 한다 — 지금 코드는 한 번만 부른다.
그 부분은 서버 코드 수정이 필요하다(시토 배959).
