# /api/track — 전환 퍼널 첫 단 측정 (배1034 · 시모 요청 · 2026-09-05 시토)

## 규격

- `POST https://erp.wellperion.com/api/track` — 공개(무로그인). 본문 JSON 2KB 상한.
  ```json
  {"event":"view"|"click", "page":"/ko/inquiry", "target":"inquiry_btn",
   "channel_code":null, "post_id":"…", "utm_source":"kakao", "utm_medium":"…",
   "utm_campaign":"…", "utm_content":"…", "ref":"m.blog.naver.com", "sid":"세션당난수"}
  ```
  응답 `{"ok": true}`. event 가 view/click 이 아니면 400. IP 미저장. User-Agent 는 원문 저장 안 하고 `is_bot` 판정만 남긴다.
- `GET https://erp.wellperion.com/api/track/summary?from=YYYY-MM-DD&to=YYYY-MM-DD&group=day|channel_code|post_id|page` — 로그인 뒤(관문).
  응답 `{"ok": true, "rows":[{"key":..., "views":N, "clicks":N, "sessions":N}]}`. bot 행 제외. from/to 생략 시 전체 기간.

## 화면 삽입 스니펫 (시모용 — 홈·문의 페이지 등 원하는 곳에 그대로)

```html
<script>fetch('https://erp.wellperion.com/api/track',{method:'POST',headers:{'Content-Type':'application/json'},
body:JSON.stringify({event:'view',page:location.pathname,
  ref:document.referrer&&new URL(document.referrer).host,
  sid:(sessionStorage.sid||(sessionStorage.sid=Math.random().toString(36).slice(2))),
  utm_source:new URLSearchParams(location.search).get('utm_source')})}).catch(()=>{})</script>
```
클릭용은 `event:'click', target:'inquiry_btn'` 로 버튼 클릭 핸들러에서 같은 꼴로 fetch.

## channel_code

`sync_inquiries.channel_code_of(utm_source, 기록시각)` 재사용 — 표 A 11종 중 텍스트로 구분 가능한 6종
(naver_blog·kakao·danggn·naver_cafe·referral·direct_visit) + search. 못 맞추면 unknown. 문의 채널코드와 같은 규칙이라
문의 퍼널·트래킹 퍼널이 같은 축으로 붙는다.

- `server/erp_api/prune_track.py` — 90일 지난 행 삭제, cron 03:20 KST 일일(`/etc/cron.d/erp-track-prune`)
- `server/deploy_track.sh` — 배포 스크립트(재배포 시 이것만 실행)

## 참고

- POST 는 nginx exact match(`= /api/track`)로 `/api/` 로그인 관문보다 먼저 잡힌다 — `/api/track/summary` 는 이 exact
  match 에 안 걸려 그대로 로그인 관문을 탄다(별도 location 불필요).
- 배포 도중 다른 레인(api_reception)이 같은 erp-api 를 동시에 재기동해 트래킹 요청 1건이 일시 502 를 받았다 —
  재시도 시 정상 200. track 코드 자체 결함 아님(서비스 재기동 경합).
