⚠️ 문제점 5가지 — 심각한 순
1
보안이 열려 있습니다
🔴 최우선
문제
업무 API와 매출·지출 API에 비밀번호나 인증이 없습니다. 웰페리온 ERP 홈은 GitHub Pages(외부 공개 서버)에 올라가 있어 URL만 알면 누구든 매출·지출·회원정보를 볼 수 있습니다. 업무 목록을 추가·수정·삭제하는 것도 마찬가지입니다.
왜 위험한가
재무 정보가 한 번 새어나가면 주워담을 수 없습니다. 외부인이 업무 상태를 몰래 바꿀 수도 있습니다.
보완방안
접근 통제부터 시작: 비공개 토큰·로그인·IP 제한 중 하나 이상 적용. 매출·지출·회원정보 등 민감한 데이터는 인증을 통과한 뒤에만 볼 수 있게. 지금 당장은 GitHub Pages 공개 범위부터 점검하는 게 첫걸음입니다.
2
숫자를 믿기 어렵습니다
🔴 긴급
문제
오늘만 봐도 지출이 51,640원 → 309,400원으로 들쭉합니다. 원천 시트의 칸(열)이 밀려서 자동 집계가 제대로 안 되고 있고, 이슈 미처리 261건은 오늘 것만이 아니라 과거 누적이 섞여 있습니다.
왜 위험한가
GM이 보고서 숫자를 보고 결정을 내리는데, 그 숫자가 틀려 있으면 잘못된 판단으로 이어집니다.
보완방안
집계 기준을 한 곳에 못 박고, "이 숫자는 맞다"를 보장하는 검증 루틴 도입. 원천 시트의 칸 정렬과 상태 표기를 통일. 아직 검증 안 된 칸은 '집계 보완 중'으로 명시해 GM이 혼동하지 않도록.
3
한 파일에 너무 많이 담겨 있습니다
🟠 중요
문제
현재 메인 파일 한 개가 약 9,000줄입니다. 여러 작업이 동시에 같은 파일을 수정하다 보니 충돌이 나서 파일이 깨진 적이 이미 있습니다(임시로 커밋 순서를 직렬화해서 막고 있는 상황). 자동 점검도 없습니다.
왜 위험한가
파일이 또 깨지면 ERP 전체가 순간 멈춥니다. 무엇이 깨졌는지 찾기도 어렵습니다.
보완방안
데이터 로직과 화면을 분리하고, 핵심 흐름에 가벼운 자동 점검을 달아 "라이브가 안 깨졌는지" 바로 알 수 있게. 페이지를 기능 단위로 나눠서 한 파일이 터져도 나머지가 살아남게 하는 방향.
4
같은 정보가 여러 곳에 흩어져 있습니다
🟠 중요
문제
"단일 출처(SSOT)"를 목표로 하지만 실제 상태값은 업무 목록 파일 · 구글시트 · 자동화 스크립트 · 브라우저 저장 공간 · HTML 본문 다섯 곳에 나뉘어 있습니다. 오늘도 '오늘 한눈에' 중복 항목을 제거했습니다.
왜 위험한가
어디가 진짜인지 헷갈려서 수정이 한 곳에만 반영되고 나머지는 옛날 정보로 남는 사고가 반복됩니다.
보완방안
"기존 것 업데이트, 새로 만들지 않는다" 원칙 고정. 한 주제 = 한 곳. 정기적으로 중복을 점검하는 루틴 추가.
5
자동화가 중간에서 끊깁니다
🟡 개선
문제
콘텐츠 발행·당근마켓 업로드·IG 슬라이드 생성 등 여러 자동화가 "시연은 되는데 실전에선 사람이 손으로" 하는 구간이 남아있습니다. 오늘 발레 콘텐츠도 결국 수동 업로드였습니다.
왜 위험한가
GM이나 실무진이 매번 반복 동작을 수동으로 해야 하고, 빠뜨리면 누락됩니다. 자동화의 이점이 반감됩니다.
보완방안
끊긴 구간 목록화 후 우선순위 지정. 자동 임시저장 → 발행 트리거 연결 등 반복이 잦은 수동 구간부터 마무리. 완성 안 된 자동화는 "아직 수동" 표시로 혼동 방지.
🎯 먼저 고칠 3가지
  1. 보안부터
    재무 정보는 한 번 새면 못 주워담습니다. GitHub Pages 공개 범위 점검과 API 접근 통제가 첫 번째입니다.
  2. 숫자 신뢰 확보
    집계 기준을 못 박고, 아직 검증 안 된 칸은 '집계 보완 중'으로 명시합니다. GM이 틀린 숫자로 결정 내리는 상황을 막습니다.
  3. 단일 HTML 분리 + 가벼운 자동 점검
    9,000줄 단일 파일을 기능별로 나누고, 배포 후 라이브가 정상인지 자동으로 확인하는 장치를 붙입니다.
