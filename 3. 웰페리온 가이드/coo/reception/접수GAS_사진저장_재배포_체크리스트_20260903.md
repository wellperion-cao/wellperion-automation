# 종합접수처 GAS — 사진 저장 실패 수리 · 재배포/재승인 체크리스트 (2026-09-03)

증상: `사진 저장 실패: DriveApp.getRootFolder을(를) 호출할 수 있는 권한이 없습니다.`
원인: 폴더 ID 속성이 없거나 죽었을 때 `DriveApp.getRootFolder()` 로 루트를 뒤지던 대체 경로가 `drive.file` 스코프에서 막힘. 스크립트 속성에 Drive 권한이 없는 상태로 재배포된 뒤 재승인이 안 됐을 가능성.

## 바뀐 것 (코드 = `coo/reception/apps_script_reception.js`)
| # | 바뀐 곳 | 내용 |
|---|---|---|
| 1 | `_drvFolder_()` 신설 | 폴더 확보 공통 — 속성 ID → 없으면 `RECEPTION_DRIVE_PARENT`(상위 폴더 속성) 아래 생성 → 그것도 없으면 `DriveApp.createFolder()`(drive.file 허용). `getRootFolder()` 호출 0 |
| 2 | `_vGetPhotoFolder()` · `_lfGetFolder_()` | 본문을 `_drvFolder_` 위임으로 교체 |
| 3 | `_drvErrMsg_()` 신설 | 저장 실패 문구 원인별 분리 — 권한 → 「관리자에게 권한 재승인 요청 필요」 / 용량·형식 → 「파일 형식 또는 용량을 확인해주세요」 / 그 외 → 「잠시 후 다시 시도」 |
| 4 | 습득물 등록·접수 2곳·구 VOC 1곳 | 실패 문구를 `_drvErrMsg_` 로. 접수는 사진 없이도 저장되되 `photoWarning` 칸으로 이유를 돌려준다 |
| 5 | `appsscript_reception.json` 신설 | 매니페스트 정본 — 스코프 4개(drive.file · spreadsheets · script.external_request · script.scriptapp) · 실행 주체 나 · 액세스 익명 허용 |

## 확인 사항 답
| 물음 | 답 |
|---|---|
| 웹앱 실행 주체 | **나(배포자 · cao@wellperion.com)** — 접수_배포 가이드 §1-4 그대로. 그래서 Drive 권한은 배포자 계정 것 하나만 승인하면 된다 |
| 사진 저장 폴더가 정해져 있나 | **있다** — 스크립트 속성 `RECEPTION_PHOTO_FOLDER`(접수 사진 · 폴더명 RECEPTION_Photos, 옛 VOC_Photos) · `LF_PHOTO_FOLDER`(습득물 사진) · `LF_SIGN_FOLDER`(수령 서명 · 비공개). 속성이 살아 있으면 그대로 쓴다. 새로 둔 선택 속성 = `RECEPTION_DRIVE_PARENT`(저장 전용 상위 폴더 ID) — 넣으면 새 폴더가 그 아래에 생긴다 |
| 사진 링크를 시트에 쓰는 로직 | **있다** — 접수 시트 `photoUrl` 칸 · 습득물 시트 사진 칸. 이번 수정으로 바뀌지 않음 |

## 재배포·재승인 순서 (GM · 10분)
1. **Apps Script 편집기 열기** — 접수 전용 GAS 프로젝트(cao@). `Code.gs` 전체를 `apps_script_reception.js` 내용으로 **교체**(수정 부분은 `[2026-09-03]` 주석).
2. **매니페스트 켜기** — 프로젝트 설정(톱니) → 「"appsscript.json" 매니페스트 파일을 편집기에 표시」 체크 → 편집기에 생긴 `appsscript.json` 을 `appsscript_reception.json` 내용으로 교체. 저장.
3. **스크립트 속성 확인** — 프로젝트 설정 → 스크립트 속성: `RECEPTION_PHOTO_FOLDER` · `LF_PHOTO_FOLDER` · `LF_SIGN_FOLDER` 값이 있으면 그대로. (선택) `RECEPTION_DRIVE_PARENT` = 저장 전용 상위 폴더 ID.
4. **재승인** — 편집기에서 아무 함수(예 `_vGetPhotoFolder`) 선택 → ▶ 실행 → 「권한 검토」 → cao@ 선택 → 고급 → 안전하지 않은 페이지로 이동 → **허용**. 새 스코프가 뜨는지 확인(Google Drive 파일 보기·관리 = drive.file).
5. **배포 → 배포 관리** → 기존 웹앱 배포의 연필(수정) → 버전 「**새 버전**」 → 설명 `사진 저장 권한 수리 2026-09-03` → 실행 계정 **나** · 액세스 **모든 사용자** 그대로 → **배포**. (URL 은 그대로 유지된다 — 새 배포를 만들지 않는다)
6. **확인** — 시크릿 크롬으로 `wellperion.com/ko/lost-found-register/` 에서 사진 1장 등록 → 갤러리에 뜨는지 · Drive 폴더에 파일 생기는지. 실패하면 문구가 「권한 재승인 요청 필요」로 뜨는지 본다.
7. `drive.file` 로 부족하면(기존에 사람이 손으로 만든 폴더를 못 열 때만) 매니페스트 스코프를 `https://www.googleapis.com/auth/drive` 로 올리고 4~5를 다시.
