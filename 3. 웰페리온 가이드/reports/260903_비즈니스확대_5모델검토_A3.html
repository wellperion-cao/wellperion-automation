핵심 리스크

  • 사람이 먼저 막힌다. 실장 라인 5명·준용M 과부하 상태 — 위탁·2호점은 사람 없이는 착수 자체가 안 된다.
  • ERP 판매 전 보안 결함. 업무·결재 GAS가 인증 없이 쓰기·삭제를 받는다(2026-06 인지). 팔기 전 반드시 수리.
  • 플랫폼 실패 경험. 이번엔 실 고객(다캠)이 먼저 있고 개발비 0 — 그래도 유료 전환 0건이 6개월 지속되면 중단선을 미리 둔다.
  • 카톡 PC 자동화 의존 — 상한 6통·창 잠김 사고(09-03) 있었음. 방 30개 넘으면 다른 통로 필요.
  • 온라인 문의 전환이 약해(19%) 「퍼포먼스 마케팅」을 팔 실적 근거가 아직 없다.

실행 액션 (승인 시)

  • 모듈: 다캠 파일럿 → 요금은 공급가부터 설계 → GM 결재 → 2·3호는 소개로만.
  • ERP 판매: AWS 서버(시토 배 909) + 보안 수리 + 하드코딩 제거 → 판매 단위 = 핵심 3모듈(회원·문의·점검) → 다캠을 2호 테넌트 후보로.
  • 퍼포먼스 마케팅: 별도 사업으로 열지 않는다 — 모듈 상품의 「콘텐츠·문의」 행으로 흡수, 고객 월 문의 수로만 잰다.
  • 위탁: 수탁 수요 1건(GM 인맥)이 나올 때까지 착수 안 함.
  • 2호점: 대기자 수·대기 기간을 회원 원장에서 세어 별도 A3.

GM 권고

  • 순서 = 모듈 → ERP 판매 → 위탁 → 2호점. 마케팅은 모듈 안에.
  • 왜 모듈이 1번인가: 돈·사람이 안 들고 첫 고객이 이미 있다. 여기서 나온 요금·회신이 나머지 전부의 근거가 된다.
  • 왜 디지털 둘을 묶나: 같은 자산(AWS·ERP·에이전트)을 쓴다 — 모듈이 ERP 판매의 진입로다.
  • 왜 현장 둘은 뒤인가: 사람·돈이 먼저인데 지금 둘 다 없다. 숫자가 나오면 그때 별도로.
  • 올해 상위 KPI 목표 = 유료 확장 1건(다캠). 건별 KPI는 각 배에 붙인다.
수치 출처: 매출 46.7억·72억 = 홈 KPI 스냅샷(8월 누계) / 회원 995·재등록 635·대기 5 = 통합회원 스냅샷 / 문의 752·등록 208 = 26년 신규문의 시트 스냅샷(1~9월) / 온라인 전환 19% = 2026-04 실측 412건 / 자산 수 = 저장소 실측(페이지 185·스크립트 255·GAS 15·모듈 29).
