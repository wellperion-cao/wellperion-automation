딜라이브에 요청할 것 (연락 오면 그대로)

  • 연동 안내서 — 홈페이지에서 다운로드가 안 되던 그 문서
  • 연동용 계정과 인증키 발급
  • 시험 발송용 환경 — 실제 회원에게 보내기 전 확인용
  • 발신번호 승인 상태 확인 — 등록한 번호가 바로 쓸 수 있는지
  • 요금표 — 짧은 문자·긴 문자 건당 단가, 선불/후불. 월 200~250건 예상 (추정)
  • 긴 문자 가능 여부와 글자 수 한도
  • 수신거부 처리 방법 — 나중에 재등록 안내를 보낼 때 법으로 필요

먼저 확인해야 할 것 · 위험

  • 접속 주소를 미리 등록해야 쓰는 방식인지 반드시 물어야 한다. 그 방식이면 지금 우리 구조로는 못 붙고 방법을 바꿔야 한다
  • 보낸 문자가 도착했는지 확인하는 기능이 없으면, 발송 실패를 아무도 모른 채 지나간다
  • 접수·문의 회신 문자는 본인이 요청한 건에 대한 답이라 사전 동의 없이 보낼 수 있다
  • 반면 재등록·만기 안내는 광고성으로 분류될 수 있어 수신 동의와 야간 발송 제한(21시~08시)을 지켜야 한다. 두 가지를 같은 통로로 묶지 않는다
  • 회원 휴대폰으로 나가는 자동 발송은 지금까지 한 건도 없었다. 첫날은 소량으로 시작해 확인한다

시토 권고

  • 서버는 지금 필요 없다. 문자는 현재 구조 그대로 붙는다. 사고 45건 중 서버로 막혔을 것은 1건뿐이었다
  • 종합접수처부터 시작한다. 연락처가 100% 모여 있고 문구도 이미 있어 붙일 것이 가장 적다
  • 문의 접수는 확인 문자까지만. 상담 내용은 사람이 하는 편이 낫다
  • 재등록·만기 안내는 나중에. 법적 조건이 다르고, GM이 정한 하루 10~20명 분할 발송 원칙을 그대로 옮겨야 한다
  • 회신이 이번 주에도 없으면 다른 문자 업체를 함께 알아보는 것을 권한다 — 준비는 이미 끝나 있어 업체만 바뀌면 된다
실측 근거 — 연락처 보유량은 종합접수처 원장 라이브 조회(115건 전수)와 문의 원장(723건) 실측. 월 발송량 200~250건은 추정치다: 접수 7월 73건·8월 41건(24일까지), 문의 최근 6개월 월평균 82건에 접수 확인과 완료 안내를 각 1통씩 보내는 경우로 계산했다.
이미 끝난 것 — 매출·운영 보고의 예약·이탈 칸 자동 기입(08/21), 이탈 명단에 사유 붙이기(08/24), 사람이 고친 칸을 자동 기입이 덮어쓰던 문제 차단(08/24). 남은 손입력은 이탈자 칸 하나이며 기준 날짜만 정해지면 전환된다.
