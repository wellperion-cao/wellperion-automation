DIRECTION방향
01
읽기 전용 API 4갈래(결제·입장·회원·상품)를 하루 단위로 당겨 AWS 서버에 쌓고, 매출보고서 숫자 칸을 자동으로 채운다
지금은 실무진이 그날 계약을 보고 시트 일자탭에 손으로 적어야 보고서가 나온다. 손이 비면 보고서가 빈다(9/4 실사고). 원천을 브로제이로 바꾸면 그 손이 사라진다. 쓰기 권한은 받지 않는다.
02
사양·키가 오면 9/4 하루치를 보고서와 대조해 맞는 갈래부터 교체 — 안 맞으면 교체하지 않는다
대조 기준 = 9/4 보고서(총 25,343,000 · 회원권 15,880,000 · 옵션 575,500 · 수영 5,305,500 · 입장 482/12/34). 10/1 결제·매출 보고 브로제이 기준 전환(보고서 H21 기록)에 맞춰 9월 안에 3일 대조를 끝낸다.
보고서 칸 (매일 09:30 카톡 3방)지금 원천브로제이에서 받아야 할 것계산 규칙(우리 쪽)
매 출 (금일 · 월 누적)
총 매출 합계 · 회원권 매출 · 옵션 매출일자탭 손입력(회원권 A~G열)A. 결제(계약) 건별 조회 — 결제일시·상품구분(회원권/강습권/옵션/일일권)·금액·결제수단·계약구분(신규/재등록/양도/환불/취소)결제일(KST) 기준 합계 · 환불·취소는 음수 또는 상태로 구분해 순매출
팀별 강습 매출 8줄(수영·P.T·골프·스쿼시·체조·P.L·뮤지컬·GXE)일자탭 손입력(강습 H~N열)A 의 종목/팀 칸 + E. 상품 마스터(상품코드 ↔ 구분·종목·팀)상품코드로 팀을 가른다 — 이름 문자열로 가르지 않는다
신규 등록 매출 · 재등록 매출 · 환불 매출일자탭 분류 칸 손입력A 의 계약구분 + 환불 원거래 ID구분별 합계 · 환불은 원거래와 짝
인 원 (등록 · 로스 · 회원 구성)
신규등록자 · 재등록자(L재등록) · 로스자일자탭 손입력 + ERP 원장A 의 계약구분 인원 + D. 회원 상태 변경분(만료·미갱신·휴회)사람 수(같은 사람 2건=1명) · 로스 = 종료일 지나 미갱신
총 회원수 · 정회원 · 중단기 · 법인 · 대기ERP 회원 원장(구글 시트 → 서버 미러)D. 회원 마스터(회원ID·이름·전화·구분·상품·시작·종료·상태·수정시각 · updated_since 조회)당분간 우리 원장이 정본 — 브로제이 값은 대조용. 회원 매칭키 = 브로제이 회원ID + 전화
입 장
일일입장객 — 멤버십 · 준회원 · 유소년손입력(8/12부터 보고 중단)C. 입장(출입) 로그 — 입장시각·회원ID·회원구분·출입구·인증수단(얼굴/카드)·퇴장시각일별 고유 인원 by 회원구분(같은 사람 재입장=1명) · 일일권은 별도
사 람 이 쓰 는 칸 (API 대상 아님)
예상 컨택·LOSS 기록 · 팀별 운영현황 · 인사&파트너 · 핵심 보고 · 목표 매출·달성률실무진 서술 · 우리 목표표—그대로 사람이 적는다(목표는 우리 SSOT)

브로제이에 요청하는 것 — 기술 조건 7

  • 조회 주소(엔드포인트) 4갈래 + 필드 정의서(문서) — A 결제 건별 · C 입장 로그 · D 회원 · E 상품 마스터
  • 인증 — API 키 또는 토큰(헤더), 발급·재발급 절차, 읽기 전용 권한
  • 조회 조건 — 기간(from·to, 결제일시/입장시각 기준 명시) · 페이징 · 건수 상한 · 시간대 KST
  • 수정·취소 반영 — 수정시각(updated_at) 필드 · 환불/취소는 상태 또는 음수, 원거래 ID 연결
  • 호출 제한(분당·일당) · 응답 지연 기준 · 장애 시 연락 창구
  • 테스트 환경 또는 표본 응답 JSON(각 갈래 하루치) — 대조는 이걸로 먼저
  • 개인정보 범위 합의 — 이름·전화 포함 여부, 회원 매칭용 브로제이 회원ID 고정값

우리 쪽 준비 — 이미 끝난 것

  • AWS 서버 저장소·배치 완료(시토 9/4) — 응답 JSON 통째 저장, 하루 단위·소급 인자, 멱등
  • 호출 주소·키는 코드가 아니라 서버 설정 4줄 — 사양·키가 오면 코드 수정 없이 그 자리에서 돈다
  • 매출·회원 현황 보고 화면(1·2페이지)은 서버 우선 읽기로 전환 완료(9/5) — 원천만 바꾸면 화면은 그대로
  • 회원 원장 서버 미러 12 라우트 대조 12/12 일치(9/5) — 회원 매칭 준비 끝
  • 원칙 — 읽기 전용 · 키는 저장소 밖 · 새 화면 없음 · 대조 안 맞으면 교체 안 함

일정 · 검증

  • 9/7(월) 사양·키 수령(GM) → 같은 날 서버 설정 4줄 채움(시토) · 표본 호출(시포)
  • 9/7~9/8 9/4 하루치 대조 — 총매출·회원권·옵션·팀별 8줄·입장 3줄이 보고서와 원 단위 일치해야 통과
  • 9/8~ 8월 1일부터 소급 적재 + 매일 새벽 자동 호출(cron) · 3일 연속 대조 무결
  • 10/1 결제·매출 보고 브로제이 기준 전환 — 보고서 매출·인원·입장 칸 자동, 사람은 서술 칸만
  • 안 맞는 갈래는 그 갈래만 시트 유지 — 부분 전환 허용, 전체 지연 없음

왜 4갈래인가 — 보고서 숫자 칸 22개 중 사람 서술 6개를 뺀 16개가 결제 건별(A)·입장 로그(C)·회원 상태(D)·상품 매핑(E) 넷으로 전부 계산된다. 일 매출 집계 API 는 A 로 계산되므로 필수 아님(있으면 대조용).
