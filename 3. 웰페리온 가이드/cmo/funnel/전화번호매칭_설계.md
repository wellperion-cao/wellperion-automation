# 전화번호 매칭 설계 — 문의→가입 전환 추적

작성일: 2026-06-02
담당: AI CMO (시모)
실무진(최종 책임자): 김남욱 GM
버전: v1.0

---

## 1. 목적

문의 누적 시트(survey 문의접수)에 쌓이는 연락처와, 회원부가 관리하는 회원 DB의 전화번호를 키로 대조한다.
"이 사람이 문의 후 실제 멤버십에 가입했는가?"를 자동으로 판별해 마케팅 현황 대시보드 5단계 퍼널의 **문의→가입 전환율** 수치를 실측값으로 채운다.

현재 두 데이터는 완전히 분리되어 있다. 문의접수 시트(Apps Script — `1g9Ohmd8C_WxyvWt9EX58oEFZLiOAJ_EG7t7XteJFuGE`)에는 `연락처` 컬럼(컬럼 D, 헤더명 `연락처`)이 있고, 회원부 시트에도 전화번호 컬럼이 있을 것이다. 두 시트를 전화번호 하나로 이어 붙이면 전환 추적이 가능하다.

---

## 2. 전화번호 정규화 규칙

두 시트의 입력 형식이 다를 수 있다(`010-1234-5678` vs `01012345678` vs `+821012345678`). 비교 전에 동일한 형태로 정규화해야 매칭이 맞는다.

### 정규화 순서

1. **숫자만 추출** — 하이픈(-), 공백, 괄호 등 모든 비숫자 문자 제거
   - `010-1234-5678` → `01012345678`
   - `010 1234 5678` → `01012345678`

2. **국가코드 제거** — 앞에 `82`가 붙어 있으면 `82` → `0`으로 교체
   - `821012345678` → `01012345678`
   - `+821012345678` → `01012345678` (1단계에서 `+` 이미 제거됨)

3. **010 표준화** — 정규화 결과가 11자리 숫자이고 `010`으로 시작하면 그대로 사용. 그 외 형식(011, 016 등 구번호)도 숫자만 추출한 상태로 보존.

4. **빈값 처리** — 정규화 후 빈 문자열이면 매칭 제외(건너뜀)

### Apps Script 정규화 함수 (구현 시 사용)

```javascript
function normalizePhone(raw) {
  if (!raw) return '';
  var digits = String(raw).replace(/\D/g, ''); // 숫자만
  if (digits.startsWith('82') && digits.length >= 11) {
    digits = '0' + digits.slice(2);            // 국가코드 제거
  }
  return digits;
}
```

## 3. 데이터 흐름도

```
[문의접수 시트]
  컬럼: id | 시각 | 이름 | 연락처 | 문의유형 | 내용 | 유입채널 | UTM소스 | UTM미디엄 | 상태 | 메모
  ↓
  normalizePhone(연락처) → 정규화 키 생성
  ↓
  정규화 키로 [회원부 시트] 전화번호 컬럼 조회
  ↓
  매칭 여부 판별
  ├── 일치하는 행 있음 → "가입 전환" 카운트 +1
  └── 없음 → "미전환" 카운트 +1
  ↓
  집계 결과
  ├── 총 문의 건수
  ├── 가입 전환 건수
  ├── 문의→가입 전환율 (가입 건수 / 문의 건수 × 100%)
  └── 채널별 전환율 (UTM소스·유입채널 기준 분리 집계)
  ↓
[대시보드 ⑤ 가입 단계 수치로 반영]
```

## 4. 대시보드 반영 방식

### 퍼널 위치

마케팅 현황 대시보드(`마케팅현황대시보드.html`)의 **⑤ 가입(Conversion)** 단계에 해당한다. 현재 해당 단계 상세 카드에 이미 아래 4개 항목이 placeholder로 준비되어 있다.

| 항목 | placeholder 위치 | 채울 값 |
|------|-----------------|---------|
| 월간 신규 가입 건수 | 상세 카드 좌상단 | 매칭 결과 가입 전환 건수 |
| 문의→가입 전환율 | 상세 카드 우상단 | 가입 건수 ÷ 문의 건수 × 100% |
| 투어→가입 전환율 | 상세 카드 좌하단 | 문의유형='투어 예약' 중 전환 비율 |
| 평균 결정 소요 기간 | 상세 카드 우하단 | 첫 문의 시각 ~ 회원부 가입일 차이(일) |

퍼널 바(width: 12%)와 우측 사이드의 `문의→가입 전환율 <placeholder>` 항목도 동일 수치로 교체한다.

### 채널별 전환율 계산식

문의접수 시트의 `유입채널` 또는 `UTM소스` 기준으로 그룹화한다.

```
채널별 문의→가입 전환율
= 해당 채널 문의 건 중 전화번호 매칭된 건수
  ÷ 해당 채널 총 문의 건수
  × 100%
```

채널별 비교 테이블(채널별 비교 섹션, `channel-table`)의 "문의 전환" 컬럼에 채널별 가입 전환 건수를, "노출→문의 전환율" 옆 컬럼(또는 기존 컬럼 대체)에 문의→가입 전환율을 추가할 수 있다.

### KPI 요약 카드 연결

상단 KPI 요약 행의 "신규 가입" 카드(`color: var(--f5)`) = 매칭 결과 월간 가입 전환 건수
"전체 문의 전환율" 카드 = 월간 가입 건수 ÷ 월간 총 노출(또는 총 문의 건수) — 정의는 GM님과 확정 후 적용

## 5. GM 확보 필요 항목

구현 착수 전에 아래 3가지가 반드시 필요합니다. 확보되면 바로 Apps Script 매칭 함수 작성 및 대시보드 수치 연동을 진행합니다.

| 번호 | 항목 | 설명 |
|------|------|------|
| 1 | **회원부 구글 시트 ID 또는 URL** | 회원 DB가 담긴 구글 시트 주소. 예: `https://docs.google.com/spreadsheets/d/{ID}/` |
| 2 | **접근 권한** | Apps Script가 해당 시트를 읽을 수 있도록 `cao@wellperion.com` 계정에 편집자 또는 뷰어 권한 부여 |
| 3 | **전화번호 컬럼명(헤더)** | 회원부 시트에서 전화번호가 들어 있는 컬럼의 정확한 헤더 이름. 예: `전화번호`, `연락처`, `Phone` 등 |

선택 확인 사항(있으면 정확도 향상):
- 회원부 시트의 가입일 컬럼명 → 평균 결정 소요 기간 계산에 필요
- 회원부 시트에서 사용 중인 탭(시트) 이름

## 6. 개인정보 주의사항

- 전화번호는 **매칭 키로만 사용**한다. 정규화된 번호끼리 일치 여부만 판별하고, 결과는 "건수"와 "전환율" 집계값만 저장한다.
- 대시보드 HTML에는 **개별 전화번호를 절대 표시하지 않는다**. 화면에 노출되는 것은 "문의 N건 중 가입 N건(전환율 N%)" 형태의 집계 수치뿐이다.
- Apps Script 내부에서도 전화번호 비교 후 즉시 변수를 파기하며, 별도 로그나 시트에 전화번호 자체를 기록하지 않는다.
- 집계 결과를 텔레그램 보고로 보낼 때도 "이번 달 문의→가입 전환율 XX%" 형식만 사용한다.

위 5번 항목 3가지(시트 ID·접근권한·컬럼명)를 GM님께 받는 즉시 구현을 시작합니다.
