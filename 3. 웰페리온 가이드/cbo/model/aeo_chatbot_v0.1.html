3. 작동 한 바퀴

  1. FAQ 씨앗 10문항 — 사장님 자료(가격표·프로그램) + "자주 받는 질문 3가지"(아침 질문) + 우리 문의 원장의 상위 질문 유형
  2. 학습 — AI 가 아침마다 사장님께 질문 1개, 답 한 줄이 FAQ 한 줄이 된다(기존 카톡 에이전트 그대로 · 하루 1문항 · 재촉 없음)
  3. 고객 답변 — 고객 질문에 FAQ 근거로만 자연스럽게 답한다. FAQ 에 없으면 지어내지 않고 "상담 예약" 으로 이어 준다. 금액·의료 표현은 금지어 관문(기존) 재사용
  4. 되돌림 — 못 답한 질문 = 다음 아침 사장님께 여쭙는 질문. 답이 오면 FAQ 에 들어가고 다음부터는 봇이 답한다
  5. AEO 자산 동시 발행 — 같은 FAQ 가 질문형 제목·즉답 문단의 공개 FAQ 페이지로 나간다(구조화 데이터 FAQPage) → AI 검색이 인용

6. 요금 — 미산정

공급가부터. 원가 = 답변 모델 호출(질문당) + 서버 몫(테넌트당) + 아침 학습 1통. 다캠 첫 달 실측(질문 수·호출 수)이 나온 뒤 설계 → GM 결재. 그 전엔 대표님께 숫자를 말하지 않는다.

7. 위험 — 이것 때문에 무너진다

위험막는 법(전부 기존 장치 재사용)
지어낸 답 한 번이면 신뢰 끝FAQ 에 없으면 답하지 않는다 — "상담 예약" 으로. 근거 없는 문장 출력 금지를 프롬프트가 아니라 코드(FAQ 매칭 실패 = 고정 문구)로
금액·의료 표현카톡 에이전트 금지어 관문 그대로. 가격은 "상담 시 안내"
고객 개인정보이름·전화 저장 안 함. 상담 예약은 접수 링크로 넘긴다(폼이 받는다)
사장님 학습 피로하루 1문항 · 답 없으면 넘어감 · "며칠째" 금지 — 기존 브리프 규칙
웰페리온이 안 써 본 것을 판다웰페리온 FAQ 로 우리가 먼저 2주 돌려 본다(자체 시험 없이 넘기지 않는다)

8. 순서 — 하나씩

  1. 다캠 FAQ 씨앗 10문항 초안(시보 · 자료 + 아침 질문 "자주 받는 질문 3") → 대표님 확인
  2. 시토: /api/chat/{센터} + 위젯 1개 + 센터별 FAQ 저장 (테넌트 1개로 시작)
  3. 웰페리온 FAQ 로 자체 시험 2주 — 자력 답변 비율 실측
  4. 다캠 라인에 FAQ 페이지 + 위젯 → 대표님 페이지로 소개(Before&After 3차)
  5. 한 달 실측 → 요금 설계(공급가) → GM 결재 → 유료 전환 제안
