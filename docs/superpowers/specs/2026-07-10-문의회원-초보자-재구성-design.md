# 문의회원 페이지 재구성 — 초보자 현황 파악 우선 (설계)

- 작성일: 2026-07-10
- 소유: 시포(AI CPO)
- 대상 파일: `3. 웰페리온 가이드/cpo/member/문의회원.html` (약 6569줄)
- 관련 배: 754 (CPO 자율화 두뇌 / 상담사 액션 허브)
- GM 승인: 방향 확정(2026-07-10) — 시안 v2 `hub-as-popup`

## 1. 배경·목표

GM 지적: "문의가이드·운영원칙루틴·문의현황·문의이후·이탈관리·오늘할일 등이 다 나열돼 보기 불편하다. '스포츠클럽 영업·회원관리 가이드&교육'도 추가하고 싶다. 전체적으로 **초보자(신규 상담사)도 쉽게 현황 파악**하게 하고 싶다. 강습도 비슷하게."

**목표:** 신규 상담사가 페이지를 열었을 때 (1) "지금 뭘 봐야 하는지"가 한눈에 잡히고 (2) '현황'과 '읽는 안내'가 구분되며 (3) 흩어진 가이드가 한 곳에서 필요할 때 열린다.

## 2. 현행 실측 (재설계 근거)

Explore 실측 결과, GM이 느낀 '나열'의 실체는 **본문이 아니라 헤더 툴바**였다.

- **본문은 이미 탭 구조** — `#type-membership` 내 5-pane(달력·문의DB·가이드·등록·활성회원)은 세로로 쌓이지 않고 `switchTab()`으로 한 번에 하나만 표시(문의회원.html 3136–3148). 스크롤 짧음.
- **진짜 어수선함 = `.header-actions` 11버튼이 그룹 없이 한 줄**(1025–1039). 정적 안내(📖문의가이드 `openGuidePopup` 2494, 📋운영원칙·루틴 `openGdoc('principle,routine')` 2506) + 라이브 현황(📊멤버십/강습 문의현황·📊문의이후 2932·🧭오늘할일 2541) + 혼합(🚪이탈관리 2532) + 외부·유틸(문의페이지·시트·ERP홈·인쇄)이 **한 줄에 뒤섞임** → 초보자가 "무엇이 현황이고 무엇이 안내인지" 구분 불가.
- **정적 안내가 두 곳에 분산** — `#pane-guide`(SOP, 1230–1318, 📖버튼이 새 창으로만 노출) + `#gdoc-tpl` 5종(principle 1930·routine 1945·churnsummary 1981·churn 1999·churnstat 2022, 모두 숨김 템플릿→모달). inline 통합 노출 지점 없음.
- **네비 없음** — 상단 목차·앵커 없음. family(멤버십/강습, `switchFamily` 3173–3192) → 유형칩(`typeChipBar` 1050) → 내부 탭(`switchTab`) 3층.
- **헤더 브랜드** — H1 `#pageTitleTxt`(1016, family 전환 시 텍스트 교체) + `#cpoReportStatusLine`(1022, 자동보고 상태줄).

## 3. 재설계 — 3가지 변화 (본문 탭 구조는 불변)

### (A) 초보자 안내 배너 + 오늘 현황 요약 (신설, 본문 최상단)

- **초보자 안내 배너**: 본문 첫 줄에 접기 가능한 안내 — "처음이세요? 이 페이지는 회원을 ①문의 받고 → ②상담·등록하고 → ③관리·이탈 방지하는 곳입니다. 아래 오늘 현황 4칸부터 보세요." 닫기(✕) 시 localStorage로 기억(다시 안 봄).
- **오늘 현황 요약(히어로)**: 큰 숫자·쉬운 말 4칸. **기존 `#cpoTodayStrip`(1062–1096)의 역할을 흡수·리스타일** — 신규 중복 블록을 만들지 않는다. 각 칸 = 아이콘 + 쉬운 라벨 + 큰 숫자 + 한 줄 설명 + "→ 이동" 안내, 클릭 시 해당 현황 화면/모달로 직행.
  - 멤버십 4칸: 🆕 새 문의(오늘·미처리) / 📅 오늘 예약 / ⚠️ 이탈 위험(갱신임박·저이용) / 🧭 오늘 할 일.
  - 데이터: 전부 **기존 라이브 소스 재사용**(cpo_today_stats·cpo_churn_stats·오늘할일 분류기). 신규 fetch·신규 집계 로직 없음. 목업/예시값 금지.
  - 상태색: 의미색으로 인코딩(이탈위험=위험색, 새문의=양호색 등). 접근성 대비 유지.

### (B) 헤더 11버튼 → 3구역 그룹핑

- `.header-actions`(1025–1039)를 라벨 붙은 3구역으로 시각 분리(좌측 색 스트립 + 소문자 라벨):
  - **📊 현황(라이브)**: 멤버십/강습 문의현황 · 문의 이후 현황 · 이탈관리(라이브 현황) · 오늘 할 일. (family 전환 시 멤버십↔강습 문의현황 대칭 노출 로직 3182–3184 보존)
  - **📖 가이드·교육**: 단일 버튼 "가이드 & 교육 허브 ▾" → 팝업(아래 C).
  - **🔧 도구**: 문의 페이지↗ · 문의 시트↗ · ERP 홈 · 인쇄.
- 버튼 동작·핸들러(onclick 대상 함수)는 그대로, **묶음·라벨·스타일만** 변경. 자동보고 상태줄(`#cpoReportStatusLine` 1022) 보존.

### (C) 가이드 & 교육 허브 = 상단 버튼 팝업 (GM 확정: 하단 섹션 아님)

- **하단 인라인 섹션을 만들지 않는다**(GM: "문의 DB 클릭하면 맨 아래까지 내려가 보기 어려움"). 헤더 📖버튼으로 여는 **팝업(모달)**로 제공.
- 기존 모달 패턴 재사용 — `.gdoc-overlay`/`.consult-overlay` 오버레이 + ✕·바깥클릭·ESC 닫기(2552). 신규 오버레이 규격 신설 최소화.
- 허브 내용(흩어진 정적 안내 **재포장·모음**, B안):
  - 📖 문의 처리 SOP — 기존 `#pane-guide`(1230–1318) 내용 이전.
  - 📋 운영 원칙 · 정기 루틴 — 기존 `#gdoc-tpl` principle(1930)·routine(1945) 이전.
  - 🚪 이탈관리 매트릭스 — 기존 churn 정적 매트릭스(churn 1999·churnstat 정적 골격) 중 **교육용 정적 부분만**. ⚠️ **라이브 이탈 현황(숫자 주입 2523–2524)은 📊현황(이탈관리 버튼)에 그대로 남긴다** — 팝업엔 '읽는 교육'만.
  - 🎓 스포츠클럽 영업 · 회원관리 교육 — **빈 자리(플레이스홀더)만 신설**. "준비 중 — 이후 채움" 정직 표기. 실제 교육 콘텐츠 작성은 본 배 범위 밖.

### (D) 강습(lesson) 동일 틀 + 정직한 공백

- `switchFamily('lesson')` 시 동일 3구역·요약·허브 틀 적용(공유 헤더).
- 강습 요약: 🆕 새 강습문의 / 📞 미컨택 / 📅 오늘 상담예약. **이탈·오늘할일(이탈 기반)은 강습에 출석·만료 데이터가 없어**(원장 7칸 `_LESSON_REG_HEADER` 439, 출석/만료 부재) 해당 칸을 **정직하게 비움**(🚧 "출석·만료 데이터 없음 · 데이터 준비 후 제공"). 억지 숫자 금지.
- 강습 허브: 강습 SOP + 공통 운영원칙 + 영업·교육 자리 + 🚧 강습 이탈관리("데이터 파이프 ≈9월 후 편입", 배754 ① 참조).

## 4. 보존 제약 (비파괴)

- 본문 탭(달력·문의DB·등록·회원관리)·강습 서브탭 **기능·라이브 데이터 전부 보존**. 재배치 대상은 헤더·안내/요약 영역·가이드 이전뿐.
- 모든 숫자 = **라이브 바인딩**. 목업/예시값 하드코딩 금지(메모리 규칙).
- `#gdoc-tpl` 물리 삭제 시 **인덱스 고정참조 깨짐 주의** — 이전(move) 시 호출부(openGdoc 인자·churn 라이브 주입 경로) 전수 확인 후. 안전 우선 시 템플릿은 두고 허브에서 재노출하는 방식 허용.
- 검증 = **시크릿 크롬 라이브 실측**(멤버십·강습 각각, 콘솔 에러 0, 기존 현황/모달 회귀 0). 역롤백 준비(커밋 단위 분리).
