## 1. 현 루프 실측 진단 — 왜 '로드맵 소진형'인가 (코드 근거)

### 1-1. 선정 함수의 입력 공간에 '목표'가 없다
`scripts/ig_series_producer.py`:
- `pick_next_episode(episodes)` (383~407행): 입력 = 로드맵 표 행 리스트 하나뿐. 로직 = ①상태 `기획예정` 완전일치(394행) ②완료 키워드 안전망(396행) ③폴더 미존재(398행) → 통과 후보를 `candidates.sort(key=lambda e: e["num"])` 번호 오름차순 정렬 후 `[0]` 반환(406~407행). 북극성·전환·클릭·주간목표 — 어떤 성과 신호도 이 함수에 들어오지 않는다. 구조적으로 FIFO 큐 소진기다.
- `parse_roadmap_episodes` (151~188행): 표에서 뽑는 필드 = num/date/folder/title/message/status 6개(175~184행). 성과·각(角)·목표 필드 자체가 스키마에 없다.

### 1-2. ⑤환류는 '선정이 끝난 뒤' 읽기전용 출력일 뿐
- `read_latest_marketing_proposal` (415~441행): 최신 주간 브리프의 `## 4. 다음 편 제안`을 읽되, 모듈 docstring 35행이 명시: "선정 자체는 절대 바꾸지 않는다 (pick_next_episode 는 이 값을 읽지도 않음)".
- main `run()` 흐름 (929→948행): `nxt = pick_next_episode(episodes)`(929행)가 먼저 끝나고, `CMO_LOOP_FEEDBACK` 플래그(기본 OFF, 410~412행)가 켜져 있을 때만 948~953행에서 제안을 [참고]로 print. 시간 순서상으로도 선정에 개입 불가능.
- 게다가 입력이 비어 있다: 최신 브리프 `status/briefs/CMO-weekly-feedback-20260706.md` 62~71행의 §3 Top/Bottom·§4 다음 편 제안이 플레이스홀더 그대로(시모 미채움) → `read_latest_marketing_proposal`은 439~440행 정직 가드로 None 반환. 즉 '참고' 물림조차 실입력 0.

### 1-3. 루프의 ①제작과 ⑤평가가 서로 다른 계정을 본다 (범주 불일치)
- producer는 개인 namuk 전용: `NAMUK_DIR`(66행), `account="namuk.wellperion"`(564행), GM 1인칭 보이스 프롬프트(534행~), 저장·댓글·팔로우 CTA(555~559행).
- ⑤평가 `scripts/weekly_marketing_feedback.py`는 공식 @wellperion 전용: `OFFICIAL_ACCOUNT = "wellperion"`(105행), `load_official_recent`가 account 정확일치로 개인 배제(277행).
- 따라서 현 배선을 그대로 켜도 "공식 전환 성과 → 개인 시리즈 제작"이라는 범주가 어긋난 되먹임이 된다.

### 1-4. 북극성 대상(공식 콘텐츠)에는 제작 루프 자체가 없다 — 가장 큰 실측
- 과제 전제("로드맵에 개인·공식이 섞여 있음")를 실측한 결과 사실과 다름: `instagram/_AI시리즈_로드맵.md` §5 표(183~225행)는 전부 namuk 개인 시리즈. 공식/F1 grep 매치 = §2 규칙 문구(로고 33행·CTA 42행·게이트 123·135행)뿐, 편 행 없음.
- 공식 F1~F3 시설 시리즈·여름방학특강 Ep1~3은 로드맵·프로듀서 밖 수작업 폴더로 존재: `instagram/260707_공식_시설_F1_운동`·`F2_편의시설`·`F3_회복`, `260629~0701_여름방학특강_ep1~3` (Glob 실측). 기계가 읽는 후보풀 SSOT가 없다.
- 결론: "producer가 북극성을 안 본다"에 더해, 북극성이 조준하는 공식 콘텐츠는 애초에 자동 루프의 대상이 아니었다.

### 1-5. 측정은 편별로 절반만 배선돼 있다
- 발행 측: 블로그·카페 링크카드와 4채널 디스패처는 콘텐츠(편)별 utm_campaign을 이미 부착 — `scripts/naver_blog_upload_playwright.py:281~282`, `scripts/cafe_upload_playwright.py:274~275`, `scripts/publish_4channel_dispatcher.py:293` (slugify_campaign(콘텐츠 폴더)).
- 수집 측: GAS에 편별 클릭 집계 액션이 이미 라이브 — `.deploy-funnel/Survey.js:2287 campaign_stats`(콘텐츠별 클릭·PII 미노출, 983행 공개 면제). 문의 레코드에도 utmCampaign 칼럼이 기록됨(Survey.js:1701, 2026-07-03 하드귀속 개통분부터).
- 소비 측: `weekly_marketing_feedback.py`는 click_stats(byUtmSource)(298~308행)와 funnel_conversion(byChannel)(311~323행)만 호출 — campaign_stats 미소비, 편별 문의 집계 액션 부재. 즉 편별 채점 재료의 절반(클릭)은 이미 있는데 아무도 안 읽고, 나머지 절반(문의)은 기록만 되고 집계가 없다.
- 커버리지 구멍(정직): IG는 편별 UTM 없음(`scripts/cta_utm.py:9·16` — IG는 CTA카드 제외, bio 링크 담당), 카카오·당근은 UTM 부착 금지 원칙(cta_utm.py 49~60행, 2026-07-09 GM 재정립 — 텍스트 CTA는 깨끗한 도메인만). 편별 귀속 = 블로그·카페 링크카드 경유 클릭만.

### 진단 요약 (근본 원인)
> 선정 함수의 입력에 목표·성과가 존재하지 않고(1-1·1-2), 성과를 재는 대상(공식)과 만드는 대상(개인)이 분리돼 있으며(1-3·1-4), 편별 채점 재료는 절반만 배선된 채 소비자가 없다(1-5). 로드맵은 목표가 아니라 큐다 — 그래서 콘텐츠는 매일 나오지만 "이 편이 회원 획득에 기여했나"에 답할 데이터 경로가 루프 안에 없다.

## 3. 구체 배선 변경 (파일·함수 단위)

### 3-1. 공식 후보풀 로드맵 신설 — `instagram/_공식시리즈_로드맵.md` (새 파일 · 사유 명시)
- 새 파일 사유(기존수정 우선 원칙의 예외): `_AI시리즈_로드맵.md` 문서 규칙 6행이 "이 문서에 6열 이상 + 첫 셀 숫자인 다른 표 추가 금지(파서 오인)"를 명시 — 같은 파일에 공식 표를 넣으면 `parse_roadmap_episodes`(전 행 무차별 스캔, 151~188행)가 개인·공식 행을 섞어 선정한다. 물리 분리가 파서 안전상 유일한 방법.
- 구조 = 기존과 완전 동일 6열 표(# | 일자 | 폴더 | 제목 | 핵심메시지 | 상태) + producer-episode-card-{n} 펜스 — 파서 3종(`parse_roadmap_episodes`·`parse_episode_cards`·`parse_season_config`) 무수정 재사용.
- 편별 카드에 키 2개 추가(파서는 generic `KEY: 값`이라 무수정): `ANGLE: 강습수요-모자수영` 같은 각 태그, `GOAL_KPI: 문의(강습)` 같은 조준 KPI. `make_folder_slug`가 만드는 폴더명이 곧 utm_campaign 슬러그가 되므로 각→편→캠페인→클릭/문의가 한 줄로 이어진다.
- 초기 시드(각 역산의 첫 실행): 주간 실측이 가리키는 수요 — 강습 등록 상위(모자수영 26·아쿠아로빅 20, 브리프 20260706 §2)·문의 상위 채널(네이버 17건)·멤버십 상품(노블레스 12개월) — 에서 각 후보 8~12행을 시모가 작성, GM 승인 후 확정. F1~F3·방학특강 기존 발행분은 '발행완료' 행으로 소급 등재(편별 성과 추적 대상화).
- **★소급 등재 형식 검증 (Med-1):** `parse_roadmap_episodes`는 첫 셀이 정수 regex `^\s*(\d+)`(172~174행)에 안 걸리는 행을 **무경고 스킵**한다. F1식 편을 소급 등재할 때 # 셀엔 반드시 정수 편번호를 부여하고 폴더 셀엔 실제 폴더 슬러그(`260707_공식_시설_F1_운동`)를 넣는다(라벨 'F1'만 넣으면 가드 ③ 매칭 실패 — §3-3.7). 등재 후 `--plan-only` 파싱 편수 = 표 행수 대조로 스킵 0 검증, 등재 스크립트에 '행수 불일치 경고'를 넣는다.

### 3-2. `scripts/weekly_marketing_feedback.py` — 편별 채점 생산 (⑤ 확장)
1. `fetch_campaign_stats(date_from, date_to)` 신설: `GAS_URL?action=campaign_stats&from&to` 호출(298~308행 `fetch_click_stats`와 동일 패턴). GAS는 이미 라이브(Survey.js:2287) — 신규 GAS 배포 불필요, 소비만 추가.
2. §5 '각 스코어카드' 섹션 추가 (`build_brief` 487행~에 parts 추가): 편(캠페인)별 표 — 캠페인 슬러그 | 각(ANGLE) | 클릭(측정) | 문의(미측정→3-4 배선 후 측정) | 커버리지 꼬리표(블로그·카페만 귀속 / IG·카카오·당근 비귀속).
3. angle-scores 펜스 블록 출력: `KEY: 값` 한 줄씩(`캠페인슬러그: clicks=N inquiries=M coverage=partial`) — 로드맵 producer-season-config와 같은 '코드가 md 펜스 직독' 관례 재사용. 새 json SSOT 만들지 않음.
4. §3/§4 보존 로직(`apply_preserved_judgment` 674~727행)은 무변경 — §5는 자동 데이터이므로 매번 재생성.

### 3-3. `scripts/ig_series_producer.py` — 선정기의 목표 입력 개통 (①)
1. `pick_next_episode(episodes, scores=None)` 시그니처 확장 (383행):
   - scores=None 또는 플래그 OFF → 기존 번호순(406~407행) 그대로 = 역롤백 기본값.
   - `CMO_NORTHSTAR_STEER=on`(신규 env, `CMO_LOOP_FEEDBACK` 410~412행과 동일 판정 패턴) + scores 존재 → 후보 정렬키를 (-angle_score, num)으로 교체. 3중 가드(①②③)는 불변.
2. `read_latest_angle_scores()` 신설 (415행 `read_latest_marketing_proposal` 옆, 동일 glob·fail-soft 패턴): 최신 주간 브리프의 angle-scores 펜스를 dict로 파싱. 편↔점수 매칭 키 = 로드맵 ANGLE 카드 태그 또는 폴더 슬러그.
3. 호출 순서 수정 (main `run()` 929행): 점수 읽기를 `pick_next_episode` 앞으로 이동 — 현행 948~953행의 '선정 후 참고 출력' 구조가 1-2 진단의 원인이므로, `scores = read_latest_angle_scores() if steer_enabled else None; nxt = pick_next_episode(episodes, scores)` 로 재배선. 플래그 OFF 시 기존 경로와 100% 동일.

### 3-6. ★측정 발행 배선 — 편별 귀속의 실제 전제 (High-1, 가장 위험)
> **경보:** 편별 귀속의 유일 채널은 블로그·카페(§1-5)인데, **공식 편이 블로그·카페에 자동으로 실리는 배선이 지금 없다.** 이 사실을 무시하고 착수하면 스코어카드가 '측정' 라벨을 단 **빈 표**가 된다.

- **실측 근거:** `publish_4channel_dispatcher.py` 자동 호출부 0건(grep — 워크트리 사본 외 스케줄러·봇 호출 없음). 텔레그램 봇 `pub:` 콜백(`telegram_bot/bot.py:1591 cmd_publish_callback`, 핸들러 1940행)은 **IG 발행 트리거 전용** — 블로그·카페는 GM이 발행 후 URL을 텔레그램에 붙여넣으면 봇이 review_queue에 기록하는 **수동 경로**(bot.py:1393~1409 `_NAVER_BLOG_RE`/`_NAVER_CAFE_RE`). 오늘 F2 편도 GM이 블로그·카페를 **수동 발행**했다.
- **의존선 (측정이 발행에 의존):** 편별 스코어카드(측정 라벨) ← 편별 클릭=campaign_stats(블로그·카페 링크카드 클릭만) ← 링크카드=블로그·카페 발행 시에만 삽입(utm_campaign 부착) ← **블로그·카페 발행=현재 GM 수동, 자동 배선 없음(끊긴 고리)**. 즉 블로그·카페가 발행되지 않은 편은 편별 클릭이 구조적으로 0 — '측정'이 아니라 '데이터 없음'이다.
- **v1 정직 표기 규칙:** §5 스코어카드의 편별 클릭/문의는 **'수동발행된 편에 한함'** 꼬리표를 단다. 블로그·카페 발행 기록(review_queue의 해당 채널 status=발행완료)이 없는 편은 클릭 셀을 `0`이 아니라 **`미발행(측정 불가)`**으로 표기(0 위장 금지).
- **선행과제 연결:** 5채널 자동발행(**ship826 '5채널 자동발행 완결' — 현재 미해결**)이 본 루프의 **측정 전제 선행과제**다. ship826이 블로그·카페 자동발행을 완결해야 편별 측정 커버리지가 '수동발행 편'에서 '전 공식 편'으로 확대된다. v1은 ship826 완결 **전에도 착수 가능**하나(수동발행 편만 측정), 편별 채점의 통계적 유효성은 ship826 완결에 좌우된다.
- **GM 개입 정직 재계상:** 자율화가 낮추는 GM 개입 = ⑤확정·발효 go. 그러나 블로그·카페 **편별 수동발행**이라는 GM 개입이 측정 전제로 잔존한다 — 자율화 성공기준(GM 개입 감소) 계상 시 이 수동발행 횟수를 **개입에 포함**해 정직하게 센다(ship826 완결 전까지 편당 2회=블로그+카페 수동발행 잔존).
