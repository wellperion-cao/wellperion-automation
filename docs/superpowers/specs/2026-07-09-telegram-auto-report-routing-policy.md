# 전사 텔레그램 자동보고 라우팅 정책 (웰리 키스톤)

> **GM 결정 2026-07-09 (모바일 탭 승인):** 자동보고 3종은 **기존 방에 종류별로 분산 라우팅**. 리포트 전용 새 방 신설 안 함. 이 정책이 배747·754·781(각 C레벨 자율화 두뇌)의 공통 대기점(방 배정)을 해소한다.

## 정책
- 각 모듈의 자동보고(일/주/월)는 `status/module_registry.json`의 `bot_room`(또는 notify_spec) 키로 방을 지정하고, 키는 `status/telegram_rooms.json`에서 chat_id로 해소된다.
- `bot_room=null`이면 발송 스킵(현재 전부 off = 정상). **실제 "발송 ON"은 방 배정과 별개로 GM go 1회 필요**(외부 발신·라이브 활성 게이트).

## 권장 매핑 (GM 조정 가능)
| 리포트 | 소유 배 | 기존 방 | telegram_rooms 키 |
|---|---|---|---|
| 점검·업무 현황 | COO 781 | 점검관리방 | `점검관리방` (-5136037543) |
| 회원 현황 | CPO 754 | 문의알림방 | `문의알림방` (-5516675010) |
| 마케팅 성과 | CMO 747 | 종합접수처 | `종합접수처` (-5065206276) |

- 근거: 점검=점검방, 회원=문의 흐름 이후=문의방, 마케팅=기존 3방 중 catch-all=종합접수처.
- **대안:** 이미 존재하는 `자동화현황방`(-5498808140)으로 3종을 모을 수도 있음(더 깔끔·한 방). GM이 "종류별 분산"을 택해 위 표를 기본으로 하되, 자동화현황방 통합을 원하면 한 줄로 전환 가능.

## 남은 단계 (각 C레벨 세션에서·발송 ON만 GM go)
1. 각 C레벨이 본인 모듈의 `bot_room`을 위 표대로 세팅(자기 세션·자기 도메인 모듈만).
2. 발송 스케줄러 라이브 ON = **GM go 1회**(외부 발신 게이트). 그 전까지 드라이런/발송 스킵 유지.
3. 역롤백 = `bot_room`을 null로 되돌리면 즉시 발송 스킵.

## 계약 연동
- 스키마 정본 = `docs/superpowers/specs/2026-07-09-module-registry-contract.md`. `notify_spec`/`bot_room`은 이 계약을 따른다.
- 방 이름→chat_id 정본 = `status/telegram_rooms.json`. 값 복사 금지·이 키로 참조만(헌법 원리1).
