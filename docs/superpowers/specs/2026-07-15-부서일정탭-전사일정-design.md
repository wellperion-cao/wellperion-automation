# 부서 일정 탭 → 전사 일정 합류 (반복 일정 포함) — 설계

- 날짜: 2026-07-15
- 소유: 시우(COO) · GM 승인 완료(대화)
- 배: (G1 신규 COO 배)

## 1. 목적 (GM 아이디어)
각 부서 체계 페이지에 **일정 탭**을 두어 부서가 직접 주요 일정을 적으면, **전사 일정 뷰에서 한눈에** 모여 보이게 한다. 점검처럼 **매년/매주 반복되는 건은 규칙 한 줄로 고정**해두면 매번 다시 안 적어도 달력에 계속 뜬다.

## 2. 핵심 발견 — 인프라 이미 존재 (재활용)
`3. 웰페리온 가이드/coo/check/전사_일정.html` 이 이미 라이브:
- 월간 달력 + 임박순 리스트, 부서 `?dept=` 필터, 편집 모드(항목 추가·수정·클라우드 저장)
- 백엔드 = `scripts/schedule_ssot_gas.gs` (ScriptProperties 단일 JSON blob, **JSON 통째 저장** → 새 필드 자동 보존)
- seed 폴백 = `status/schedule_ssot.json`
- 현재 담긴 것 = **정기 안전·법정 점검만** (type=정기점검)

즉 그릇은 있고, ① 부서 탭 진입점과 ② 점검 외 일반 이벤트 + 반복 규칙이 비어 있음.

## 3. 확정 방향 (GM 결정)
- 일정 종류 = **주요 이벤트 중심** (행사·점검·납품·정기교육 등 굵직한 것; 잡다한 회의 제외)
- 작성 방식 = **탭 안에서 바로 편집**
- 방식 = **iframe 심기** (코드 1벌·저장 1곳 GAS·전사 즉시 반영). 대안 B(부서마다 위젯 복사)·C(링크만) 기각 — 약속 L01(한 곳만 본다).

## 4. 데이터 모델 확장 (`schedule_ssot.json` + GAS 통과)
기존 `정기점검` 항목과 **한 그릇 공존**. 신규 `type="이벤트"` 항목:

| 필드 | 뜻 | 필수 |
|---|---|---|
| `name` | 제목 | ✅ |
| `next_due` | 날짜(YYYY-MM-DD) = 이벤트 시작/기준일 | ✅ |
| `category` | 분류(행사·납품·교육·기타 또는 점검 분류) | |
| `dept` | 담당 부서 | ✅(탭에서 자동) |
| `assignee` | 담당자 | |
| `note` | 메모 | |
| `repeat` | **반복 규칙**: `""`(없음)·`weekly`·`biweekly`·`monthly`·`yearly` | |

- `types.이벤트 = {label:"주요 이벤트", desc:"부서 주요 일정(행사·납품·교육 등)"}` 추가.
- 신규 categories 추가: `event`(행사·모임)·`delivery`(납품·계약)·`general`(일반). `edu`(교육)·점검 분류는 재사용.
- **반복 = 규칙 1줄만 저장**, 달력 렌더 시 그 달의 해당 날짜로 전개(항목 폭증 없음).

## 5. `전사_일정.html` 변경
### 5-1. embed 모드 (`?embed=1`)
부서 탭 iframe용 군더더기 숨김: 운영흐름 nav·`.header-top`(편집버튼은 유지)·honesty 배너·footer·부서 칩 숨김. `?dept=X`로 부서 고정(cur=dept, "전체" 선택 불가). 남는 것 = 요약·달력·리스트·편집바.

### 5-2. 반복 전개 (달력·리스트)
- `occurrencesInMonth(item, y, m)` 신설: `repeat` 있으면 앵커(next_due) 기준 그 달의 모든 발생일 반환.
  - weekly/biweekly = 앵커에서 7·14일 스텝. monthly = 매달 같은 날. yearly = 같은 월·일.
  - `repeat` 없음(점검 포함) = 기존 `computeDue` 단일 날짜.
- `nextOccurrence(item)` 신설: 반복 항목의 다음 발생일(≥오늘)로 임박순 정렬·D-day 계산. 비반복=기존 로직.
- `calBuildMap()`·`renderList()`·`statusOf()`가 위 두 함수를 경유하도록 교체. **점검 경로 무변경 보장**(repeat 미설정 시 기존과 동일).

### 5-3. 편집 폼 분기
- `type==="이벤트"` 카드 = 간소 폼(제목·날짜·분류·담당·메모·**반복 셀렉트**). 점검 카드 = 기존 폼 유지.
- `➕ 항목 추가` = 드롭다운/버튼 2종("＋ 이벤트"·"＋ 정기점검") 또는 추가 후 type 토글. 기본 = 이벤트(부서용).

## 6. 부서 체계 페이지 5종 — `🗓️ 일정` 탭
`시설부·지원부·주차관리부·운영부·파트너팀 체계.html` 각각:
1. 탭 버튼 `<button class="tab" onclick="switchTab('schedule')">🗓️ 일정</button>` 추가(탭줄).
2. 탭 내용 `<div id="tab-schedule" class="hidden"><iframe ...></div>` — iframe src=`전사_일정.html?dept={부서}&embed=1`, height≈85vh 자체 스크롤, **lazy-load**(탭 첫 진입 시 src 주입).
3. `switchTab()`에 `document.getElementById('tab-schedule').classList.toggle('hidden',tab!=='schedule');` 한 줄 + 진입 시 iframe lazy set.

부서명 매핑: 파일명 부서 = `?dept` 값 그대로(시설부·지원부·주차관리부·운영부·파트너팀).

## 7. 범위·순서
- **Phase 1(시범):** 5-1~5-3(전사_일정.html) + `schedule_ssot.json` 확장 + **지원부** 1개 탭. 시크릿 크롬 실측.
- **Phase 2(확산):** 나머지 4부서 탭(동일 기계작업 · executor 위임). 실측 후 GM 1줄 보고.

## 8. 안전·정합
- 전부 **가역**(페이지 편집·seed JSON). 외부 전송·결제·보안 없음 → COO 자율 범위.
- GAS 재배포 불필요(저장 규약 무변경, 새 필드는 자동 통과). URL 교체 없음.
- 점검 기존 동작 회귀 0 = repeat 미설정 시 기존 코드 경로 그대로.
- 커밋·푸시 즉시(약속 L13). 라이브 검증 후에만 완료 도장(L03).
