# CONTACT (연락 이력) 일정형 격상 — 멤버십·강습 문의 회원관리

- **작성**: 2026-07-08 · 시포(CPO) · GM 브레인스토밍
- **대상 파일**: `3. 웰페리온 가이드/cpo/member/문의회원.html` (프론트) · `.deploy-funnel/Survey.js` (GAS) · 인사 GAS(NOTION_FN, 시로 조율)
- **원칙**: 기존 수정 우선(새 파일 최소) · 저장소=구글시트 유지 · 되돌리기 쉬운 단계 · PII 비노출

---

## 0. 배경 · 문제
- 강습 문의가 많은데 "**언제·무슨 내용으로 컨택했는지**"를 남길 곳이 없다. 현재 각 강습 팀이 팀별 구글시트로 따로 관리 → 체크 부재.
- 멤버십 CONTACT는 옛 3칸(C1·C2·C3) 고정이라 날짜가 강제되지 않고 3회 제한.
- 강습·멤버십 목록 로딩이 5~43초로 요동(GAS가 호출마다 전체 행 재조회, 서버 캐시 없음).

## 1. 목표 (한 줄)
멤버십·강습 문의의 CONTACT 칸을 **일정(예약)과 같은 모달형 "연락 이력"**(날짜+시간+상담내용, 무제한 추가)으로 격상하고, 첫 컨택 시 텔레그램 알림, 강습 담당자를 인사 명부 기반 드롭다운으로, 로딩을 캐시로 가볍게.

## 2. 스코프 (6개 축)

### 축1. 성능 — GAS 조회 캐시 (최우선·독립 배포 가능)
- `lesson_inquiry_list`·`member_inquiry_list`에 **CacheService 30~60초 캐시** 추가. type/scope별 키.
- 쓰기(`*_inquiry_update`) 성공 시 해당 캐시 무효화(다음 조회 최신 반영).
- 저장소=시트 그대로. gviz 직접읽기는 채택 안 함(원본 공개·PII, JWT 전 비권장).
- **효과**: 두 번째 조회부터 즉시. 역롤백=캐시 블록 제거 후 재배포.

### 축2. CONTACT (연락 이력) 데이터 모델
- 멤버십·강습 시트에 `연락이력`(JSON 리스트) 컬럼 **멱등 추가**.
  - 멤버십: `member_inquiry_*` 관리컬럼 로직에 추가.
  - 강습: `_LESSON_MGMT_COLS`에 `연락이력` 추가(기존 `상담메모` 컬럼은 강습 화면에서 CONTACT로 대체되나 시트 컬럼은 보존).
- 항목 스키마: `{ "date":"2026-01-08", "time":"14:00", "note":"가격·체험 안내, 등록 의사" }`
- 정렬: `date`+`time` 오름차순 저장, 표시 최신 우선.
- **멤버십 기존 C1·C2·C3 비파괴 흡수**: 읽기 시 `연락이력`이 비어 있고 C1/2/3에 값이 있으면 각 값을 `{date:"", time:"", note:C_n}` 항목으로 합성해 초기 이력으로 표시. 새 항목은 `연락이력`에 append. (C1·C2·C3 컬럼은 그대로 두어 원복 가능)
- 백엔드 read → `contacts` 배열 반환, update → `contacts` JSON 수신·저장.

### 축3. CONTACT 모달 UI (멤버십·강습 공통)
- 열 이름 = **`CONTACT (연락 이력)`**.
- 칸 표시 = 요약: `N건 · 최근 MM/DD`(0건이면 `＋ 연락 추가`). 강습 표에서 **CONTACT 열이 가장 넓게**.
- 칸 클릭 → **모달**(예약 모달 `openInquiryResModal` 패턴 재사용):
  - 이력 리스트(날짜·시간·상담내용) + `＋ 연락 추가` 버튼.
  - 각 항목: 날짜(달력 date picker) · 시간(06~22시 드롭다운, 예약모달 `buildScheduleEditBlock` 재사용) · 상담내용(textarea).
  - 수정·삭제 가능. 저장=`*_inquiry_update`(keyPhone 행키검증). IME 안전(입력 중 DOM 재생성 없음).
- 예약(일정)과 **별개 리스트**(예약=미래 약속 / 연락=과거 기록). 모달 UI 골격만 공유.

### 축4. 강습 회원관리 개편 (강습 전용 추가분)
- **메모 열 → CONTACT (연락 이력)** 로 교체(강습 lessonRender 컬럼 개편).
- **담당 편집 가능**(현재 강습 담당은 읽기전용) → 드롭다운. 옵션 = **종목별 재직 강사**(축5).
- **연락처 = 이름과 같은 흰색·같은 크기**(멤버십 패턴 미러, 현재 강습은 dim·작음).
- 진행상태 select(기존)·종목칩·최신순 정렬 유지.

### 축5. 담당자 드롭다운 — 인사 명부 연동 (시로 조율)
- 출처 = CHRO 임직원 명부(`강습부`, `재직 상태≠퇴사`, 소속=종목).
- **경량 이름-전용 통로**: 인사 GAS(NOTION_FN)에 읽기전용 액션(예 `lesson_instructors`) 추가 → `{ "수영":["홍길동"], "골프":[...], ... }` (PII 없음, 이름만).
- 강습 페이지가 이 통로를 불러와 종목별 담당 드롭다운 구성. 퇴사=자동 제외·신규=자동 반영.
- **종목 브릿지 매핑표**(문의 종목 → 명부 소속): 예 `P.T→헬스`, `WSC 체조→체조&트램폴린`, `수영→수영`, `골프→골프`, `필라테스→필라테스`, `발레→(명부 확인)`. 최종 매핑은 명부 실측 후 확정.
- 명부에 없는 종목·미매칭은 자유입력 fallback 유지(데이터 손실 방지).

### 축6. 텔레그램 알림
- **1차 컨택 알림(신규)**: `연락이력`이 **0→1건**으로 처음 기록되는 순간 → '문의 알림' 방:
  ```
  📞 1차 컨택 진행 — 홍길동 (성인 수영)
  일시: 1/8 14:00
  내용: 가격·체험 안내, 등록 의사 있음
  담당: ○○ 강사
  ```
  - 멤버십·강습 공통. 백엔드 `*_inquiry_update`에서 이력 카운트 전이 감지 시 1회 발송.
  - **기존 '상태=상담중' 컨택 알림과 정리**: 이력-기준(더 정확)으로 일원화, 상태-기준 컨택 알림은 중복 방지 위해 제거 또는 억제.
- **매일·주간 점검 현황 알림 반영**(GM 요청): 알림에 `연락 미기록 신규문의: N건` 한 줄. 판정=`연락이력` 0건. `daily_scheduler.py`(시토 배선 영역)라 시토 조율.

## 축7. 강습 종목별 독립 관리 (GM 2026-07-08 확정)
- **문제**: 한 강습 문의가 종목 여러 개면(예 P.T+수영+스쿼시), 종목마다 담당 팀·진행이 다름. 지금은 문의 1행에 진행상태·담당·연락이력이 각 1개뿐.
- **결정**: 종목별로 **분리 리스트업** + 각 종목 줄이 **독립**(자기 진행상태·담당·CONTACT). "많아져도 이게 맞다"(GM).
- **데이터 모델(백엔드)**: 강습 시트에 `종목별관리`(JSON) 컬럼 추가 = `{ "<sportKey>": {status, owner, contacts:[...]}, ... }`. 멱등 생성.
  - `lesson_inquiry_list`: 행마다 `bySport`(파싱맵) 반환. **비파괴 폴백**: 특정 sportKey에 항목 없으면 기존 단일 `진행상태/관리담당/연락이력`을 그 종목 값으로 표시(편집 시 `종목별관리[sport]`에 기록). 기존 단일 컬럼 삭제·덮어쓰기 금지.
  - `lesson_inquiry_update`: `(rowIndex, sport, {status|owner|contacts})` 수신 → `종목별관리[sport]` 갱신. keyPhone 행키 유지. 1차 컨택 알림=해당 종목 연락이력 0→1.
- **분리 로직 = 프론트에서만**(백엔드/ gviz는 행당 sport문자열+bySport 반환, 프론트가 종목 분해해 N줄 렌더). gviz 어댑터(`gvizLessonRows_`)도 `종목별관리` 필드 읽게 동기(백엔드와 짝).
- **진행상태 4종**: `컨택중 / 가망 / SUC / LOSS` (기존 5종 교체). SUC=등록(레지스트리 upsert 연동), LOSS=이탈.
- **담당 드롭다운**: 종목별 명단 + "담당자 X"(미배정). 종목→명단키 브릿지 매핑(수영·아쿠아/P.T/필라테스/골프/스쿼시/체조&트램폴린/뮤지컬팀/웰니스). 미매칭 종목=담당자 X만 + 정직표기.
  - ※명단 정본 위치 변경(2026-07-27 시포): `status/lesson_instructor_roster.json` → **`membership.html` 의 `LESSON_INSTRUCTOR_ROSTER` 블록 한 곳**. 페이지가 JSON을 '복사'해 두던 구조가 실제로 어긋나(김광수·김태훈 누락) 실무진 피드백으로 드러났고, 읽는 코드가 없던 JSON 쪽을 삭제했다(약속 L01·L21).
- **순서**: 대시보드 배(문의회원.html 편집 중) 완료 후, 백엔드(Survey.js)+gviz 어댑터+프론트(lessonRender 분리·4종·담당)를 **한 조율 작업**으로. gviz 캐시버스터도 같은 패스에 추가.
