## 2. 항목별 판정

### A. 영문 Survey 폼 자체화 + 한영 일관 + 같은 시트 — **가능(조건부)**

**근거:** 자체폼이 이미 `?type=` 구동 데이터드리븐 단일파일이라, 영문판은 **FORMS 오브젝트에 영문 라벨/옵션만 추가**하면 렌더 엔진·GAS 전송·스팸방어를 그대로 상속. 주입 파이프라인도 존재(post_id 8408, `--mode draft-inquiry-en`).

**선결(정직히):**
1. 백엔드 `intake_submit`에 **영문 category 저장 라우팅** 배선(현재 영문 미허용).
2. **유형 범위 결정** — 영문 현재 3종 → 6종 전체 복제할지 3종만 할지 **GM 확정**.
3. 발효 = 비가역 유입경로 변경 → 기존 구글폼은 **롤백 자산으로 보존**.

**난이도:** 중 (프론트 영문 변형 + 백엔드 라우팅). **위험:** 발효 후 구글폼↔자체폼 이중수집 혼선 → 컷오버 시점 명확히.

**같은 시트 안:** 영문 응답을 별도 외국인 시트가 아니라 **한글과 같은 탭**(`'26년 신규문의'`/강습 응답탭)에 쌓되, `유입언어`(KO/EN) 컬럼 1개로 구분. → D에서 상술.

### B. ERP 새 문의 카드 유입경로 셋팅 — **가능**

**B-1. 알게된 경로(고객 자기응답) — 값목록 확정(실측):**
프론트 `CHANNELS`(wp_inquiry_form.html:319) 10값 그대로 SSOT:
```
네이버 검색·플레이스 / 네이버 블로그 / 인스타그램 / 당근마켓 /
동부이촌동 커뮤니티 / 카카오톡 / 소개·지인 / 기존·과거 회원 /
오프라인(간판·방문) / 기타
```
멤버십=라벨 '알게 된 경로', 강습=라벨 '문의 경로'(같은 key `channel`). 백엔드 표준 10버킷 `CANONICAL_CHANNELS`(Survey.js:215).

**B-2. 자동 유입경로(링크추적) — 부분 존재 + 버그:**
- 프론트 캡처: `utm_source`·`utm_medium`·`utm_content`(wp_inquiry_form.html:469–475). **`document.referrer`·`stage_funnel`은 미캡처**.
- 백엔드 저장: 멤버십은 `'유입경로(자동)'` 컬럼에 `utmSource|utmMedium` 기록(Survey.js:2807).
- ★ **버그(수정 대상):** 프론트가 `utmContent`를 보내지만 `intake_submit`이 **읽지 않아 유실**(Survey.js:2775–2776, source/medium만). IG 계정 구분(official/namuk)용 utm_content가 저장 단계에서 사라짐.
- 강습은 UTM 전용 컬럼 없이 utmSource가 '문의 경로'에 폴백 병합.

**B-3. ERP 노출 분리(핵심 설계):**
- **ERP 문의 카드/화면 = '알게된 경로'(자기응답)만 노출.** 고객이 스스로 고른 신뢰 높은 값.
- **UTM(자동추적) = 시트/백단 기록 전용.** 마케팅 귀속 분석용(대시보드 M1), 상담원 화면에는 안 띄움.
- 구현: membership.html 문의 그리드/모달은 `channel` 컬럼만 바인딩, `유입경로(자동)`/`utm_*` 컬럼은 렌더 제외(읽기 O, 표시 X).

**난이도:** 하~중 (버그수정 소, 분리 노출은 UI 바인딩 규칙).

### C. 휴회 — **가능 · 경량안 권장**

**무거운 안 (비권장):**
- 별도 '휴회 관리 시스템'(신규 시트 + 신규 페이지 + 상태전이 이력 테이블 + 별도 GAS 액션군). 회원 상태를 enum('유효/휴회/만료')로 정식 도입하고 전이 로그를 별도 관리.
- 공수: 상. 위험: 회원 상태 SSOT가 잔여일 파생인데 별도 enum을 얹으면 **이중 진실**(잔여일 vs 상태 라벨) 사고. 규칙(JS/GAS) 이중화 위험(약속 L01).

**경량 안 (★권장):**
- **데이터:** `유효회원` 탭에 컬럼 4개만 추가 — `휴회횟수`(3회 검증), `휴회누적일수`(총60일), `휴회시작일`, `휴회종료일`.
- **자동계산:** 휴회 종료 시 `종료일자`에 휴회일수 가산 → `잔여일`이 종료일자 파생이라 **자동 반영**(별도 계산기 불필요). (추정: 잔여일 산출식 원본은 서버 `member_active_list`에 있어 미확인 — 배선 시 확인 필요.)
- **검증(3회/총60일/최소7~최대60일):** **서버 GAS `member_active_update` 액션 단일 SSOT**에 검증 1블록. 클라(membership.html)는 **표시·미러링만**(약속 L01 준수 — 규칙 두 곳 두면 사고).
- **UI:** membership.html 재등록 상담 모달 계열에 '휴회 신청' 폼 1개 + `_remainColorInfo`(membership.html:5711)에 '휴회중' 상태색 1개. 별도 페이지 신설 불필요(원하면 얇은 접수폼만).

**추천:** **경량안.** "무거워질까"라는 GM 우려에 정확히 부합 — 신규 시스템 0, 기존 회원DB 필드 4개 + GAS 검증 1블록 + UI 폼 1개.
**공수:** 중(서버 검증 로직 + 시트 컬럼 + UI 폼). 무거운안 대비 1/3.

### D. 시트 통합 + 유입경로 자동기록 — **가능**

**D-1. 외국인 시트 통합:**
- 방식: 영문 자체폼(A)이 **같은 GAS `intake_submit`을 호출**하되 payload에 `lang:'en'` 추가. 백엔드는 영문 category를 **한글과 같은 탭**(`'26년 신규문의'`/강습 응답탭)에 append + `유입언어` 컬럼(KO/EN)로 구분.
- 대안(더 안전한 1단계): 기존 영문 구글폼 응답탭을 그대로 두고 **읽기 병합만 유지**(현행 `_collectFormInquiries_`)하다가, 자체폼 컷오버 후 쓰기까지 통합. → 로드맵 단계화.

**D-2. 유입경로 자동기록 배선:**
- utm_source/medium은 이미 기록. **utm_content 유실 버그 수정**(intake_submit이 utmContent 읽어 `'유입경로(자동)'`에 함께 기록).
- (옵션) `document.referrer` 캡처 추가 → `유입 referrer` 컬럼. stage_funnel 연동은 후속.

**D-3. ★함정 회피(메모리 실측 반영) — 통합 설계가 반드시 지킬 것:**
1. **쓰기/읽기 칸 불일치**(`reference_inquiry_sheet_write_read_column_mismatch`): 웹접수 A열 쓰기 vs 화면 B열 읽기(헤더 스캔 순서차이). → 신규 컬럼은 **헤더 이름 기반**으로만 접근, 위치 하드코딩 금지. 특히 `_findCol_`은 **부분일치 폴백**이 오탐 위험(Survey.js:75–83) → 신규 컬럼명은 기존 헤더와 부분일치 충돌 없게 유니크하게(예 '유입언어'가 '유입경로'와 부분일치 안 나게 `_findColExact_` 사용).
2. **행번호 삭제 레이스**(`reference_row_index_delete_race`, INC 07-20 실고객 오삭제): A열/행 인덱스 삭제 금지, 대조키(휴대폰) 필수, 쓰기 직렬화.
3. **이름칸 순서 함정**(`reference_inquiry_sheet_name_col_trap`): '성함' 순서 필수.
- **결론: 통합은 새 시트를 만들지 않고 기존 탭에 컬럼만 추가**하는 방향이 위 함정을 가장 적게 밟는다.

**난이도:** 중~상 (라우팅 + 버그수정 + 함정 회피 검증).

### E. 강습(성인/유소년) 폼 일관 — **가능(대부분 완성)**

- 강습 문의는 **이미 동일 Survey.js `intake_submit`** 처리(별도 엔드포인트 아님). 한글 강습 자체폼도 이미 라이브.
- 남은 것 = **영문 강습만 구글폼** → A(영문 자체화)에 포함하면 자동 해결.
- 옵션: 영문 강습을 6종 전체 복제 범위에 넣을지(A의 유형범위 결정과 동일 GM 포인트).

## 4. 유입경로 2종 셋팅 초안

### 4-1. 알게된 경로 (고객 자기응답 · ERP 노출)
드롭다운 SSOT(현행 10값 유지):
`네이버 검색·플레이스 / 네이버 블로그 / 인스타그램 / 당근마켓 / 동부이촌동 커뮤니티 / 카카오톡 / 소개·지인 / 기존·과거 회원 / 오프라인(간판·방문) / 기타`
- 영문 폼: 동일 10값 영문 라벨(How Did You Hear) → 저장 시 한글 표준 버킷(`CANONICAL_CHANNELS`)으로 정규화.

### 4-2. 자동 유입경로 (링크추적 UTM · 백단 전용)
표준 파라미터 규약:
```
utm_source   = naver | instagram | danggn | blog | cafe | kakao | direct ...
utm_medium   = organic | paid | social | referral | qr | link ...
utm_content  = official | namuk | <콘텐츠ID>   ← IG 계정 구분(현재 유실 버그)
utm_campaign = <캠페인명>                      ← (옵션 추가)
referrer     = document.referrer               ← (옵션 추가, 현재 미캡처)
```
- 저장: `유입경로(자동)` 컬럼에 `source|medium|content` 기록(현행 source|medium → **content 추가로 버그 수정**).
- 노출 규칙: **ERP 상담 화면 비노출**, 마케팅 대시보드(M1)·귀속 분석에서만 소비.

## 5. 휴회 경량안 vs 무거운안 비교

## 6. 단계별 구현 로드맵 (의존순서)

| 단계 | 작업 | 의존 | 공수 | 발효 |
|---|---|---|---|---|
| **0** | (즉시 가능) **utm_content 유실 버그 수정** — intake_submit이 utmContent 읽어 `유입경로(자동)`에 기록 | 없음 | 소 | 코드만(자체폼 유입, 저위험) |

**핵심 묶음 = 2+3+E**: 영문 자체화·시트통합·강습 일관이 한 배선으로 해결.

## 7. GM 결정 필요 포인트

1. **영문 유형 범위:** 영문 폼 현재 3종 → (a) 3종만 우선 통일 / (b) 6종 전체 복제. → 추천 (a) 우선, summer/rental/business 영문판은 2단계.
2. **컷오버 방식:** 영문 구글폼 → 자체폼 전환 시 (a) 즉시 전환 / (b) 병행 후 컷오버. → 추천 (b), 구글폼은 롤백 자산 보존.
3. **휴회 안:** 경량안(추천) vs 무거운안 확정.
4. **휴회 페이지:** 별도 접수 페이지 신설 여부(경량안은 membership.html 내 폼으로 충분).
5. **UTM referrer/stage_funnel 캡처 추가 여부**(후속 단계로 미뤄도 됨).
