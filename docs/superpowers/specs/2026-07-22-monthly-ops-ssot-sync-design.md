# 월간운영계획 내부내용 자동반영 구조 — 설계안 (배9678 · COO-2026-07-22-MONTHLY-OPS-SSOT-SYNC)

> 담당 시우(COO) · GM 지시 2026-07-22 · 시우64 입항 후속
> 정본 데이터=`status/monthly_ops_plan.json` · 페이지=`3. 웰페리온 가이드/월간운영계획.html`(렌더만)
> 상태: **설계안(라이브 변경 0) · GM 접근 승인 대기**

## 1. 문제 (실측)
- 월간계획 알맹이(objectives의 `progress`·`status`)는 **수동 PIN 편집** → 정본 파일 **2026-07-14 이후 8일 미갱신(정체)**.
- **매출·ERP%만 자동**(home_kpi GAS 실시간). 나머지 운영 목표·진척은 사람이 손 안 대면 멈춤.
- 근본원인: **objective ↔ '그 일이 실제 기록되는 곳(업무·실무 SSOT)' 사이 링크가 없음.** 그래서 자동으로 돌 수가 없다.

## 2. 목표 (GM 핵심 포인트)
- 각 월별 objective의 진척/상태가 **업무·실무 SSOT에서 자동으로 당겨져 갱신**되고 **계속 돌아간다.** 소스 없는 것만 수동 유지.
- **시우(COO) = 페이지 '진실 검수'만** (내부 채우기는 준용M). 값 조작 금지·정직 배지.

## 3. 소스 4종 — objective가 무엇을 가리키나
| source | 실체 | 무엇을 반영 | 상태 |
|---|---|---|---|
| `metric_live` | home_kpi GAS | 매출·ERP% 등 지표 | ✅ 이미 라이브 |
| `queue` | `status/_queue.json` 배 | AI C-Level 자동화 배 status/priority | 신규 배선 |
| `todo_ssot` | 업무현황 SSOT(GAS `todo_list`) 실무 항목 | 준용M·실무진 4부서 업무 상태 | 신규 배선 |
| `manual` | (없음) | 소스 못 붙는 목표 = **수동 유지 + '✋수동' 정직 배지** | 현행 보존 |

## 4. 스키마 추가 (비파괴·additive) — objective에 `sync` 블록
```jsonc
"sync": {
  "source": "queue",                 // queue | todo_ssot | metric_live | manual
  "ref": ["CTO-2026-...-...", 9678],  // 연결된 배 task_id/ship_no 또는 todo 항목 id
  "rule": "avg_progress",             // status_map | avg_progress | count_done
  "last_auto": "2026-07-22T21:00",    // 엔진이 마지막 자동 갱신한 시각
  "auto_value": 57                    // 엔진이 계산한 실값(감사용)
}
```
- **rule 정의:** `status_map`(배 DONE→100 / IN_PROGRESS→진행값 / PENDING→0) · `avg_progress`(연결 배들 progress 평균) · `count_done`(N개 중 M개 완료 %).
- `source: "manual"` → 엔진이 **손 안 댐**(현행 값 그대로 보존).
- 기존 필드(progress·status·progress_note) **그대로 유지** — sync는 그 위에 얹는 추가 블록(회귀 0).

## 5. 엔진 — `scripts/monthly_ops_sync.py` (신규·결정론·LLM 불필요)
1. `monthly_ops_plan.json` 로드 → 당월 objectives 순회.
2. 각 objective `sync` 읽음 → 소스에서 실값 계산.
3. `progress`/`status` 갱신 + `progress_note`에 '(자동·소스명)' 꼬리표 + `last_auto`·`auto_value` 기록.
4. JSON 저장 → **커밋(워처가 푸시)**. 페이지는 GitHub Pages로 자동 반영.
- **정직(L05):** 소스 없음/조회 실패 = **값 안 건드림 + '⚠️자동 미연동' 표기.** 가짜 % 절대 금지.
- **게이트:** `MONTHLY_SYNC_APPLY` 기본 **OFF**(드라이런만) → 검증 후 GM go로 ON. 역롤백 1줄.
- **예약:** 매일 1회(또는 월말 카드 발송 직전) — 기존 월간 카드 예약에 편승(새 예약작업 최소화).

## 6. 시우 검수 층 (페이지 배지)
- 각 목표에 배지: **🔄 자동(소스명)** / **✋ 수동** / **⚠️ 자동실패**.
- 상단에 **'마지막 자동갱신 YYYY-MM-DD HH:MM'** 한 줄.
- 시우 일일 검수 = 자동값이 실제와 맞나 **시크릿 크롬 확인** → 어긋나면 `sync.ref` 배선 수정(값 자체 조작 아님·L03).

## 7. 준용M 단일 입력 원칙 (이중입력 제거)
- 준용M는 4부서 실무를 **업무현황 SSOT 한 곳**에만 기록 → 월간계획이 그걸 렌더.
- 월간 objective ↔ 업무현황 SSOT 항목 **매핑표**(초기 1회 시우가 배선).

## 8. 롤아웃 (단계별·각 단계 역롤백)
| 단계 | 내용 | 라이브 영향 | 역롤백 |
|---|---|---|---|
| 1 | 스키마 `sync` 블록 추가 + 엔진 드라이런 | **0**(값 무변경) | 블록 삭제 |
| 2 | objective별 소스 배선(시우 1회, 자동가능분부터) | 0 | ref 비움 |
| 3 | 게이트 ON(자동갱신 발효) + 페이지 배지 라이브 | 자동 갱신 시작 | 게이트 1줄 |
| 4 | 준용M 단일입력 전환 | 운영 규율 | — |

## 9. 정직 한계 (지어내기 금지)
- 물리 실무(테라스 리뉴얼·채용 등)는 **준용M가 SSOT에 입력해야만 자동 반영됨.** 입력 안 하면 여전히 수동.
- 즉 '자동'의 전제 = **실무가 machine-readable한 곳에 기록되는 습관.** 이건 코드로 강제 못 함 → 운영 규율(준용M 단일입력)로 보완.
- 이 한계를 숨기지 않고 페이지 배지(✋수동/⚠️미연동)로 **정직하게 노출**하는 게 이 설계의 핵심 안전장치.
