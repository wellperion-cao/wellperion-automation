# 예약 오지목 근본 수리 — 안정 고유키(rowKey) 설계

**작성:** 2026-07-22 시포 · **트리거:** GM 사고 보고(윤은혜→심수지 22일 예약 오지목, 손은숙↔김윤지1, Susan·익명여). **GM 지시:** 봉합→근본 둘 다 + 시포 대조키 복구. **연관:** INC-013, membership.html:2759.

## 1. 근본 원인 (확정)
회원 행을 지목하는 **안정적 고유 키가 없다.** 쓰기 대상 행을 ①위치(rowIndex) ②전화번호로만 찾는다. 이름은 키가 아님("익명여"만 20행+).

**가드(Survey.js:2992-3003)의 구멍 3개 — 실측:**
1. **keyPhone 빈값 → 가드 통째 스킵**(`String(body.keyPhone)!==''`) → 압축·밀린 rowIndex를 물리행으로 그대로 씀 → 엉뚱한 회원.
2. **중복 전화 첫매칭**(`_findRowByPhone_` Survey.js:108) → 같은 번호 2행 중 엉뚱한 쪽에 기록. 실측 7쌍(…5742 익명여 등).
3. **강습 신규문의 맨위 삽입**(intake_submit `insertRowAfter(1)` Survey.js:2731) → 기존 강습행 전부 +1 밀림 → 캐시 rowIndex가 인접 회원 지목(손은숙↔김윤지1 유형). 멤버십은 appendRow(2700)라 무해.

## 2. 실측 오염 현황 (2026-07-22, gviz 읽기전용)
- 멤버십 시트(631행): 이탈(LOSS)인데 예약목록 보유 = **1건**(심수지 phys600, 날짜없는 메모"체험/웰컴패키지 준비하고 문자발송하기"). Susan(phys632) 예약목록 비어있음.
- 중복 전화 7쌍: …1477(이주희/최민서) …1027(김정연×2 재문의) …0988(심우섭/심재엽 가족) …9601(강예진/익명수영문의) …9137(강민희×2) …7735(한혜수×2) …5742(익명여×2).

- ★강습(6팀시트) 측은 별도 스캔 필요(insertRowAfter 밀림 위험 높음).

## 3. 봉합(fail-closed) — 임시 안전망, 새 오염 즉시 0
대상: `.deploy-funnel/Survey.js` + `.deploy-funnel-v2/Survey.js`(동기 필수). 액션: member_inquiry_update·member_active_update·lesson_inquiry_update.

- **B1 keyPhone 빈값 fail-closed:** 예약(body.reservations 등) 쓰기인데 keyPhone 없거나 대상행 전화와 대조 불가 → **저장 거부**(`error:'row-key-unverified'`, 화면 경고). raw rowIndex 맹목 쓰기 금지.
- **B2 중복 전화 거부:** `_findRowByPhone_`가 2건+ 매칭 → 첫매칭 금지, **거부**(`error:'duplicate-phone-ambiguous'`, "동일 번호 여러 건 — 새로고침/담당 확인"). 신규 헬퍼 `_countRowsByPhone_` 또는 반환 확장.
- **B3 프론트 표면화:** membership.html apiPost/WriteBuffer가 위 거부를 **낙관 성공으로 삼키지 말 것** — park+경고+텔레그램(기존 실패경로 재사용). no-cors 은폐 금지(INC-013).
- **정직 트레이드오프:** 전화 빈값·중복 회원은 예약 저장이 일시 막힘(rowKey 완성 전까지). 오염보다 안전.

## 4. 근본(지문키) — 영구 해결 · ★칸 추가 0 (GM 확정 2026-07-22)
GM 결정: **새 칸을 만들지 않는다.** 기존 값 조합을 자연키(지문)로 쓴다.
- **키 정의 = 타임스탬프 + 연락처 조합**(둘 다 정규화: 숫자만 추출). 실측 검증(멤버십 631행, 2026-07-22): 타임스탬프 빈값 0 · 타임스탬프만은 10행 중복(옛 00:00:00 일괄등록) · **[타임스탬프+연락처] 조합은 631행 전원 유일(충돌 0)**. 연락처만 빈 8행도 조합은 유일. → 새 칸 불필요.
- **왜 조합:** 타임스탬프=불변(접수시각, 편집 안 함) → 강한 축. 연락처=타임스탬프 중복 시 구분. 연락처 편집 가능성은 로드시 키 재취득으로 흡수.
- **R1 읽기:** gviz·GAS 목록이 각 행에 `rowKey`(=정규화 타임스탬프+연락처) 실어 반환. 프론트 보관.
- **R2 쓰기:** 모든 update가 **rowKey 정확일치로 물리행 탐색**(`_findRowByKey_`, 타임스탬프칸+전화칸 동시 대조). 매칭 1건=진행 / 0건 or 2건+=거부(fail-closed).
- **R3 강등:** rowIndex·keyPhone 단독은 폴백 계층으로. 확산 후 제거.
- **효과:** §1 구멍 3개(압축·밀림·빈값/중복전화) 전부 무효. 정렬·삭제·삽입·동명이인·빈전화 전부 내성. B1 봉합의 '빈전화 8행 저장차단' 제약도 해소(타임스탬프가 키). 9월 자체DB PK로 그대로 승계(배18/101).
- **회귀 안전:** rowKey 미동봉(구클라) 요청은 기존 keyPhone 경로 폴백(점진 전환).
- **강습:** 6팀시트도 동일 원리(타임스탬프+연락처). 팀시트 헤더 실측 후 칸 위치 확인.

2. **전수 특정(읽기전용):** 이탈+예약 보유·중복전화 교차·최근 변경 예약목록 → [물리행|회원|현재예약|의심근거|추정원주인] 표.
