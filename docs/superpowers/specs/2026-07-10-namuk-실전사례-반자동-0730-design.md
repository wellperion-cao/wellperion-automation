### producer 편입이 아니라 별도 스크립트인 이유 (net-zero 판단)
- `ig_series_producer.py`(1,056줄)의 몸통 = **헤드리스 claude(시모) 창작 호출**(build_producer_prompt·invoke_simo_producer·주제이탈검사·로드맵 §5/§5.1 파싱). 실전사례는 **창작 호출이 0이어야 하는 트랙**이라, 편입하면 "AI 생성 금지" 가드를 창작 전용 코드 경로 안에 끼워 넣는 꼴 — 안전 원칙이 코드로 분리되지 않는다.
- 대신 **부품 재사용은 최대**: `publish_register.register_publish`(등록·미리보기·montage 발송), `send_review_card.py`(카드·dedup), `render_hand_slides.py`(렌더), producer의 소진 가드·텔레그램·마킹 **패턴**을 그대로 옮긴다. 신규 = 오케스트레이션 1파일뿐.
- **예약작업은 신설하지 않는다.** 기존 `ig/start_ig_series_producer.bat` 끝에 dispatcher 호출 1블록 추가 → 07:30 작업 1개 유지(producer는 로드맵에 '기획예정'이 다시 생기면 그대로 살아나는 공존 — 상호 간섭 없음). 일회성 `Wellperion-EP01-ReviewCard` 작업은 삭제.

## 2. 대본 재고 구조 — `_실전사례_2주플랜.md` 편별 재고 표 (단일 SSOT)

새 파일을 만들지 않고 기존 편성 SSOT에 표를 추가한다(기존수정 기본 원칙). 로드맵 §5 표 파싱 패턴(6열 마크다운 표 + 상태 완전일치)을 그대로 계승 — 검증된 방식.

```markdown
## 재고 (대본 발행 대기 큐 — case_series_dispatch.py 파싱 표 · 헤더/열 구조 변경 금지)
| 편 | 트랙 | 제목 | 폴더 | 상태 |
|---|---|---|---|---|
| 04 | 평일 | (사례2) 점검 원클릭… | instagram/namuk.wellperion/2607XX_실전사례04_점검원클릭 | 대본대기 |
| 05 | 평일 | … | … | 재고(대본완료) |
| … | | | | |
```

- **상태 수명주기(완전일치 문자열):** `대본대기`(폴더/대본 미완 — 선정 제외) → `재고(대본완료)`(시모가 대본·캡션 완성 후 직접 마킹 — **이 상태만 발송 후보**) → `검수발송(YYYY-MM-DD)`(dispatcher 자동 마킹) → `발행완료(YYYY-MM-DD)`(발행 대조 후 — 기존 웰리 대조 리듬, 수동/후속 자동화 무관). 보류는 `보류(사유)`.
- **선정 규칙:** `재고(대본완료)` 중 편 번호 최소 1건. 로드맵 producer의 3중 가드 계승: ①상태 완전일치 ②같은 queue_id가 review_queue에 이미 검수대기/발행완료로 존재하면 스킵(재발송 사고 차단 — send_review_card dedup과 이중) ③표 마킹 실패 시 텔레그램 경고(다음날 중복 위험 고지).
- **대본 폴더 규약(01~03 실측 관례 유지):** `instagram/namuk.wellperion/{제작일YYMMDD}_실전사례{NN}_{슬러그}/` 안에 `ep{NN}_diary_source.html`(pad 6장) + `caption.md`. output/은 시모가 미리 렌더해 둬도 되고(그대로 재사용) 안 해도 됨(07:30에 자동 렌더).
- **queue_id 규약:** `CMO-{발송일 YYYY-MM-DD}-CASE{NN}-{슬러그}` (01~03 동일 패턴 계승).

## 3. 07:30 자동 발송 상세 (case_series_dispatch.py)

1. **요일 게이트:** 월~금만 진행. 토·일은 `트랙=주말GM` 행이 재고에 있으면 동일 로직 소비, 없으면 **조용히 종료**(§5 주말 훅 — 알림 스팸 금지).
2. **선정:** §2 규칙. 0건이면 §4 정직 가드로.
3. **렌더(재사용 우선):** 폴더 `output/post_1..6.jpg` + `_검수_미리보기_6장.png` **6장 전부 존재하면 렌더 생략**(시모 사전 렌더 재사용 — 시각 확인까지 마친 산출물 존중). 하나라도 없으면 `render_hand_slides.py --diary-html {대본} --out-dir {폴더}/output --prefix post` 서브프로세스 호출, exit≠0 → 불량 처리(등록 금지 + 경고).
4. **등록:** `publish_register.register_publish(content_folder, slug, montage=_검수_미리보기, caption=caption.md 본문, location="웰페리온 스포츠클럽", mentions=[], account="namuk.wellperion", slides=post_1..6, queue_id, title="실전사례 {NN} — {제목}(개인계정)", channel="인스타그램 (namuk.wellperion)")` — status='검수대기' upsert + montage 텔레그램 사진까지 기존 함수가 수행.
5. **검수카드:** `send_review_card.py --id {queue_id}` 서브프로세스(버튼 카드 = 유일한 무폴링 발행 트리거). 실패 시 producer 동일 관례: 등록은 유지 + "수동 발송: send_review_card.py --id …" 경고.
6. **마킹:** 재고표 해당 행 상태 → `검수발송(YYYY-MM-DD)`. 실패해도 죽지 않고 경고만(등록·카드는 이미 완료).
7. **발행·대조:** 변경 0 — GM [✅승인] 탭 → bot pub: → watcher --once → 발행 → 웰리 대조. **스케줄 발행 없음 불변.**
