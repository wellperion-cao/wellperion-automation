### 과거 시도가 왜 실패했나
`TOKEN_ENFORCE`라는 스위치는 **"열쇠 없으면 전부 거절"** 방식입니다. 그런데 회원 정보를 돌려주는 액션 8종은 **처음부터 '면제' 목록에 올라 있어서** 이 스위치의 영향을 안 받습니다. 결과적으로 스위치를 켜면 **보호는 0인데, 면제 목록에 없는 다른 기능들이 열쇠가 없어 거절**됩니다. 그래서 "잠갔더니 페이지가 통째로 막혔다" → 롤백. **효과는 없고 부작용만 있는 스위치였습니다.**

| **P0** | GM이 열쇠값 결정((가) `1200` / (나) 새 값). ScriptProperties `ACCESS_TOKEN` 설정. `PII_MASK`는 **설정 안 함** | **0** (스위치 OFF) | `pii_status` 액션으로 토큰 설정됨·`PII_MASK` 미설정 확인 |
| **P1** | 마스킹 배선 코드 배포 (`:3171` 외 4개 액션). `PII_MASK` OFF이므로 `_piiFull_`은 항상 `true` 반환 | **0** (동작 동일) | `membership.html`·`renewal.html`·메인 허브 3곳 정상 렌더 + 목록 건수 P1 전후 동일 확인 |
| **P2** | (나) 선택 시에만: 커튼 비번을 새 값으로 교체 + 실무진 공지 | 비번 변경 | 실무진 전원 입장 성공 확인 |
| **P3** | `PII_MASK='on'` — **여기서 처음 실제 변화** | 열쇠 없는 조회만 마스킹 | ① 비번 입력한 직원 화면 = 전체 표시 ② 시크릿 창(열쇠 없음) = `김**` ③ **1영업일 무이슈** |
| **P4** | (선택) VOC `TOKEN_ENFORCE=1` — VOC는 면제목록이 이미 정상이라 거절이 실제 보호가 됨. **단 `종합접수처_현황.html`이 열쇠를 붙이는지 선확인 필수** | VOC 조회 거절 가능 | 접수처 페이지 정상 + COO 확인 |
| **P5** | 9월 서버 도입 시 D(JWT)로 교체. 스냅샷 통로 동시 해결 | — | 배 101·18과 동시 |

**P3에서 멈춰도 됩니다.** P4는 별개 판단입니다.

### 2-4. 롤백 방법

| 단계 | 롤백 | 소요 | 재배포 |
|---|---|---|---|
| P0 | `ACCESS_TOKEN` 속성 삭제 | 1초 | 불필요 |
| P1 | 없어도 됨 (동작 변화 0). 굳이 되돌리려면 이전 버전 재배포 | 수 분 | 필요 |
| P2 | 커튼 비번 원복 (HTML 1줄 + push) | 수 분 | Pages 반영 대기 |
| **P3** | **`PII_MASK` 속성 삭제 → 다음 호출부터 즉시 전체 풀 복귀** | **1초** | **불필요** |
| P4 | `TOKEN_ENFORCE` 속성 삭제 | 1초 | 불필요 |

> 위험 단계(P3·P4)는 **전부 속성 1개 삭제로 1초 복귀·재배포 불필요.** 이것이 B를 C보다 추천하는 실질적 이유입니다.

### 2-5. 실무진 영향
