## 1. '컨택한 사람'(by) 구조화 — 저장 형식

새 시스템·새 시트 없음. **기존 폼(CONTACT 연락 이력 모달·상담 모달)과 기존 저장 칸 그대로**, 노트 끝에 기계가 읽는 평문 마커 하나를 표준화했다(GM: 시트에 JSON 금지 → 사람이 읽는 평문 유지).

| 위치 | 저장 형식 (한 건) | 예 |
|---|---|---|
| 멤버십 Contact1/2/3 칸 | `날짜 시간 내용 (컨택:이름)` | `2026-07-25 14:00 상담 통화 (컨택:임정은)` |
| 멤버십 연락이력 칸(4건째~ JSON) | `{date,time,note,by}` | `{"note":"4번째 컨택","by":"최준용"}` |
| 강습 Contact 칸(줄바꿈 평문) | `날짜 시간 [종목] 내용 (컨택:이름)` | `2026-07-25 [수영] 레벨 문의 (컨택:이경연)` |

- 읽기 파서(GAS `Survey.js` + `membership.html` gviz 이중 파이프라인 **양쪽 동일 수정**)가 마커를 `by` 필드로 분리 — 화면·집계는 구조화된 `by`를 쓴다.
- 마커 규칙: **줄 끝**의 `(컨택:이름)`만 인식(`/\s*\(컨택:([^()]*)\)\s*$/`). 일반 괄호·중간 괄호 오탐 없음(로컬 20케이스 실측).
- 과거 줄(마커 없음)은 그대로 보존·표시 — 무회귀.

### 입력 UI
| 폼 | 추가된 칸 | 규칙 |
|---|---|---|
| CONTACT 연락 이력 모달(멤버십·강습 공용) | 연락 1건마다 '컨택한 사람' 드롭다운 | **새 기록 = 필수**(비면 저장 차단). 과거 행은 강제 안 함(옛 데이터가 저장을 볼모로 잡히지 않게) |
| 상담 모달(달력) | '컨택한 사람' 드롭다운 1개 | 상담 내용 입력 시 **필수** — 그 내용이 CONTACT로 쌓일 때 by 동봉 |

- 드롭다운 명단 = `OWNER_OPTIONS` 재사용(명단 이원화 방지). 마지막 선택을 localStorage에 기억해 다음 기록 기본값.
- 1차 컨택 텔레그램 알림에 `컨택: 이름` 줄 추가(배정 담당과 구분 표기).

## 2. owner 분리 — 개념 정리 (필드 신설 최소)

| 개념 | 필드 | 화면 표기 |
|---|---|---|
| 리드 배정자 (이 문의를 챙기는 사람) | 기존 `owner`(담당/지정 강사 칸) 그대로 | 표 헤더 **'배정 담당'** 으로 개명(+툴팁) |
| 실제 컨택자 (그 연락을 실제로 한 사람) | 신설 `contacts[].by` (컨택 1건마다) | CONTACT 칸에 이름 칩 병기 |

owner 칸의 의미·저장 경로는 불변 — 새 필드는 `by` 하나뿐이다.

## 3. 이탈(LOSS) 사유 — 필수화 + 체계 통일

- **필수화:** LOSS 사유 모달에서 사유 미선택 저장 차단. LOSS인데 사유 공란인 행은 목록에 '⚠ 사유 미기록' 표시(강습 성인 84·유소년 84건 백로그 표면화).
- **새 체계 v2 (9종):** 가격·프로모션 / 거리·위치 / 시간대 안 맞음 / 타업체 선택 / 단순 문의(등록의사 없음) / 연락 두절 / **강습 전환(신설)** / **상품·시설 안 맞음(신설)** / 기타
  - 신설 2종은 실데이터가 요구: 강습전환 28건·한종목만 이용 16건+시설 불만족 5건.
- **★원본 보존:** 과거 시트 값은 덮어쓰지 않는다. 매핑은 **읽기 시점**(모달 프리필)에만 — 실무진이 저장 버튼을 눌러야 그 행만 새 값으로 바뀐다.
