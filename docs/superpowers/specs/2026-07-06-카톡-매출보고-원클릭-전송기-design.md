# 카톡 매출보고 원클릭 3방 전송기 (design)

- 날짜: 2026-07-06 (창-제목 방식 재설계 + 자동 방 열기 추가)
- 소유: 시토(AI CTO)
- 배: CTO-2026-07-06-KAKAO-REPORT-SENDER (ship_no 488)
- 상태: **재설계 완료 + 자동 방 열기 추가 + GM PC 라이브 검증 완료**(웰페리온 운영부 방
  실전송 1회 성공, 자동 방 열기는 "김남욱" 방으로 안전 검증 완료 — §0-6 참조).
  나머지 2방(차의주 회장님·웰페리온 관리부)은 GM이 방을 열어둔 뒤 3방 전체 실행만 남음.
  자동 방 열기 덕분에 PC 재부팅으로 방이 안 열려 있어도 GM이 미리 열어둘 필요가 없어졌다.

## 0. 재설계 배경(2026-07-06) — 검색창 방식 폐기
기존 방식(카톡 메인창 상단 검색창에 방 이름을 입력해 여는 방식)이 "검색창(Edit)을
찾지 못함"으로 실패했다. 실측(win32gui.EnumWindows)으로 확인한 결과:
**열려 있는 카톡 채팅방은 각각 독립된 최상위 창으로 존재**하며, 창 클래스=
`EVA_Window_Dblclk`·창 제목=방 이름 그대로다(메인창도 같은 클래스이나 제목이
"카카오톡"이라 자연 제외됨). → **방을 검색해서 여는 대신, 이미 열려 있는 방 창을
제목으로 직접 찾는 방식**으로 전면 재설계했다. 전제조건: **GM이 전송 대상 3방을
카톡에서 미리 열어(대화창을 띄워)둬야 한다.** 방이 안 열려 있으면 명확한 에러로
실패한다(검색으로 자동으로 여는 폴백은 최후수단으로만 시도).

## 1. 목적
매일 9시 텔레그램으로 오는 매출보고 이미지를, GM이 텔레그램 인라인버튼 한 번 탭하면
**카카오톡 3개 방(차의주 회장님·웰페리온 관리부·웰페리온 운영부)에 그대로 자동 전송**한다.
카톡 그룹방은 공식 봇 API가 없어 **카카오톡 PC 앱 UI 자동화**로 처리한다(회색지대 필연).

## 2. 데이터 흐름

   `{ text: "📤 카톡 3방 전송", callback_data: "kakao_send" }`.
2. GM이 그 사진 아래 버튼을 탭 → 텔레그램이 같은 봇(회사 `telegram_bot/bot.py`가 폴링 중인
   그 봇, 토큰 8297784147 동일)으로 `CallbackQuery(kakao_send)`를 전송.
3. `bot.py`의 `cmd_kakao_send_callback`(pattern `^kakao_send$`)이 수신:
   - 콜백이 달린 메시지의 사진(`photo[-1].file_id`, 최대 해상도)과 `caption`을 그대로 취득.
     **재생성 없음·시트 접근 없음** — 그 텔레그램 사진 그대로.
   - `getFile` → `telegram_bot/_kakao_tmp/`에 로컬 다운로드.
   - 버튼을 즉시 제거(`edit_message_reply_markup(None)`, 중복 탭 방지).
   - `scripts/kakao_report_sender.py --image <path> --caption "<caption>"`을
     서브프로세스(`.venv` 파이썬, 옵션 없음=3방 실발송)로 실행.
   - 결과 1줄만 회신: "✅ 카톡 3방 전송 완료" 또는 "⚠️ 카톡 전송 실패: <사유>".
4. `scripts/kakao_report_sender.py`가 `scripts/kakao_rooms.json`의 방 목록을 순서대로 처리
   (창-제목 방식, 2026-07-06 재설계):
   `find_room_window(room_name)`으로 **이미 열려 있는** 방 창을 제목 완전일치로 탐색
   (클래스=`EVA_Window_Dblclk`) → `focus_window`(pywinauto `set_focus()`로 포그라운드 전환
   — 이유는 §0-1 참조) → 이미지 Windows 클립보드(CF_DIB) 세팅 → 채팅 입력창(`Document`
   컨트롤, 실측 확인·Edit 아님) 포커스 → Ctrl+V → **"클립보드 이미지 전송" 팝업**(별도
   모달 창, §0-2 참조) 캡션칸에서 Enter로 전송 확정 → 캡션 텍스트는 메인 입력창에
   클립보드 경유 붙여넣기 후 Enter(전송, 별도 메시지) → 스크린샷 증빙(`scripts/poc-evidence/`).
   방 창을 못 찾으면 `open_room_via_search`(기존 검색 방식)를 **최후수단 폴백**으로만 시도.

### 0-1. 포그라운드 전환 함정(실측)
`win32gui.SetForegroundWindow()`를 직접 호출하면 **오류 183**(Windows 포그라운드 잠금
정책 — 배경 프로세스는 임의로 포그라운드를 뺏을 수 없음)으로 막힌다. pywinauto의
`window_spec.set_focus()`는 내부적으로 AttachThreadInput 등 우회 처리를 하므로
이걸 반드시 써야 한다(`focus_window()` 함수).

### 0-2. "클립보드 이미지 전송" 팝업 함정(실측, 2026-07-06 라이브 확인)
Ctrl+V는 메인 채팅 입력창에 인라인 미리보기를 넣는 게 아니라 **별도 모달 팝업**
("클립보드 이미지 전송", 클래스도 `EVA_Window_Dblclk`이나 **제목이 빈 문자열**,
캡션칸 `Edit` 컨트롤 1개 보유·50자 제한, "전송" 버튼은 UIA에 노출되지 않는
커스텀 컨트롤)을 띄운다. 원래 채팅 입력창 참조로 Enter를 보내면 팝업이 아닌
엉뚱한 곳에 꽂혀 무반응이거나 포커스를 뺏을 수 있다 — **반드시 이 팝업 자체를
찾아(`find_clipboard_popup`, 제목 빈 `EVA_Window_Dblclk` + Edit 자식으로 식별)
그 캡션칸에서 Enter를 보내야 전송된다**(`confirm_clipboard_popup`). dry-run
종료 시에도 이 팝업은 메인 입력창과 별개 창이라 `clear_input`만으론 안 닫히므로
Escape로 팝업 자체를 직접 닫는다(`cancel_clipboard_popup`).

### 0-3. print_control_identifiers 호출 함정(실측)
`Desktop(backend=...).windows()`가 반환하는 객체(이미 resolve된 Wrapper)에는
`print_control_identifiers`가 없다(`AttributeError`). 반드시
`Desktop(backend=...).window(handle=hwnd)`(지연평가 `WindowSpecification`)로
접근해야 진단 트리 출력이 가능하다. 실제 전송 로직(`descendants`/`click_input`/
`type_keys`)은 Wrapper·WindowSpecification 둘 다 지원하므로 무관하다.

### 0-4. 검색 Edit "폭 0 붕괴" 함정(실측, 자동 방 열기 재조사 2026-07-06)
당초 "카톡 메인창 검색창(Edit)을 찾지 못함"으로 실패했던 원인을 라이브
`print_control_identifiers`(uia+win32 둘 다) 및 `win32gui.EnumChildWindows`로
직접 조사해 확인했다: 검색 Edit는 win32 클래스="Edit"로 **실제 존재**하지만,
비활성 상태에서는 `GetWindowRect`가 폭 0(`L==R`)인 좌표를 반환한다. UIA
`descendants(control_type="Edit")`는 이 상태의 컨트롤을 전혀 찾아내지 못한다
(당초 실패 원인 규명). 메인창 **우상단 돋보기 아이콘을 먼저 클릭**해야 이
Edit가 실제 폭(`R-L>0`)을 가지고 나타난다. 이 아이콘은 UIA/win32 트리에
별도 버튼으로 노출되지 않는 커스텀 그림 아이콘이라, 창 우상단 기준 고정
픽셀 오프셋(우측 끝에서 -112px, 상단에서 +57px)으로 클릭한다(라이브 실측·
검증됨). 검색 Edit 활성화 여부는 `win32gui.EnumChildWindows`로 class_name=
"Edit"·visible=True·폭>0인 것만 걸러 판정한다(`_find_visible_search_edit`).

### 0-5. Ctrl+A 전역 단축키 가로채기 함정(실측, 2026-07-06 라이브 확인)
검색 Edit에 기존 텍스트가 있을 때 이를 지우려 `Ctrl+A`(전체선택)를 보내면
**이 앱은 그것을 편집칸 단위 동작이 아닌 전역 단축키로 가로채 "친구 추가"
다이얼로그를 띄운다**(실측으로 실제 발생 확인, Escape로 안전하게 닫아 회피).
따라서 검색 Edit의 기존 텍스트 제거는 **`Ctrl+A` 대신 `{END}`→`{SHIFT+HOME}`→
`{DELETE}`만 사용**한다(`open_room_via_search` 내부). 텍스트 입력 자체는
한글 IME 문제로 `type_keys` 직접 타이핑 대신 클립보드 경유 `Ctrl+V`
(paste_text와 동일 원칙)로 넣고, 마지막 `{ENTER}`로 최상단 검색결과를 연다
(정확히 일치하는 방 이름이면 Down 키 없이 Enter 한 번으로 그 방이 곧바로 열림).

### 0-6. 자동 방 열기 라이브 검증 절차·결과(2026-07-06)
안전한 테스트 대상("김남욱" 방, 회장님/관리부 방은 오발송 방지로 절대 사용 안 함)을
의도적으로 닫은 뒤(`WM_CLOSE`), `kakao_report_sender.py --dry-run --only-room "김남욱"`
을 그대로 실행해 전체 경로를 라이브로 검증했다. 로그: "방 창이 안 열려 있음 →
카톡 메인창 검색으로 자동 열기 시도 → 자동 열기 성공(검색) → DRY-RUN: 미리보기까지
확인, 전송 생략". 스크린샷 증빙(`scripts/poc-evidence/kakao_send_김남욱_dryrun_preview_
20260706_132543.png`)으로 "김남욱" 방 창이 실제로 열려 포커스되고 클립보드 이미지
전송 팝업까지 뜬 뒤 Enter 없이 안전하게 취소된 것을 확인했다. 방 창을 찾는 최종
확인은 항상 **제목 완전일치**로만 성공 판정하므로(§4 안전장치), 검색 결과가 엉뚱한
대상을 열더라도 그 창에는 절대 진행하지 않고 타임아웃으로 안전하게 실패한다.

## 4. 안전장치(절대 원칙)
- **(2026-07-06 갱신) 방을 미리 열어두지 않아도 된다** — 방 창을 못 찾으면 카톡
  메인창 검색으로 **자동으로 그 방을 연 뒤** 전송을 진행한다(`open_room_via_search`,
  §0-4~0-6). 자동 열기까지 실패한 경우에만 `RoomNotOpenError`로 명확히 실패
  ("방 '{방이름}'을 자동으로 열지 못함. 카톡에서 직접 열어두세요.").
- `--dry-run`: 방 창 탐색+포커스+클립보드 세팅+이미지 붙여넣기(팝업까지)만 수행.
  **전송 트리거(팝업 캡션칸 Enter)는 어떤 경우에도 호출하지 않음** — 대신 팝업을
  Escape로 직접 닫아 방에 잔여물을 남기지 않는다(§0-2 참조).
- `--only-room "<방이름>"`: 지정 방 1개만 처리 — 검증 단계 필수 사용.
- 기본 실행(옵션 없음) = **3방 즉시 실발송**이므로, GM 실테스트 전 임의 실행 절대 금지.
  특히 "차의주 회장님" 방 오발송은 절대 금지.
- 봇 콜백은 버튼 탭 즉시 버튼 제거(재탭 방지) + 실행 전 "⏳ 처리 시작" 알림으로
  이중 실행 오인을 줄인다(단, 진짜 재입력 방지는 아니므로 GM은 1회만 탭할 것).

## 5. 한계(정직히 기록)
- **(2026-07-06 해소)** 이전에는 "방을 미리 열어둬야 함"이 전제조건이었으나, 자동
  방 열기(`open_room_via_search`, §0-4~0-6)를 추가해 GM PC 라이브로 검증 완료했다
  ("김남욱" 방을 의도적으로 닫은 뒤 자동 재오픈 성공). 다만 자동 열기도 카톡 메인창의
  검색 아이콘을 고정 픽셀 오프셋으로 클릭하는 방식이라 카톡 버전 업데이트로 아이콘
  위치가 바뀌면 다시 깨질 수 있다 — 실패 시 `RoomNotOpenError`로 명확히 실패하며
  GM 수동 열기로 폴백 가능(이전과 동일한 안전망 유지).
- 카카오톡 PC 앱 UI(창 클래스·팝업 구조)는 **버전 업데이트에 취약**하다. 이번 재설계는
  2026-07-06 실측 기준(창 클래스 `EVA_Window_Dblclk`, 팝업 구조 등)이며 카톡 클라이언트
  업데이트 시 다시 깨질 수 있음 — 실패 시 로그에 어느 방·어느 단계에서 멈췄는지 남는다.
- 전제조건: GM PC가 켜져 있고, 카카오톡이 로그인·자동실행 상태이며, 화면잠금이 해제되어
  있어야 한다(이미 충족 확인됨). PC 꺼짐/잠김 시 자동화 불가 → GM 수동 전송으로 폴백.
- 봇 콜백 코드는 **다음 봇 재기동 시 발효**(GM 재부팅 또는 아침 자동재기동). 즉시 반영 아님.
- **2026-07-06 GM PC 라이브 검증 완료**: "웰페리온 운영부" 방을 실제로 열어 dry-run
  (방 탐색·포커스·팝업 취소)과 실전송(이미지+캡션, 안전한 테스트 이미지·"[전송기 테스트]"
  캡션) 둘 다 성공 확인(`scripts/poc-evidence/kakao_send_웰페리온 운영부_*` 스크린샷 증빙).
  단, GM PC에 동시에 다른 창(다른 작업)이 화면을 겹칠 수 있어 **스크린샷 증빙이 간헐적으로
  엉뚱한 창을 캡처할 수 있음**(z-order 경합 — `capture_as_image()`가 PrintWindow 대신
