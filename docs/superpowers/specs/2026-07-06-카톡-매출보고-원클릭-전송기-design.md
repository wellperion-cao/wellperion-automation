# 카톡 매출보고 원클릭 3방 전송기 (design)

- 날짜: 2026-07-06
- 소유: 시토(AI CTO)
- 배: CTO-2026-07-06-KAKAO-REPORT-SENDER (ship_no 488)
- 상태: 코드·버튼 배포 완료 / 실발송 GM PC 테스트 대기

## 1. 목적
매일 9시 텔레그램으로 오는 매출보고 이미지를, GM이 텔레그램 인라인버튼 한 번 탭하면
**카카오톡 3개 방(차의주 회장님·웰페리온 관리부·웰페리온 운영부)에 그대로 자동 전송**한다.
카톡 그룹방은 공식 봇 API가 없어 **카카오톡 PC 앱 UI 자동화**로 처리한다(회색지대 필연).

## 2. 데이터 흐름
1. 09:00 GAS(`매출보고_자동발송.js` `sendDailyReport`)가 매출 시트 → PNG → 텔레그램
   `sendPhoto`(GM 개인 chat 8254867551, @namuki_report_bot)로 발송. 이번 변경으로
   `sendTelegramPhoto`가 **인라인버튼 1개**를 함께 붙인다:
   `{ text: "📤 카톡 3방 전송", callback_data: "kakao_send" }`.
2. GM이 그 사진 아래 버튼을 탭 → 텔레그램이 같은 봇(회사 `telegram_bot/bot.py`가 폴링 중인
   그 봇, 토큰 8297784147 동일)으로 `CallbackQuery(kakao_send)`를 전송.
3. `bot.py`의 `cmd_kakao_send_callback`(pattern `^kakao_send$`)이 수신:
   - 콜백이 달린 메시지의 사진(`photo[-1].file_id`, 최대 해상도)과 `caption`을 그대로 취득.
     **재생성 없음·시트 접근 없음** — 그 텔레그램 사진 그대로.
   - `getFile` → `telegram_bot/_kakao_tmp/`에 로컬 다운로드.
   - 버튼을 즉시 제거(`edit_message_reply_markup(None)`, 중복 탭 방지).
   - `scripts/kakao_report_sender.py --image <path> --caption "<caption>"`을
     서브프로세스(`.venv` 파이썬, 옵션 없음=3방 실발송)로 실행.
   - 결과 1줄만 회신: "✅ 카톡 3방 전송 완료" 또는 "⚠️ 카톡 전송 실패: <사유>".
4. `scripts/kakao_report_sender.py`가 `scripts/kakao_rooms.json`의 방 목록을 순서대로 처리:
   메인창 활성화 → 상단 검색(이름 기반)으로 방 열기 → 이미지 Windows 클립보드(CF_DIB)
   세팅 → 채팅 입력창 포커스 → Ctrl+V(미리보기) → Enter(전송) → 캡션 텍스트를
   클립보드 경유 붙여넣기 후 Enter(전송, 별도 메시지) → 스크린샷 증빙(`scripts/poc-evidence/`).

## 3. 컴포넌트
| 파일 | 역할 |
|---|---|
| `scripts/kakao_report_sender.py` | 핵심 실행기. CLI: `--image --caption [--dry-run] [--only-room]` |
| `scripts/kakao_rooms.json` | 수신 방 목록(순서대로 전송). 기본 3방 |
| `telegram_bot/bot.py` `cmd_kakao_send_callback` | 콜백 수신→다운로드→서브프로세스 실행→1줄 회신 |
| GAS `매출보고_자동발송.js` `sendTelegramPhoto` | 인라인버튼 부착(`reply_markup` JSON.stringify) |

## 4. 안전장치(절대 원칙)
- `--dry-run`: 방 열기 + 클립보드 세팅 + 입력창 미리보기(Ctrl+V)까지만. **Enter(실제 전송)는
  어떤 경우에도 호출하지 않음.** dry-run 종료 시 입력창 잔여물은 정리(`Ctrl+A`+`Delete`).
- `--only-room "<방이름>"`: 지정 방 1개만 처리 — 검증 단계 필수 사용.
- 기본 실행(옵션 없음) = **3방 즉시 실발송**이므로, GM 실테스트 전 임의 실행 절대 금지.
  특히 "차의주 회장님" 방 오발송은 절대 금지.
- 봇 콜백은 버튼 탭 즉시 버튼 제거(재탭 방지) + 실행 전 "⏳ 처리 시작" 알림으로
  이중 실행 오인을 줄인다(단, 진짜 재입력 방지는 아니므로 GM은 1회만 탭할 것).

## 5. 한계(정직히 기록)
- 카카오톡 PC 앱 UI(창 제목·검색창 UIA 트리)는 **버전 업데이트에 취약**하다. 방 검색·채팅방
  열기는 이름 기반 검색(좌표 하드코딩 최소화)이나, 카톡 클라이언트 업데이트 시 키 입력
  시퀀스가 깨질 수 있음 — 실패 시 로그에 어느 방에서 멈췄는지 남는다.
- 전제조건: GM PC가 켜져 있고, 카카오톡이 로그인·자동실행 상태이며, 화면잠금이 해제되어
  있어야 한다(이미 충족 확인됨). PC 꺼짐/잠김 시 자동화 불가 → GM 수동 전송으로 폴백.
- 봇 콜백 코드는 **다음 봇 재기동 시 발효**(GM 재부팅 또는 아침 자동재기동). 즉시 반영 아님.
- 이 스크립트는 이 저장소 개발 환경(카카오톡 미설치)에서는 py_compile·의존성 체크·에러
  핸들링 경로만 검증 가능했고, **실제 카톡 UI 상호작용(방 검색→열기→붙여넣기→전송)은
  GM PC 실환경에서만 검증 가능**하다.

## 6. GM 테스트 절차 (필수 순서)
1. **dry-run 1방**: `python scripts\kakao_report_sender.py --image <아무_보고_png> --caption "테스트" --dry-run --only-room "웰페리온 운영부"` 실행 → 카톡 "웰페리온 운영부" 방이 열리고
   입력창에 이미지 미리보기가 뜨는지, Enter 없이 자동으로 지워지는지 확인.
2. **안전한 1방 실발송**: `--only-room "웰페리온 운영부"` (dry-run 옵션 제거) 실행 → 실제
   전송되는지, 캡션이 별도 메시지로 따라오는지 확인.
3. **텔레그램 버튼 경로 1회 확인**: 9시 매출보고 아래 "📤 카톡 3방 전송" 버튼을 탭 →
   봇이 "⏳ 처리 시작" → "✅ 완료" 순으로 회신하는지, 카톡 3방(회장님방 포함) 모두
   정상 도착했는지 확인. **봇 재기동 후에만 이 경로가 동작함**을 유의.
4. 문제 발생 시 `scripts/poc-evidence/kakao_send_*` 스크린샷과 `telegram_bot/bot.log`의
   `[kakao_send]` 라인으로 어느 방·어느 단계에서 실패했는지 추적.

## 7. 비목표(YAGNI)
- 방 목록 GUI 편집 도구는 만들지 않음(`kakao_rooms.json` 직접 편집).
- 카톡 발송 이력 로그 DB화는 후순위(현재는 스크린샷 증빙 + bot.log만).
- 공식 카카오 API 대체 조사는 별건(현재는 UI 자동화가 유일한 그룹방 전송 경로).
