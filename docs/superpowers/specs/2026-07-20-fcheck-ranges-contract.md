# 시설부 점검 기준값 단일화 — 데이터 계약 (SSOT)

작성: 시우(AI COO) 2026-07-20 · 배9199 · 상위 명세 `.omc/specs/deep-interview-facility-check-threshold-ssot.md`

> **이 문서가 규격의 원천이다.** 프론트·GAS·대시보드 세 곳은 모두 이 계약만 따른다.
> 기준 숫자를 이 문서나 코드에 적지 않는다 — 숫자는 오직 시트에만 존재한다.

## 1. 원천 = 「점검기준」 시트 1장

점검 스프레드시트(기존 GAS가 여는 것과 동일)에 시트 1장 추가.

| 열 | 키 | 예 | 설명 |
|---|---|---|---|
| A | 항목id | `fc_pool_temp` | 프론트 입력 필드 id와 동일. **불변 키** |
| B | 이름 | 수영장 수온 | 사람이 읽는 이름 |
| C | 단위 | ℃ | 표시용 |
| D | 법정하 | (빈칸) | 법정 하한. **빈칸 = 법정 기준 없음** |
| E | 법정상 | (빈칸) | 법정 상한 |
| F | 목표하 | 28 | 목표 하한. 빈칸 = 목표 없음 |
| G | 목표상 | 33 | 목표 상한 |
| H | 측정주기 | 일일 | `일일` \| `외부검사` |
| I | 경보 | Y | `Y`=경보 켜짐 / `N`=기록만(경보 끔) |
| J | 비고 | 2주 실측 후 확정 | 자유 |

**초기 행 (법정값은 체육시설법 시행규칙 · 목표값은 2주 관찰 후 확정 전까지 경보 N)**

| 항목id | 이름 | 법정하 | 법정상 | 목표하 | 목표상 | 주기 | 경보 |
|---|---|---|---|---|---|---|---|
| fc_pool_ph | 수영장 pH | 5.8 | 8.6 | | | 일일 | Y |
| fc_pool_cl | 유리잔류염소 | 0.4 | 1.0 | | | 일일 | Y |
| fc_pool_temp | 수영장 수온 | | | | | 일일 | **N** |
| fc_sauna_* (7종) | 사우나 각 탕 | | | | | 일일 | **N** |
| fc_wq_turbidity | 탁도 | | 1.5 | | | 외부검사 | Y |
| fc_wq_kmno4 | 과망간산칼륨 소비량 | | 12 | | | 외부검사 | Y |
| fc_wq_coliform | 총대장균군 | | 2 | | | 외부검사 | Y |

→ **수온·사우나는 경보 N으로 시작** = 2주간 값만 쌓고 경보 없음(명세 확정사항).
→ 목표 칸이 비면 🟡 판정 자체가 없다. 2주 뒤 숫자를 채우면 그때부터 🟡이 산다.

## 2. 판정 규칙 (세 곳 공통 · 이 규칙만 구현)

```
판정(값, 기준행):
  경보 == 'N'        → 🟢 (기록만, 집계 제외)
  값이 빈칸           → 판정 없음 (미입력, 경보 아님)
  법정하/법정상 있고 그 밖 → 🔴 이상
  목표하/목표상 있고 그 밖 → 🟡 주의
  그 외                → 🟢 정상
```

- **이상 건수(abnormalCount) = 🔴 개수만.** 🟡은 별도 카운트(warnCount), 이상에 합산 금지.
- 기준행이 없는 항목 = 판정 없음(조용히 스킵). 지어내지 않는다.

## 3. GAS 액션 (신규 2개)

| 액션 | 인증 | 입출력 |
|---|---|---|
| `fcheck_ranges_get` | 공개(읽기) | `{}` → `{ok:true, ranges:[{id,name,unit,legalMin,legalMax,targetMin,targetMax,cycle,alert,note}]}` |
| `fcheck_ranges_save` | 직원 게이트 | `{rows:[...]}` → 전체 교체 저장 후 `{ok:true,count:n}` |

- 빈 숫자칸은 `null`로 반환 (0과 구분 — **0을 빈칸으로 쓰지 말 것**)
- 시트가 없으면 `fcheck_ranges_get`이 자동 생성 + 위 초기행 시드 (멱등)

## 4. 세 곳이 할 일

| 위치 | 지금 | 바꿀 것 |
|---|---|---|
| 입력화면 `시설부 체계.html` | `FC_RANGES` 하드코딩 | 로드시 `fcheck_ranges_get` → 그 값으로 판정·힌트 표시. **하드코딩 삭제** |
| GAS `_facilityRangeHits` | `FC_MEASURE_RANGES` 하드코딩 | 시트에서 읽어 §2 규칙 적용. 🔴만 abnormalCount |
| 대시보드 `wellperion_guide(main).html` | `FACILITY_RANGES` 하드코딩 | 동일 액션 호출. **하드코딩 삭제** |

**폴백:** 조회 실패 시 판정을 아예 하지 않는다(경보 0). 옛 하드코딩으로 되돌아가지 말 것 — 그게 이번 사고의 원인이다.

## 5. 추가 UI

- **기준표 편집** — 시설부 체계 페이지에 표 1개. 기존 편집형 표(직원구성·장비비품) 패턴 재사용. 저장 = `fcheck_ranges_save`.
- **사유 칸** — 측정값이 🔴/🟡일 때 그 항목 옆에 한 줄 입력칸 노출, 제출 시 함께 저장.
- **수질검사 기록** — `측정주기=외부검사` 항목은 일일 점검표와 분리된 별도 섹션. 일일 이상 집계에 미포함.
- **실측 분포표** — 항목별 최근 2주 값의 최소·최대·평균·건수. 목표치 확정용.
