# CMO 자율화 두뇌 (레퍼런스) — 검증 후 타 C-Level 복제 템플릿

- 날짜: 2026-07-09
- 발의: GM 직접 지시 (Fable 세션 = "결과물 아닌 뼈대를 남긴다")
- 소유: **시모(CMO)** — GM 정정("시토 게 아니라 시모 것"). 부팅 좌석=시모, CMO 두뇌를 레퍼런스로 먼저 잘 셋업.
- 확산: GM이 전 C-Level에 동일 지침 이미 전달 완료 → 이 문서는 CMO 레퍼런스. 검증되면 헌장으로 박제해 타 C-Level이 같은 계약으로 복제.
- 상태: 아키텍처 확정 → 착수. **라이브 보안 발효 = GM go + 즉시 역롤백**

## ✅ 확정 (deep-interview 2026-07-09 · 6R · 모호도 4.6% · 크리스탈 스펙 = `.omc/specs/deep-interview-cmo-autonomy-brain.md`)
1. **대상 = 다른 비즈니스 업체** — "AI 없이 쓰게"의 사람=타 업체. 북극성 'ERP 상품화' 직결.

3. **Platform A** = 봇 1개 + 모듈별 대상 chat, `report(일/주/월)`, 등록 레지스트리 외부화. "등록만 하면 온다".
4. **Platform B = 세션 우선 + PW 암호화 폴백**(원안 'PW 저장 자동로그인' 교정). 2FA·캡차=사람 1회. 평문 PW 0.
5. **MVP = M3→M1 병합 + Platform A**(보안무관·GM go 불필요). Platform B는 검증 후.
6. **③ 프론트 = 기존 M1/M2/M3 기능 캡슐 정리**(신규 페이지 남발 X).

## 0. 원칙 (GM)
Fable(고성능)이 떠난 뒤에도 각 Sonnet C-Level이 스스로 똑똑하게 돌게 하는 **뼈대(자율화 두뇌·프롬프트·가드레일·아키텍처)**를 남긴다. 두뇌를 찍으면 복리로 남는다.

각 C-Level 자율화 두뇌 = 본인 소유 **백엔드+프론트엔드(ERP 페이지)** 기준으로:
- ① 백엔드 = AI 없이도 실무진이 쓰게 설계 (구조·API·처리흐름 단순화)
- ② UI/UX = 프로세스 단계·소요시간 최소화 (정말 신경써서)
- ③ 프론트 = 모듈화 가독 (남들도 쉬워짐 · 모듈마다 고유 기능 캡슐)
- ④ 모듈별 텔레그램 알림·보고 자동화 (봇 등록 시 일/주/월 자동)
- ⑤ 채널 자동화 (계정 웹 등록 → 자동 로그인·진행 · **보안 중요**)

CMO는 ⑤(채널 자동로그인)의 첫 실사용처라 레퍼런스로 적합. CMO 두뇌가 "잘 도는" 걸 확인하면 ④⑤ 인프라는 재사용 가능하게 지어 타 C-Level 모듈이 얹기만 하면 되게 한다.

## 1. CMO 두뇌 두 서브시스템 (재사용 설계)

### Platform A — 모듈별 텔레그램 자동보고
등록 한 번 → 일/주/월 리포트 자동 발송. 시모는 콘텐츠만, 파이프가 스케줄·발송을 담당.

- **등록 UI (ERP):** 봇 토큰 · 봇 ID · 대상 chat_id · 모듈/C-Level 태그 · 주기(일/주/월) 등록.
- **모듈 계약(인터페이스):** 각 M 모듈은 표준 함수 1개만 구현
  `report(period) -> {title, summary_lines[], metrics{}, honesty_tag}` (period ∈ 일/주/월).
  파이프는 이 반환을 표준 카드로 포맷·발송. 정직 꼬리표(측정/부분/미측정) 필수.
- **스케줄 엔진:** 기존 `daily_scheduler.py`(CronTrigger, KST) 확장 — 등록 레지스트리를 읽어 주기별 트리거. 새 예약작업 최소화.
- **레지스트리:** `status/telegram_module_registry.json` (모듈→봇·chat·주기·마지막발송). 단일 SSOT.
- **재사용 자산:** `telegram_bot/`, `daily_scheduler.py`, `clevel_post_action.py`(1줄 보고), 헬스체크(13시+drift 가드).

### Platform B — 채널 자격증명 등록 + 자동로그인 (보안)
GM 결정 = **ERP 웹 등록 UI(암호화 저장)**. 첫 대상 = CMO 5채널(IG·블로그·카페·카카오·당근).

- **등록 UI (ERP):** 채널 **세션 시딩**(업체가 최초 1회 로그인) + PW **암호화 저장**(평문 금지). 세션 우선, PW는 폴백용.
- **암호화:** 대칭키(예: Fernet/AES-GCM). 키는 환경변수/OS 자격증명 관리자에 보관, ERP·git·로그에 절대 미노출. 자체서버(≈9월·JWT·배101) 도입 시 **서버 볼트로 이관**.
- **자동로그인 엔진:** 기본=persistent-profile 세션 유지. 세션 만료 시에만 암호화 PW로 재로그인 폴백. 2FA·캡차=사람 1회 개입. 손상 프로필 재생성 경로 유지.
- **보안 게이트(불변):** 라이브 발효 = **GM go + 1초 역롤백**. `TOKEN_ENFORCE`/`PII_GATE`류 무중단 스위치 패턴 재사용(기본 OFF로 배포, GM go 시 ON). 참조: `feedback_security_live_activation_needs_gm_go`.
- **접근통제:** 자격증명 열람/편집 = 관리자 게이트(민감페이지 gate.js 커튼 재사용). 로그: 누가·언제 등록/사용.

## 2. 모듈 표준 (CMO 모듈 → 복제 시 공통 계약)
각 소유 ERP 모듈 = 아래 3개를 만족하면 자동화 두뇌에 "얹힌다":
1. **읽기 쉬운 프론트** — 모듈 단위 분리, 모듈마다 고유 기능 1묶음, 전문용어·게이트·해석난이도 낮춤.
2. **AI 없이 쓰는 백엔드** — 실무진이 직접 입력·조회 가능한 단순 구조·최소 클릭.
3. **`report(period)` 구현** — Platform A가 일/주/월 자동보고.
(채널 소비 모듈만) **채널 소비** — Platform B 자격증명·자동로그인 사용.

## 3. 보안·과도기 결정 (GM 확정 + 오픈)
- ✅ 자격증명 = ERP 웹 등록 UI, 암호화, 자동로그인. 라이브=GM go+역롤백.
- ⚠️ 암호화 키 보관: 과도기=로컬 env → 자체서버 도입 시 서버 볼트 이관.
- ❓ 봇 정책: 단일 봇 멀티 chat vs 모듈별 봇 — 등록 레지스트리는 둘 다 수용.
- ❓ 자동로그인 채널 우선순위: IG·블로그·카페·카카오·당근 중 착수 순서.

## 4. CMO 착수 (레퍼런스 검증)
- **M3 → M1 병합**(GM 지시): 채널·검수·발행(M3)을 콘텐츠 제작(M1)으로 흡수 → 단일 흐름. (보안 무관 → 즉시 착수 가능)
- 병합 후 채널 발행 = Platform B 자동로그인 위에서 동작.
- 각 M 모듈 = `report(period)` 구현 → Platform A로 마케팅 일/주/월 자동보고.
- 프론트 = 실무진 눈높이 모듈화 가독(배545 대시보드 정상화 미션의 연장).
- 이 CMO 파일럿이 "잘 도는" 걸 확인 → 계약을 헌장으로 박제 → 타 C-Level 복제.

## 5. 롤아웃 순서
1. M3→M1 병합 (문서·나브 정합, 보안 무관 → 먼저).
2. Platform A 레지스트리+스케줄+`report()` 계약 확정 → CMO 모듈 시범 자동보고 라이브 검증.
3. Platform B 등록 UI + 암호화 저장 (기본 OFF·휴면 배포).
4. GM go → 자동로그인 라이브(1채널부터) + 역롤백 대기.
5. 검증된 CMO 두뇌를 헌장으로 박제 → 타 C-Level 복제.

## 6. 재발방지 가드
- 라이브 보안 스위치는 코드 0변경·기본 OFF 배포, GM go 후에만 ON (역롤백 명령 함께 기록).
- GAS/라이브 즉흥수정 금지 — 로컬 검증 후 1회 배포.
- 자격증명 평문(파일·로그·git·ERP DOM) 노출 0 — 커밋 전 스캔.
