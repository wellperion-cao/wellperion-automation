# 웰페리온 C-Level 공통 부팅 절차 (실행 정본 · §1~5 = 6역할 / §6~7 = CEO 포함 7역할)

**이 스킬은 정본이 아니다** — 값·규칙의 단일 출처(SSOT)는 항상 원본 파일이며, 여기는 6역할이 공유하는 실행 절차를 모아 "한 곳 수정 = 전체 반영"되게 하는 인덱스다. 각 에이전트 `.md`의 §1(ERP 메뉴)·§3(보고 라인)·닉네임·페르소나는 역할별 고유부라 이 스킬 밖에 그대로 남는다. ▸경위 = 이력.md.

**★안전 원칙:** 이 스킬이 어떤 이유로든 로드되지 않아도 부팅 신뢰성이 깨지면 안 된다. 그래서 각 에이전트 `.md`에는 "`ssot/약속.json` + `ssot/CONSTITUTION.md` 직독·흡수"라는 최소 크리티컬 지시가 **인라인으로 그대로 남아 있다**. 이 스킬은 그 위에 상세·연동·자율실행 절차를 얹는 역할만 한다.

## 1. 부팅 시 헌법 직독·흡수 (크리티컬 — 각 에이전트에도 인라인 중복 유지)

- 부팅 시 아래 한 줄로 **약속·재발방지·공식값·자율화규약·CONSTITUTION·모듈등록부를 역할별 슬라이스**로 받아 흡수한다(배1014 · 2026-09-05 시토 — 6벌 통째 직독 대신 필요한 부분만):
  ```
  C:\Python314\python.exe scripts/boot_pack.py --role {role}
  ```
  - 파일은 여전히 한 벌 그대로다(약속 L01) — 이 명령이 **읽는 순간**에만 잘라 준다(§2 `hangro_board.py --role` 과 같은 원리). 전문이 필요하면 원본 파일을 직접 연다.
  - ★**`ssot/자율화규약.md`(v1.1 · 2026-08-03 GM 확정)의 발효 상태**는 슬라이스 맨 위 줄에 나온다 — 미발효 구간에는 기존 규칙(약속 L20 · 본 스킬 §2-1)이 함께 살아 있고, 어긋나면 날짜가 최신인 쪽을 따른다. ▸경위 = 이력.md.
  - 규약이 정하는 것: 편제(리드 2인 웰리·시토 / 실행자 3인 시포·시모·시우) · 위임 계통(GM→리드→실행자, 실행자 GM 직보 금지) · 권한(반복·기존=자율 / 변경·신규=승인 · 영구 승인은 💰🔒🚫 3-트리거) · 보고 채널 · 자율화 레벨.
  - 약속: L15(업무=G1 단일진실) · L16(항로 양식) · L14(모호성 게이트) · L10/L12(보고 형식)
  - 헌법(CONSTITUTION.md): 불변원리 3 · 구조0 정합성 게이트 · 구조2 재발방지 · GM 정합성 가드
- **정본 = 각 파일 자체.** 이 스킬에도, 각 에이전트 `.md`에도 원칙 본문을 하드카피하지 않는다 — slice는 발췌일 뿐 원본을 대체하지 않는다.
- 페이지(HTML)를 읽는 것만으로는 흡수되지 않는다(클라이언트 JS 렌더라 "불러오는 중…"만 보임) — 슬라이스로도 부족하면 `ssot/*.json`·`.md` **파일 자체**를 직독한다.
- **★부팅 시 `wellperion-gm-report` 스킬을 반드시 함께 로드한다 (2026-07-27 GM 지적 · 7역할 공통).** 항로 출력 전, 이 스킬과 같은 자리에서 로드한다 — GM께 내는 **첫 글자보다 먼저** 규칙이 들어와 있어야 한다.
  - **'참조'가 아니라 '로드'다.** 보고 형식 정본(L18 ★표로만 답한다 = 그 스킬 §4-2)은 그 스킬 안에만 있다 — 읽히지 않은 규칙은 없는 규칙이다(약속 L02).
  - **적용 범위:** 러닝 데이터뿐 아니라 **중간 과정·중간 산출물**까지. 판정 = 그 문장을 지워도 GM 판단이 달라지지 않으면 지운다.
  - **★이번 세션에서 GM이 남긴 교정·선호는 세션이 끝나기 전에 원장에 남긴다** (2026-07-30 · 배10267). 남기는 자리 = 이미 지나가는 관문 하나:
    ```
    python wellperion-agents/scripts/clevel_post_action.py ... --gm-signal "GM: <남긴 한 줄>" --gm-signal-type preference
    ```
    (`--gm-signal-type` = `correction`(교정) · `preference`(선호) · `missed`(놓침) 중 하나 · 기본 correction)
    - 7역할이 모두 지나가는 이 자리에만 적는다(약속 L21). ▸경위 = 이력.md.
  - **같이 흡수: `status/gm_profile.md`** (2026-07-27 웰리 결정). **여기서 파일을 직접 열지 않는다** — §2 `hangro_board.py --role` 이 「📋 GM 프로필 요약(부팅 슬라이스)」로 `선호·습관·자주 놓치는 것` 3섹션을 함께 낸다. 자가점검용 상세가 필요할 때만 파일 자체를 연다. ▸주의: **날짜 표기가 있는 항목만 확정** — 날짜 없는 서술은 잠정. ▸경위 = 이력.md.

## 2. 부팅 후 위임 task(항로) 표출

- 부팅 후 **본인 role**의 열린 배를 **약속 L16 항로 양식**(3섹터 마크다운 표 · 아이콘 표준 A안)으로 출력한다(출력 후 멈추지 않는다 — 이어서 §6 선언 → **§7 자율 진행**). 양식 상세는 `ssot/약속.json` L16 직독 + `wellperion-gm-report` 스킬 §5 — 본문 재기술 없음.

- **★`status/_queue.json` 을 통째로 읽지 않는다 (2026-07-29 · 배10369).** 아래 한 줄로 **본인 배만** 받는다:
  ```

  ```
  (이 PC 는 `python` 만 치면 윈도우 별칭 스텁에 걸려 실행이 안 된다 — 전체 경로로 부른다)
  - **파일은 한 벌 그대로다.** 역할별로 쪼개지 않는다(진실이 7벌이 되면 약속 L01 위반) — 읽는 순간에만 잘라 준다. ▸경위(왜·슬라이스 자수) = 이력.md.
  - **정보 손실 0:** 전 역할 항로는 `--role` 없이 같은 명령, 특정 배의 전체 기록은 **그 배 하나만** 큐에서 찾아 읽는다. 배를 착수할 땐 아래 「낡은 지시 금지」대로 **그 배 note 는 끝까지** 읽는다.
  - **이 한 줄이 §6 KPI값·§1 GM 프로필까지 같이 낸다(배433).** 출력 끝에 `📌 담당 KPI(...)`·`📋 GM 프로필 요약`이 자동으로 붙는다 — 두 파일을 따로 열 필요 없다.
- `status/{role}.json`(예 `status/cfo.json`)은 **보조(메타)일 뿐** — 그 안 DONE·terminal 항목을 부활시켜 다시 보여주지 않는다.

**★쿵짝표 — 어제 못 끝낸 것부터 (★7역할 공통 · GM 지시 2026-08-10).** 항로 표출 다음, 자가점검(§2-1) 전에 아래 한 줄로 낸다.

## 2-1. 아침 자가점검 (★7역할 공통 — CEO 포함 · 약속 L20 실행 절차 · 2026-07-25 · 2026-08-19 개정)

> ★★**여기서 찾은 것으로 배를 만들지 않는다 (GM 확정 2026-08-19 · 이 절에서 가장 강한 규칙).** 점검 결과는 셸에 「🔎 아침 점검 정리」 표 한 장으로만 낸다(칸 = 어디 / 무엇이 걸렸나 / 그냥 두면 / 내 제안). 표 밖 줄글 금지. **그 표를 보고 GM 이 전달해 주신 것만 배가 된다** — 전달이 없으면 참고로 끝나고, 다음 아침에 또 올라와도 정상이다.
> - **예외(종전대로 즉시 배로):** 실무진이 신고한 것 · GM 이 지시한 것 · 실제로 사람이 못 쓰고 있는 장애. **사람이 답을 기다리고 있으면 배다.** 점검에서 내가 "발견"한 것만 배 금지다. 아래 본문에 남은 "그게 오늘 첫 배다"류 표현은 이 예외에 해당할 때만 읽는다.
> - **남의 도메인**도 같다 — 사람이 기다리는 건이면 §5-1 `queue_dispatch.py` 로 담당에게 넘기고, 내가 발견한 개선거리면 표에만 적는다.
> - 배로 올린 건은 커밋·푸시까지 해야 상대·GM 화면에 뜬다(§5-2 `safe_commit.py`).
> - 판정 한 줄: **"이걸 안 고치면 사람이 불편한가?"** 그렇다 = 배. 아니다 = 표에만 적는다.
> - 종전 2026-07-27 판("상설 배 1척에 줄로 붙여라")은 폐지. ▸GM 원문·경위 = 이력.md.

## 5-1. 남의 도메인 일 = '배'로 띄워 넘긴다 (★7역할 공통 · 2026-07-23 GM 지시)

  ```
  python scripts/safe_commit.py -m "메시지" -- <경로1> <경로2>
  ```
- 이 도구가 보장하는 것: **락 직렬화** · 라이브 인덱스 무접촉(임시 인덱스를 `read-tree HEAD` 로 시작) · **지정 경로만** 담김 · 커밋 직전 HEAD 재검증 + `update-ref` 원자 갱신 · 커밋 후 **무관 경로 혼입 검증** · push 연계.
- **절대 하지 않는 것:** `git add -A` · `git add .` · 내가 안 고친 경로 staging · 작업트리를 바꾸는 명령(`reset --hard` · `checkout --` · `rebase`).
- `.git/index.lock` 이 보이면 **다른 세션이 커밋 중**이다 — 지우지 말고 기다렸다 재시도한다.
- 커밋 후 **HEAD 에 내 변경이 실제로 들어갔는지 확인**한다(`git show HEAD:<경로> | grep …`).

> 정본 = `scripts/safe_commit.py`. 같은 일을 하는 헬퍼를 새로 만들지 않는다.
