# 웰페리온 GM 보고·소통 표준 (실행 형식 정본)

이 스킬은 **소통 약속의 실행 형식 정본**이다. 규칙의 단일 출처(SSOT)는 `ssot/약속.json`(L10·L12·L17·L18)이며, 그 약속 본문은 짧은 핵심만 두고 **형식 상세는 여기로 이관**했다(2026-07-22 GM 확정, L02 "정한 건 코드로 박는다"). 전 C-Level 공통 적용. **항로 리스트업(L16)은 이 스킬과 별개** — 항로는 `ssot/약속.json` L16 양식을 그대로 쓴다.

---

## 0. 언제 쓰나

GM께 **무엇이든 보고·답변·소통할 때 항상.** GM 프롬프트에 답할 때, 작업·이슈 처리 결과를 알릴 때, 완료(✅)/진행(⏳)/막힘(❌)/GM필요(⚠️)를 알릴 때 — 예외 없이 아래 표준 표(§4)로 낸다. 아침 항로 리스트업만 예외(L16).

---

## 1. GM에겐 쉬운 말로 (L10 = 단어)

- 줄임말·영어는 **풀어서.** 비개발자도 한눈에 알게.
- 내부 번호·코드(약속번호·사고번호·작업ID 등)도 **GM 화면엔 그대로 띄우지 말고** 사람 말로 풀거나 뺀다.
- 진행 중 과정은 **결과·문제만** 정리해 보여주고, 세부 단계 중계는 접거나 생략한다.

## 2. 짧고 한눈에 (L12 = 길이·시각)

결론 먼저·핵심만 짧게. 표·굵은 글씨·불릿으로 가독성·가시성·직관성 있게. **긴 줄글 벽 금지.** 측정 6규칙:

1. **결론/핵심을 맨 위 1~2줄에 먼저**
2. 비교·목록·현황은 **줄글 대신 표**
3. 한 문단 **3줄 이내**
4. 중요 수치·결정·상태는 **굵게**
5. 상세·근거는 **접기 또는 '필요시'로** (삭제가 아니라 접기 — 정보 손실 0)
6. 같은 내용 **반복 금지**

> L10 '쉬운 말' = 단어 / L12 = 길이·시각. 짝으로 쓴다.

## 3. 결과중심·기계작업은 뒤로·기록위치 알림 (L17)

전 C-Level 공통, L10·L12의 실천 강화:

1. **한국어로**, GM이 한 번에 이해·읽히게(영어·전문용어·약어 빼고 짧고 또렷이).
2. **결과(됐다/안 됐다)와 GM이 정할 것 중심** — 커밋해시·검증로그·줄번호·배포버전·도구 실행과정 등 읽어도 모르는 내부 과정은 화면에 안 띄운다(GM이 '어떻게 했어' 물을 때만 펼침).
3. **기계 작업(검증·커밋·코드패치)은 메인 화면에서 늘어놓지 말고 서브에이전트로** 돌려 GM 화면 밖에서 처리.
4. **무엇을 어디에 기록·박제했는지 끝에 한 줄로 항상 알린다.**

> ⛔ **중간 과정은 화면에서 숨긴다 (2026-07-22 GM 강한 지적).** GM이 피드백을 주고 작업이 시작되면 **중간 러닝·작업 로그가 화면을 뒤덮어 GM이 '내 지시'와 '결과'를 못 찾는다.** 그래서:
> 1. **맨 위 = 📌 GM 지시 되짚기 → ✅ 결과** 순으로 먼저 보인다(§4 표준 표 그대로).
> 2. **중간 러닝·위임·에이전트 왕복·검증 과정은 GM 화면에 나열 금지** — 전부 서브에이전트로 화면 밖에서 돌린다.
> 3. **'위임합니다 / 대기합니다' 같은 진행 중계·에이전트 보고 원문 relay 금지.** GM은 결과만 본다.
> 4. **아직 진행 중이면 '진행중' 한 줄만** 낸다(과정 나열 대신).

## 4. GM 문답·작업 보고 = 표준 표 (L18 · 핵심)

GM 프롬프트에 답하거나 작업·이슈 처리 결과를 보고할 땐 **반드시 이 표준 표로.** (항로 리스트업은 L16 유지·별개.)

### 4-1. 구성 (위→아래 고정 순서)

1. **맨 위 1줄 = 상태 결론** : `✅완료 / ⏳진행 / ⚠️GM필요 / ❌막힘` + 담당 닉네임+배번호 + 제목.
2. **표 5행 (고정 순서 = GM 문답 5요소):**

| 요소 | 뜻 | 예시 |
|---|---|---|
| 📌 GM 지시 | GM이 시킨 것·물은 것을 한 줄로 되짚기 — GM이 '내 말을 제대로 받았나' 즉시 확인 | "반복 실수 근절해라" |
| 🔍 실측 | 실제로 확인한 내용을 쉬운 말로 1~2줄(추측 아닌 실측, 전문용어·수치 나열 금지) | 결정이 큐에 안 박혀 재발동 |
| ✅ 반영 | 한 것·커밋·배포 1줄 | 종결마커+가드 박제 |
| 🔎 웰리 검수 | 라이브 시크릿크롬 실측 1줄(가능하면 확인 링크) | 확인 OK |
| 👉 GM 액션 | GM이 정하거나 해야 할 것 — **필요할 때만**, 없으면 행 삭제 | 라이브 발효 1개 |

3. **맨 끝 1줄 = 기록 위치** (어디에 박제·기록했는지, L17④).

### 4-2. 규칙

- 상세·근거·커밋해시·로그는 **기본 접고** GM이 '어떻게 했어' 물을 때만 펼친다(L12⑤ — 삭제가 아니라 접기, 정보 손실 0).
- **여러 건이면** 각 건을 표로 + 맨 위 한눈 요약 1줄.
- **목적:** GM 지시→실측→반영→검수→내 차례를 한눈에. 📌 지시 되짚기가 '내 말 반영됐나'를, 👉 GM 액션 행이 'GM이 할 일'을 구조적으로 못 놓치게 보증한다.

### 4-3. 이력(경위)

2026-07-22 GM 확정 — 구 🔴이슈/🔧해결 2행을 📌GM지시/🔍실측으로 교체·병합. 소통 약속(L10·L12·L17·L18) 형식 상세를 본 스킬로 이관하고 약속 본문은 핵심만 축약.

## 5. 아침 항로 리스트업 양식 (L16 · 보고와 별개)

★ 이 §5는 §1~4 GM 보고와 **별개**다. 아침에 본인 항로(오늘 할 일)를 리스트업할 때 전 C-Level이 같은 **3섹터 마크다운 표** 양식으로 적는다(아이콘 표준 A안).

### 5-1. 3섹터 (각 섹터 = 마크다운 표)

- 🚢 **진행중** / ⚓ **대기중** / 🏁 **입항 완료 (오늘)**
- 상태 아이콘(⚓·🏁)은 **섹터 제목에만** 쓴다 — 배 칸엔 넣지 않는다.

### 5-2. 표 칼럼 (5개 고정)

`배 | 담당 | 진행명 | 간단설명 | 본질에 대한 핵심조언`

- **배** = 항상 난이도 배 아이콘만 : 🛳️ 크루즈=무거움 / ⛴️ 여객선=보통 / ⛵ 돛단배=가벼움.
- **담당** = 닉네임 + 식별번호(`status/_queue.json`의 ship_no), 예 '시모 28'. **'CMO' 같은 약어 금지.** 식별번호로 같은 담당의 여러 배를 구별한다(번호는 배마다 고정·불변). 닉네임: CMO→시모 / COO→시우 / CTO→시토 / CPO→시포 / CFO→시뽀 / CHRO→시로 / CEO→웰리.
- **본질에 대한 핵심조언** = AI본질(그 일을 AI로 푼 핵심 한 줄) + 핵심조언(GM이 알아야 할 판단·다음 한 줄)을 **한 칸으로 합침**.

### 5-3. 섹터별 꼬리표

- **⚓ 대기중** : 신규 대기(배만) + 보류(진행중이다 멈춤)는 배 칸 옆 '**보류**' 꼬리표로 구분. 보류 건의 핵심조언엔 **멈춘 이유·재개 조건** 기재.
- **🏁 입항 완료 (오늘)** : 각 건에 🔗(다음 남김=**항로점**) 또는 🌀(다음 없음=**표류**) 꼬리표. 🌀 표류 건의 핵심조언엔 반드시 '**👉 다음 뭐 할지 정하세요**' 촉구 포함.
- 완료 표현은 '**입항 완료 (오늘)**'으로 통일. ★⚓ 뜻 = '대기/정박'(완료 아님) / 완료 = 🏁.

### 5-4. 예시

| 배 | 담당 | 진행명 | 간단설명 | 본질에 대한 핵심조언 |
|---|---|---|---|---|
| ⛴️ 🔗 | 시모 4 | #18 발행 | 검증 후 발행완료 | 다음=19편 기획(다리 놓음) |
| ⛵ 🌀 | 시모 7 | △△ 정리 | 완료 다음 미정 | 👉 다음 뭐 할지 정하세요 — 표류 중 |
