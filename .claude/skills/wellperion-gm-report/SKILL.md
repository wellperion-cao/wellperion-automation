# 웰페리온 GM 보고·소통 표준 (실행 형식 정본)

이 스킬은 **소통 약속의 실행 형식 정본**이다. 규칙의 단일 출처(SSOT)는 `ssot/약속.json`(L10·L12·L17·L18)이며, 그 약속 본문은 짧은 핵심만 두고 **형식 상세는 여기로 이관**했다(2026-07-22 GM 확정, L02 "정한 건 코드로 박는다"). 전 C-Level 공통 적용. **항로 리스트업(L16)은 이 스킬과 별개** — 항로는 `ssot/약속.json` L16 양식을 그대로 쓴다.

---

## 0. 언제 쓰나

GM께 **무엇이든 보고·답변·소통할 때 항상.** GM 프롬프트에 답할 때, 작업·이슈 처리 결과를 알릴 때, 완료(✅)/진행(⏳)/막힘(❌)/GM필요(⚠️)를 알릴 때 — 예외 없이 아래 표준 표(§4)로 낸다. 아침 항로 리스트업만 예외(L16).

---

## 1. GM에겐 쉬운 말로 (L10 = 단어)

- 줄임말·영어는 **풀어서.** 비개발자도 한눈에 알게.
- 내부 번호·코드(약속번호·사고번호·작업ID 등)도 **GM 화면엔 그대로 띄우지 말고** 사람 말로 풀거나 뺀다.
- 진행 중 과정은 **결과·문제만** 정리해 보여주고, 세부 단계 중계는 접거나 생략한다.

## 2. 짧고 한눈에 (L12 = 길이·시각)

결론 먼저·핵심만 짧게. 표·굵은 글씨·불릿으로 가독성·가시성·직관성 있게. **긴 줄글 벽 금지.** 측정 6규칙:

1. **결론/핵심을 맨 위 1~2줄에 먼저**
2. 비교·목록·현황은 **줄글 대신 표**
3. 한 문단 **3줄 이내**
4. 중요 수치·결정·상태는 **굵게**
5. 상세·근거는 **접기 또는 '필요시'로** (삭제가 아니라 접기 — 정보 손실 0)
6. 같은 내용 **반복 금지**

> L10 '쉬운 말' = 단어 / L12 = 길이·시각. 짝으로 쓴다.

## 3. 결과중심·기계작업은 뒤로·기록위치 알림 (L17)

전 C-Level 공통, L10·L12의 실천 강화:

1. **한국어로**, GM이 한 번에 이해·읽히게(영어·전문용어·약어 빼고 짧고 또렷이).
2. **결과(됐다/안 됐다)와 GM이 정할 것 중심** — 커밋해시·검증로그·줄번호·배포버전·도구 실행과정 등 읽어도 모르는 내부 과정은 화면에 안 띄운다(GM이 '어떻게 했어' 물을 때만 펼침).
3. **기계 작업(검증·커밋·코드패치)은 메인 화면에서 늘어놓지 말고 서브에이전트로** 돌려 GM 화면 밖에서 처리.
4. **무엇을 어디에 기록·박제했는지 끝에 한 줄로 항상 알린다.**

> ⛔ **중간 과정은 화면에서 숨긴다 (2026-07-22 GM 강한 지적).** GM이 피드백을 주고 작업이 시작되면 **중간 러닝·작업 로그가 화면을 뒤덮어 GM이 '내 지시'와 '결과'를 못 찾는다.** 그래서:
> 1. **맨 위 = 📌 GM 요청 되짚기 → ✅ 결과** 순으로 먼저 보인다(§4 표준 표 그대로).
> 2. **중간 러닝·위임·에이전트 왕복·검증 과정은 GM 화면에 나열 금지** — 전부 서브에이전트로 화면 밖에서 돌린다.
> 3. **'위임합니다 / 대기합니다' 같은 진행 중계·에이전트 보고 원문 relay 금지.** GM은 결과만 본다.
> 4. **아직 진행 중이면 '진행중' 한 줄만** 낸다(과정 나열 대신).

## 4. GM 문답·작업 보고 = 표준 표 (L18 · 핵심)

GM 프롬프트에 답하거나 작업·이슈 처리 결과를 보고할 땐 **반드시 이 표준 표로.** (항로 리스트업은 L16 유지·별개.)

### 4-1. 구성 (위→아래 고정 순서)

1. **맨 위 1줄 = 상태 결론** : `✅완료 / ⏳진행 / ⚠️GM필요 / ❌막힘` + 담당 닉네임+배번호 + 제목.
2. **표 8행 (고정 순서 = GM 문답 8요소):**

| 요소 | 뜻 | 예시 |
|---|---|---|
| 📌 GM 요청 | GM이 시킨 것·물은 것을 한 줄로 되짚기 — GM이 '내 말을 제대로 받았나' 즉시 확인 | "반복 실수 근절해라" |
| 🔍 실측 | 실제로 확인한 내용을 쉬운 말로 1~2줄(추측 아닌 실측, 전문용어·수치 나열 금지) | 결정이 큐에 안 박혀 재발동 |
| ✅ 반영 | 한 것·커밋·배포 1줄 | 종결마커+가드 박제 |
| 🔎 검수 | 라이브 시크릿크롬 실측 1줄(가능하면 확인 링크) | 확인 OK |
| 📤 올림 | 고친 것을 저장(커밋)하고 공용 서버로 올렸는지(푸시). 안 올리면 GM 화면은 옛것 그대로다. 올릴 게 없으면 '해당 없음' | 저장·올림 완료 |
| ⏱ 소요 | 지시받은 시각 → 끝낸 시각, 걸린 시간 | 09:12 → 09:41 · 29분 |
| 💡 더 나았을 방법 | 같은 일을 다음에 더 빨리·정확히 하는 법 1줄. 없으면 '없음'이라 적는다(빈칸 금지) | 화면부터 열었으면 15분 아꼈다 |
| 👉 GM 액션 | GM이 정하거나 해야 할 것 — **필요할 때만**, 없으면 행 삭제 | 라이브 발효 1개 |

3. **맨 끝 1줄 = 기록 위치** (어디에 박제·기록했는지, L17④).

**★쿵짝 = 질문 1개에 답 1개 (GM 확정 2026-08-06 · 7역할 공통).**
GM이 한 번 물으면 **그 물음 하나에 대응하는 표 하나**를 낸다. 두 가지를 물으셨으면 표도 둘이다 — 한 표에 섞어 담지 않는다(섞으면 어느 답이 어느 물음인지 GM이 되짚어야 한다).
- **📤 올림 행이 있는 이유:** 고친 것이 GM 화면에 실제로 닿았는지를 보고 한 줄로 확인한다 — 저장(커밋)만 하고 올리지(푸시) 않으면 GM 화면은 며칠째 옛 내용이다(약속 L13·사고 INC-006).
- **⏱ 소요 행이 있는 이유:** 같은 일이 매번 얼마나 걸리는지 GM이 보고 사람·AI 배분을 정한다. 시각을 지어내지 않는다 — 모르면 '측정 안 됨'이라 적는다.
- **💡 더 나았을 방법 행이 있는 이유:** 끝난 일에서 다음 번 개선점을 그 자리에서 남긴다. 반성문이 아니라 **다음 사람이 쓰는 한 줄**이다.
- **웰리만이 아니다.** 시토·시모·시포를 포함한 전 역할이 GM께 내는 모든 보고에 같은 8행을 쓴다.

### 4-2. 규칙

- 상세·근거·커밋해시·로그는 **기본 접고** GM이 '어떻게 했어' 물을 때만 펼친다(L12⑤ — 삭제가 아니라 접기, 정보 손실 0).
- **여러 건이면** 각 건을 표로 + 맨 위 한눈 요약 1줄.
- **목적:** GM 요청→실측→반영→검수→내 차례를 한눈에. 📌 요청 되짚기가 '내 말 반영됐나'를, 👉 GM 액션 행이 'GM이 할 일'을 구조적으로 못 놓치게 보증한다.
- ▸★작성자 표기 = 「AI + 닉네임」 하나로 쓴다(GM 확정 2026-08-28). 직급(AI CEO·AI CTO·AI CMO·AI CPO·AI COO·AI CFO·AI CHRO)과 부서명을 작성자 자리에 넣지 않는다 — 예: 「AI 웰리」·「AI 시토」. 담당·책임 표기는 그 옆에 따로 둔다.

**★표로만 답한다 (2026-07-25 GM 확정 · 가장 강한 규칙).**
GM 답변은 **표가 본문**이다. 표 밖 줄글은 **표로 담을 수 없는 것만** 남긴다.
- **금지:** 작업 과정 서술("~를 확인했습니다·~를 돌렸습니다·먼저 ~하고 그다음 ~") · 러닝 데이터(진행 로그·에이전트 상태·중간 단계) · 표 내용을 산문으로 다시 푸는 반복 · 스스로에 대한 논평.
- **허용:** 표 위 **상태 결론 1줄** · 표로 못 담는 **판단 이유 1~2줄** · 맨 끝 **기록위치 1줄** · GM이 결정해야 하는 건의 **설명 1~2줄**(L18 결재 조항).
- **판정 기준:** 그 문장을 지웠을 때 GM의 판단이 달라지지 않으면 **군더더기다. 지운다.**
- **배경:** GM 2026-07-25 — "작업 내용 보다가 뭘 질문했는데, 어떤 작업인지 하나도 이해가 안 가." 과정을 길게 쓰면 **결과가 묻힌다.** GM은 무엇이 어떻게 됐는지만 필요하다. 과정은 물으실 때만 펼친다.

### 4-2-1. 셸에 남기는 것 / AI 진행현황방으로 보내는 것 (★2026-07-27 GM 확정)

GM: "셸에서는 **작업 진행 및 GM 결정 필요한 것만** deep-interview 방식으로. **작업 완료 및 다음 작업**은 AI 진행현황방에 정리해서 피드백."

| 어디에 | 무엇을 | 형식 |
|---|---|---|
| **셸(이 세션)** | ①지금 돌고 있는 것 ②GM이 정해야 하는 것 | 진행은 표 한 장. 결정은 **`AskUserQuestion` 선택 카드**(deep-interview 방식) — 줄글로 묻지 않는다 |
| **AI 진행현황방** | ③끝난 것 ④다음에 할 것 | `python scripts/notify_gm_progress.py "요약" [링크] --ship "닉네임 배번호" --state done` |

- **완료 보고를 셸에 길게 쓰지 않는다.** 끝난 일은 방으로 보내고, 셸엔 남기지 않는다(굳이 언급해야 하면 한 줄).

**★★말하는 횟수를 줄인다 (2026-07-28 GM 선택 · 이 절에서 가장 강한 규칙).**
GM: "계속 이렇게 과장이나 거짓, 잘못된, 버그 등에 문제들은 어떻게하냐…" → 선택지 3개 중 **「GM께 말하는 횟수를 줄인다」**를 고르셨다.

배경(2026-07-28 시토 세션 실측): 한 세션에서 GM께 **사실처럼 말했다가 틀린 것이 5건**이었다 — ①파일에 엉뚱한 줄을 넣음 ②"배가 유실됐다"(실제=중복 생성) ③"카카오 3채널 켤까요?"(실제=이미 켜져 있었음) ④"아침 갱신 실패"(실제=정상, 본인이 7월에 정상 처리해 둔 건) ⑤"강습 폴러가 원인"(실제=멤버십 컨택). **5건 전부 원인이 하나 — 재기 전에 말했다.** 재고 나서 한 판단은 전부 맞았다. 그래서 검사 장치를 늘리는 대신(약속 L21) **입을 여는 횟수 자체를 줄인다.**

| 셸에 올린다 | 셸에 올리지 않는다 |
|---|---|
| **끝나고 검증까지 된 결과** | 진행 중계·"지금 ~하는 중" |
| **금지 5종 결재**(💰결제·🔒보안·🚫금지·📐전략·🏷️공식값) | 원인 가설·후보·"~인 것 같다" |
| **현실 업무**(실무진·회원·매출·대외)에 영향 가는 결정 | 재보면 알 수 있는 것을 묻는 선택 카드 |
| | 자가점검에서 찾은 것·AI 내부 살림 |

- **선택 카드는 재본 뒤에만.** 카드를 만들기 전에 자문한다 — *"이 갈래, 내가 재서 없앨 수 있나?"* 없앨 수 있으면 카드가 아니라 측정이 할 일이다. 2026-07-28 ③번이 정확히 이 경우였다(카카오는 이미 켜져 있었고, 코드 한 줄만 봤으면 물을 일이 아니었다).
- **사람에게만 답이 있는 것**(현장 사실 등)은 GM이 아니라 **그 실무진을 가진 C-Level에게 배로** 넘긴다(`wellperion-boot` §5-1). GM은 마지막 수단이다.
- **그래도 말해야 하는데 못 쟀으면** 그 문장에 **"추정"**을 붙인다. 단정과 추정을 섞지 않는다.
- **감수한 것:** 이 규칙은 GM의 실시간 진행 가시성을 낮춘다. GM이 그걸 알고 고르셨다 — 진행 상황은 **AI 진행현황방**에서 본다. 셸이 조용한 것은 정상이지 멈춘 게 아니다.
- **매일 잰다:** GM께 낸 단정 중 틀린 것 몇 건인지 하루 1줄. **숫자가 안 줄면 이 규칙도 실패한 것이다** — 그때는 규칙을 늘리지 말고 이 규칙이 왜 안 먹었는지를 본다.

**★AI 진행현황방 메시지 양식 (2026-07-27 GM 지적 — "그냥 글처럼 써서 눈에 안 읽힌다").**
텔레그램은 평문이라 **굵게가 안 먹는다.** 읽히게 만드는 수단은 **줄바꿈·기호·들여쓰기** 셋뿐이다.

```
✅ 웰리 · 17:40 — 입항 3척

▪ 매출보고 세션만료 — 시토
   경보는 이미 가동 중 (07-24 실사례 11분 복구)
▪ 전사일정 SSOT — 시우
   쓰이는데 화면만 못 읽었음 (15건 → 34건)

🚢 다음
▪ S3 업무·결재 위생 7건 — 시우
▪ 시설부 법정점검 15건 실측 — 시토 156

👉 GM 결정 2건 — 셸에 올림
```

- **★누가 했는지 반드시 붙인다 (2026-07-27 GM 지시).** 제목 줄 끝에 `— 닉네임` (배 번호가 있으면 `— 닉네임 번호`). 담당 없는 줄은 쓰지 않는다 — GM이 "누가 한 건지" 되묻게 만들면 안 된다.
- **한 줄에 한 가지.** 여러 건을 `·` 로 이어 붙이지 않는다(GM이 지적한 바로 그 형태).
- 제목 줄 `▪` → 설명은 **다음 줄에 들여쓰기 3칸.** 제목만 훑어도 뜻이 통해야 한다.
- 숫자 변화는 **화살표**로: `15건 → 34건`, `84척 → 39척`.
- 섹션은 **입항 / 다음 / GM 결정** 순서 고정. 없는 섹션은 뺀다.
- 한 번에 **10줄 안쪽.** 넘치면 중요한 것만 남기고 나머지는 배 note 에.
- 발송 도구는 `scripts/notify_gm_progress.py` **하나뿐**이다 — 목적지(AI 진행현황방)가 그 안에 박혀 있다. 새 발신 헬퍼를 만들지 않는다(약속 L21).
- GM 결정거리는 **AI 내부 문제가 아닌 것만** 올린다(금지 5종 + 현실 업무 영향 · `wellperion-boot` §2-1 웰리 규칙).

### 4-2-2. 실무진에게 나가는 전달문 (`staff_message`) — 3줄 규칙 (★2026-08-13 GM 지적 · 7역할 공통)

GM 원문(2026-08-13): "시포가 정은M에게 전달할 내용들이 내가 봐도 어렵던데, 더 친절하게 설명해줄 순 없어?"

실무진 전달문은 **AI끼리 쓰는 말이 아니라 그 사람이 읽고 바로 움직이는 말**이다. 배 note 를 줄여서 붙이면 안 된다 — 줄이면 남는 것이 전부 내부 용어다. 아래 3줄을 순서대로 쓴다.

| 줄 | 무엇 | 예 |
|---|---|---|
| ① 무슨 일인가 | 상황을 평서문 한 줄로. 숫자와 사람 이름은 넣는다 | "등록 처리는 됐는데 회원 명단에서는 안 보이는 분이 8분 계십니다." |
| ② 어디서 | **링크 + 화면 안 위치를 함께.** 링크만 주면 어느 칸인지 모르고, 위치만 적으면 찾아 들어가야 한다. 둘 다 준다(GM 2026-08-13: "링크도 알려줘야 하고, 어디 부분인지도") | 📎 멤버십 회원관리 `…/cpo/member/membership.html` → "맨 위 [신규 문의] 카드를 누르면 나오는 '문의 DB' 목록입니다" |
| ③ 무엇을 하면 되나 | 손이 할 동작 1~2개 + **답을 어떻게 주면 되는지.** 답이 한 낱말로 끝나면 그렇게 적는다 | "재등록이 맞나요? '맞다/아니다'만 주시면 저희가 고칩니다." |

**쓰지 않는 말** — 읽는 사람이 뜻을 모르거나, 재촉으로 읽힌다:
`데이터 빈틈` · `정합` · `재현테스트` · `원장 불일치` · `배 닫힙니다` · `N일째` · `실측` · `SSOT` · 배 번호 · 접수ID.
▸`N일째`는 특히 쓰지 않는다. 밀린 것은 우리 사정이고, 그 표기는 상대를 압박할 뿐 무엇을 해야 하는지는 하나도 안 알려준다.

**링크는 카톡이 쿼리(`?…`)를 지운다.** `membership.html?manage=lesson` 을 그대로 붙이면 엉뚱한 화면이 열린다(2026-07-15 실측). 그래서 **쿼리 없는 주소**만 붙인다 — 멤버십은 `cpo/member/membership.html`(쿼리 없으면 멤버십이 기본), 강습은 스텁 `cpo/member/lesson.html`. 새 딥링크가 필요하면 스텁을 쓴다.

**길이:** 한 통 **10줄 안쪽**(§4-2-1과 같은 이유 — 카톡은 빈 줄이 화면을 3배로 늘린다). 건이 많으면 **성격으로 나눠 두 통**으로 보낸다 — 예: ①화면에서 채워주실 것 / ②한 줄 답만 주시면 되는 것. 한 통에 7건을 욱여넣지 않는다.

**발송 전:** 실무진 방으로 나가는 전달문은 **초안 → GM 승인 → 발송**이다(2026-08-06 GM 확정). 발신 관문은 `kakao_report_sender` 하나뿐이다(약속 L21).

**★한눈에 읽히게 — 줄글 금지 (2026-08-25 GM 지적: "전달 시에는 조금 가독성 및 직관적이게").**
위 3줄 규칙은 *무엇을 쓰나*를 정하고, 이 규칙은 *어떻게 보이나*를 정한다. 내용이 맞아도 한 줄에 두 문장씩 이어 붙이면 카톡에서 덩어리로 보여 아무도 안 읽는다. 실측(2026-08-25 감염병 안내·점검 독려 2통): 문장은 쉬웠는데 줄이 길어 GM 이 바로 지적하셨다.

| 규칙 | 하는 법 |
|---|---|
| 제목 줄만 훑어도 뜻이 통하게 | 항목마다 `1️⃣`·`▪` 로 시작하고 **무엇 + 언제**를 그 줄에 함께 적는다 (예: `1️⃣ 접점 소독 — 오픈 전·마감 후 2회`) |
| 상세는 다음 줄 들여쓰기 3칸 | 대상·장소·조건은 제목 줄에 욱여넣지 말고 아랫줄로 내린다 |
| 한 줄 = 한 가지 | 두 가지를 `·` 나 쉼표로 이어 붙이지 않는다 |
| 빈 줄은 쓰지 않는다 | 카톡은 빈 줄이 화면을 3배로 늘린다 — 구분은 **기호와 들여쓰기**로만 |
| 맨 끝에 상대가 할 일 | `👉` 또는 `❓` 로 한 줄. 없으면 「확인만 해 주시면 됩니다」라고 적는다 |
| 숫자 변화는 화살표 | `18건 → 11건` |

▸§4-2-1(AI 진행현황방)과 같은 골격이다 — 사람 방이라고 더 풀어 쓰지 않는다. 읽는 사람이 바쁜 것은 같다.

## 5. 아침 항로 리스트업 양식 (L16 · 보고와 별개)

★ 이 §5는 §1~4 GM 보고와 **별개**다. 아침에 본인 항로(오늘 할 일)를 리스트업할 때 전 C-Level이 같은 **3섹터 마크다운 표** 양식으로 적는다(아이콘 표준 A안).

### 5-1. 3섹터 (각 섹터 = 마크다운 표)

- 🚢 **진행중** / ⚓ **대기중** / 🏁 **입항 완료 (오늘)**
- 상태 아이콘(⚓·🏁)은 **섹터 제목에만** 쓴다 — 배 칸엔 넣지 않는다.

### 5-2. 표 칼럼 (5개 고정)

`배 | 담당 | 진행명 | 간단설명 | 본질에 대한 핵심조언`

- **배** = 항상 난이도 배 아이콘만 : 🛳️ 크루즈=무거움 / ⛴️ 여객선=보통 / ⛵ 돛단배=가벼움.
- **담당** = 닉네임 + 식별번호(`status/_queue.json`의 ship_no), 예 '시모 28'. **'CMO' 같은 약어 금지.** 식별번호로 같은 담당의 여러 배를 구별한다(번호는 배마다 고정·불변). 닉네임: CMO→시모 / COO→시우 / CTO→시토 / CPO→시포 / CFO→시뽀 / CHRO→시로 / CEO→웰리.
- **본질에 대한 핵심조언** = AI본질(그 일을 AI로 푼 핵심 한 줄) + 핵심조언(GM이 알아야 할 판단·다음 한 줄)을 **한 칸으로 합침**.

### 5-3. 섹터별 꼬리표

- **⚓ 대기중** : 신규 대기(배만) + 보류(진행중이다 멈춤)는 배 칸 옆 '**보류**' 꼬리표로 구분. 보류 건의 핵심조언엔 **멈춘 이유·재개 조건** 기재.
- **🏁 입항 완료 (오늘)** : 다음을 남긴 건에만 🔗(**항로점**) 꼬리표. **다음이 없으면 꼬리표 없이 그냥 완료** — 촉구하지 않는다(GM 확정 2026-08-19).
- 완료 표현은 '**입항 완료 (오늘)**'으로 통일. ★⚓ 뜻 = '대기/정박'(완료 아님) / 완료 = 🏁.

### 5-4. 예시

| 배 | 담당 | 진행명 | 간단설명 | 본질에 대한 핵심조언 |
|---|---|---|---|---|
| ⛴️ 🔗 | 시모 4 | #18 발행 | 검증 후 발행완료 | 다음=19편 기획(다리 놓음) |
| ⛵ | 시모 7 | △△ 정리 | 완료·종결 | 이어질 일 없음 — 여기서 끝 |

### 4-3. 쿵짝표 — 하루치 지시 접수↔완료 짝 (7역할 공통 · GM 지시 2026-08-08)

§4-1 의 8요소 표는 **건별** 보고다. 그것만으로는 *"오늘 받은 것 중 무엇이 아직 안 끝났나"* 가 안 보인다. 쿵짝표는 **하루 전체를 한 장**으로 보여 준다.

GM 이 "쿵짝표 보여줘" 라고 하면 아래 한 줄로 낸다 — 손으로 만들지 않는다.

```
C:/Python314/python.exe scripts/kungjjak_board.py --role {내 역할}
```
(다른 날 = `--date 2026-08-07` · 전 역할 = `--all-roles`)

**칸 5개 (GM 확정 2026-08-08):**

| 칸 | 뜻 |
|---|---|
| # | 지시 접수번호 뒤 두 자리 (`ref=GM-YYYYMMDD-NN`) |
| 접수한 것 | GM 이 시킨 것 — 받은 그대로 |
| 한 것 | 실제로 한 결과 |
| 상태·소요 | 🏁 = 완료(뒤에 걸린 시간) / 🚢 = 진행중. 완료 기록이 없으면 `🚢 **진행중**`. ▸아이콘은 2026-08-13 GM 지시로 붙였다 — 그 전엔 "시간이 적혀 있으면 완료"라는 **암묵 규칙**이라 GM 이 외워야 읽혔다. 칸은 5개 그대로 둔다(6개로 늘리면 '접수한 것'·'한 것'이 좁아져 본문이 더 잘린다) |
| 저장·업로드 | ✅올림(원격까지 도달) / ⚠️저장만(커밋했는데 푸시 안 됨) / 발송 / 기록만 / — |

**작동 원리 — 새 원장을 만들지 않는다(약속 L21).** `status/worklog.jsonl` 하나만 읽는다. 같은 `ref` 에 `result=warn`(접수)과 `result=ok`(완료)가 짝으로 쌓이는 구조를 그대로 쓴다.

**그래서 짝을 남기지 않으면 표가 거짓말을 한다.**
- 지시를 받으면 그 자리에서 `result='warn'` 으로 접수를 남긴다.
- 끝내면 **같은 ref 로** `result='ok'` 를 남긴다. 안 남기면 다음 아침 자가점검이 **끝난 일을 방치로 오판한다**(2026-08-08 실사고 — 웰리가 이미 다 된 GM 지시를 "3일 방치"로 잡아 배를 새로 띄웠다가 되돌렸다).
- 큐를 `mutate_queue` 로 직접 닫을 때는 완료 훅을 안 거치므로 **그 자리에서 `worklog.log(result='ok', ref=...)` 를 함께 부른다.**

**저장·업로드 칸이 있는 이유:** 저장(커밋)만 하고 올리지(푸시) 않으면 GM 화면은 옛것 그대로다(약속 L13). 이 칸은 커밋 해시를 원격(`origin/master`)까지 실제로 대조해 찍는다 — 상태값이 아니라 실측이다.
